# v7.3.4.2 Development Notes

## Comprehensive memory notes for fresh start

### Project position at the start of this step
- `v7.3.3` remained the last broader stabilization baseline
- `v7.3.4` introduced Phase 1 structural work:
  - `App.State` write chokepoints
  - centralized delegated `bindEvents()`
  - removal of inline handlers
- `v7.3.4.1` repaired the startup blocker where the dashboard stayed on `connecting...`
- after that repair, the dashboard could load/connect again, but three remaining user-visible dashboard issues were identified:
  - merged `Export All` failed with `HTTP 502`
  - chart point markers did not fully follow sensor recolor changes
  - 15-minute chart markers were larger than the real-time charts
- an additional follow-up requirement was added for this conversation: when switching theme, chart-rendered elements should redraw correctly **without** requiring `Ctrl+F5`

### Key continuity rules locked in for this conversation
- every build must be delivered as a ZIP named with the version
- every ZIP must contain a `Docs` folder with versioned documentation and development notes
- version comments/headers across code and docs must stay aligned
- documentation must include changelog, bug causes, lessons learned, and third-party opinion review if requested
- development notes must include fresh-start memory notes, request understanding, deliverables, implementation approach, file purposes, smoke/preflight results, and user test expectations
- test worksheets should be kept as a single combined file
- pass/fail results must be included in the documentation
- use the latest known-good actual files instead of reconstructing from memory when a branch has diverged

## Implementation approach used

### What changed intentionally
- replaced merged export’s parallel multi-sensor history fan-out with sequential fetching
- updated chart recolor path to include point-marker properties
- aligned 15-minute marker size with the live charts
- added a forced chart redraw helper invoked from the theme-toggle path
- kept comments/version markers aligned to `v7.3.4.2`
- extended preflight to statically verify the hotfix patterns

### What was deliberately not changed
- no transport logic rewrite
- no retained-history backend rewrite
- no import feature work started
- no auth/management behavior change
- no chart-instance destroy/recreate approach unless later testing proves that narrower redraw is insufficient
