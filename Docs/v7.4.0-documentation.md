# v7.4.0 Documentation

_Date: 2026-03-09_
_Branch: `feature/import-v1` → PR #2 targeting `main`_

---

## Summary

This version adds CSV import capability to the gateway. Users can import previously exported sensor history data back into the device's NVS flash storage. The feature works through both direct LAN access and Cloudflare tunnel (pending final validation).

---

## New Endpoints

| Endpoint | Method | Auth | Purpose |
|----------|--------|------|---------|
| `/api/import/begin` | POST | Basic | Clear history partition, allocate import buffer |
| `/api/import/d/<data>` | POST | Basic | Add data points to current segment (no NVS write) |
| `/api/import/w/<data>` | POST | Basic | Add data points AND write segment to NVS |
| `/api/import/finish` | POST | Basic | Finalize metadata, restore RAM from NVS, free buffer |

### Data format

Semicolon-delimited lines in the URL path:
```
/api/import/d/office,temp,1772528400,21.50;office,hum,1772528400,45.00;first_floor,temp,1772528400,14.10
```

Each line: `sensor_id,series,epoch,value` where series is `temp` or `hum`.

### Import flow

1. Browser reads CSV → detects format (single-sensor or merged) → validates and sorts
2. Browser groups data into hourly segments, splits into URL-safe batches (~250 chars each)
3. User confirms (shows point count, batch count, sensor names)
4. `POST /api/import/begin` — clears history, allocates snapshot buffer
5. Sequential `POST /api/import/d/...` batches (accumulate data in memory)
6. `POST /api/import/w/...` on last batch of each hourly segment (writes to NVS)
7. `POST /api/import/finish` — saves metadata, restores newest segments to RAM
8. Dashboard charts and storage stats auto-refresh

## Validation

### Browser-side (before any data is sent)

- Auto-detects single-sensor vs merged CSV format from column headers
- Timestamp: rejects < year 2000 or > 1 day in the future
- Temperature: -50°C to 80°C
- Humidity: 0% to 100%
- Sorts chronologically, deduplicates within hourly segments
- Shows confirmation dialog with summary before proceeding

### ESP-side (per data batch)

- Sensor ID must match a known sensor
- Epoch must be valid and not future
- Temperature and humidity range checks
- Series must be "temp" or "hum"
- Segment slot overflow protection (max 4 per series per sensor per hour)

## Transport Design Notes

The URL-path approach was chosen after three alternatives failed:

1. **POST body** — ESPHome ESP-IDF does not deliver body to `handleBody()` in custom handlers
2. **URL query params** — `url_to()` strips query string, returns path only
3. **Custom headers** — Works on LAN but Cloudflare adds headers that exceed ESP-IDF's 512-byte buffer

The URL path is preserved by all HTTP proxies and is already proven in this codebase for history endpoints. Each batch stays under 250 chars of data, fitting within the 512-byte URL buffer limit with room for the `/api/import/d/` prefix.

---

## Known Limitations

- Import is replacement-first: all existing history is cleared before writing
- Export causes ~40KB temporary heap drop (response stream buffer allocation)
- Maximum ~250 chars of data per import batch (URL buffer constraint)
- For 498-row multi-sensor CSV: ~375 batches, ~20 seconds on LAN
