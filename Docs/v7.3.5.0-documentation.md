## Summary

This version adds the `GET /api/status` health endpoint to the gateway firmware, providing a lightweight JSON response with version, uptime, sensor health, and memory information. It also represents the first feature developed through the full GitHub PR workflow with branch protection and CI gating.

---

## Changes

### New: `/api/status` endpoint

Returns JSON with no authentication required:

```json
{
  "ok": true,
  "version": "v7.3.5.0",
  "uptime_seconds": 98,
  "sensor_count": 3,
  "sensors": [
    {
      "id": "office",
      "name": "Office",
      "last_seen": 1772966572,
      "temp_valid": true,
      "hum_valid": true
    }
  ],
  "ram_history_points_per_series": 96,
  "persist_days": 45,
  "free_heap": 84704
}
```

### Bug fix: JSON truncation

The initial implementation packed `ram_history_points_per_series`, `persist_days`, and `free_heap` into a single `snprintf` call targeting a 64-byte buffer. The formatted output was 72 bytes, causing silent truncation. The fix splits this into three separate print calls.

### Files modified (relative to v7.3.4.2)

- `dashboard/sensor_history_multi.h` — new `handle_status_()` method, route registration in `canHandle()` and `handleRequest()`, constructor updated to accept version string
- `firmware/esp32-c3-multi-sensor.yaml` — version string passed to `register_history_handler()`
- `scripts/preflight.sh` — new check `status_endpoint_present`

## Notes for Future Development

- The `char num[64]` buffer pattern is used in multiple handlers. Any new endpoint returning JSON should use the split-print approach or a larger buffer.
- The `/api/status` endpoint is designed as the health check for future gateway aggregation (7.7) — it exposes everything a remote aggregator needs to assess gateway health.
