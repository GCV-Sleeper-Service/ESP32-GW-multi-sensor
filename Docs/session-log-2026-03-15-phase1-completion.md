## Design Decisions

### Why `gateway_manifest.h` instead of inline resp->print()

The architectural intent was a compile-time static string that:
1. Is generated from the Python manifest source of truth (not maintained separately in C++)
2. Requires zero heap allocation during HTTP serving (ESPHome's `beginResponse(200, ..., static_str)` takes a const char*)
3. Eliminates the risk of the C++ inline manifest drifting from the actual sensor configuration
4. Makes the manifest JSON easily inspectable without running the firmware

### Why `to_manifest_v2()` as the canonical builder

Having a single function that both `render_sensor_config.py` (for gateway_manifest.h and fixture) and external scripts (`change_sensor_number.py`, `save_manifest()`) call ensures all manifest consumers produce the same schema shape. `manifest_v2()` is kept as a thin wrapper for backward compatibility.

### Version format: "v7.5.1" in JSON

The firmware's `firmware_version_` string is "v7.5.1" (from the YAML register_history_handler call). The manifest JSON now uses the same "v7.5.1" format for consistency. The `VERSION` constant in render_sensor_config.py is "7.5.1" (no prefix) and is prefixed when passed to manifest functions.
