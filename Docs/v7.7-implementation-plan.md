# Phase 7 — Per-Device Persistence Engine

_Implementation Plan for v7.7.0.x through v7.7.2.x_
_Date: 2026-03-19_
_Prerequisite: v7.5.x Phases 1–6 complete (or at minimum Phase 4 complete, v7.5.4.x on `main`)_
_Repo: [GCV-Sleeper-Service/ESP32-GW-multi-sensor](https://github.com/GCV-Sleeper-Service/ESP32-GW-multi-sensor)_

---

## Goal

Replace the monolithic `SegmentSnapshot` persistence model with a per-device segment engine. When Phase 7 is complete:

1. Each device's history is stored in its own NVS key namespace
2. Adding/removing a device never touches another device's data
3. Per-device delete, export, and import are available
4. Automatic migration from v7.x format preserves recent history
5. Retention is budgeted per device from manifest priority tiers
6. All existing Playwright tests pass with no behavioral regression

**Key principle:** Build the new engine alongside the old one. Validate with environmental devices first. Remove the old engine only after migration is proven on real hardware.

**Implementation details:**
```cpp
static bool persist_device_segment_(int device_index) {
  const SensorEntity &dev = devices[device_index];
  // 1. Build DeviceSegment from device's HistoryBuffers
  // 2. Open NVS read-write
  // 3. Load DeviceHistoryMeta → dedup check
  // 4. Write segment to ds_{hash}_{next_slot}
  // 5. Update meta → save
  // 6. Close NVS
  return true;
}

static void persist_all_devices_v2() {
  for (int i = 0; i < PERSIST_DEVICE_COUNT; i++) {
    int dev_idx = persist_device_indices_[i];
    persist_device_segment_(dev_idx);
    maybe_yield_nvs_scan_(i);  // BUG-043 pattern
  }
}
```

- [ ] Ring buffer wraps correctly when `valid_segments == max_slots`
- [ ] NVS handles are opened and closed on every code path (no leaks)
- [ ] `maybe_yield_nvs_scan_()` called between device persists
- [ ] Old `persist_hourly_segment()` still runs (dual-write period)
- [ ] All existing Playwright tests pass

- Version bump: ALL locations to `7.7.0.2`

**Retention budget implementation:**
```cpp
struct RetentionBudget {
  int device_index;
  int max_slots;
  uint8_t priority;  // 0=high, 1=normal, 2=low
};

static void calculate_retention_budget_(RetentionBudget *budgets, int count) {
  uint32_t partition_size = find_partition_size_bytes_(HISTORY_PARTITION_LABEL, ...);
  uint32_t usable = (partition_size * 85) / 100;
  uint32_t meta_cost = count * (sizeof(DeviceHistoryMeta) + 48);
  uint32_t seg_budget = usable - meta_cost;

  // Count devices per tier
  int high_count = 0, normal_count = 0, low_count = 0;
  for (int i = 0; i < count; i++) {
    if (budgets[i].priority == 0) high_count++;
    else if (budgets[i].priority == 1) normal_count++;
    else low_count++;
  }

  // Allocate shares (redistribute empty tiers)
  uint32_t high_share = high_count > 0 ? (seg_budget * 70) / 100 : 0;
  uint32_t normal_share = normal_count > 0 ? (seg_budget * 20) / 100 : 0;
  uint32_t low_share = seg_budget - high_share - normal_share;
  // ... redistribute if a tier is empty ...

  uint32_t per_slot = sizeof(DeviceSegment) + 48;
  for (int i = 0; i < count; i++) {
    uint32_t tier_share = ...; int tier_count = ...;
    budgets[i].max_slots = min(999, tier_share / (tier_count * per_slot));
  }
}
```

**Acceptance criteria:**
- [ ] Budget calculator produces correct slot counts for test scenarios
- [ ] `restore_device_()` loads segments from NVS into HistoryBuffer
- [ ] Metric mismatch handled gracefully (fewer metrics → load subset; more → leave new empty)
- [ ] `valid_segments` capped to budget's `max_slots` if budget shrank
- [ ] Restore yields every 4 blobs
- [ ] Restore completes within 10 seconds for 3 devices × 460 segments
- [ ] Old `restore_from_nvs()` still runs first (backward compat during transition)
- [ ] All existing Playwright tests pass
- [ ] Version is `7.7.0.2` everywhere

**Risk:** High. Boot restore is critical path — errors mean no history on dashboard.
**Estimated effort:** 3–4 sessions.
**Device testing required:** YES — critical. Verify history loads on dashboard after boot.

## Flash Persistence: What Changes and What Doesn't

**CHANGES:**
- NVS key scheme (hash-based per-device keys replace shared `seg_NNN` keys)
- Blob format (`DeviceSegment` replaces `SegmentSnapshot`)
- Restore path (per-device iteration replaces single-pass)
- Persist path (per-device iteration replaces single-blob write)
- Storage stats (per-device breakdown)
- Delete (per-device option added)
- Import/export (per-device CSV format)

**DOES NOT CHANGE:**
- `HistoryBuffer` class (RAM ring buffers — same as today)
- `HistEntry` struct (epoch + float — same as today)
- 15-minute averaging intervals
- 1-hour persist intervals
- Chart.js rendering pipeline
- SSE/REST data transport
- Dashboard card rendering (CARD_RENDERERS)
- Manifest v2 schema (extend, not replace)
