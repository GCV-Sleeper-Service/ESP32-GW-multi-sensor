## Override 1: §2 Required Reading — Item 7 (dashboard.js) additions

Add these observations to the Required Reading for `dashboard/dashboard.js`:

- **Unified boot path (LESSON-OPS-074):** `App.Boot.start()` is NO LONGER a forked
  if/else between satellite and aggregator. Both roles run the full satellite pipeline
  (manifest → sensors → cards → charts → SSE/polling → status → storage stats →
  history). If `isAggregator`, `initAggregatorDashboard()` is called AT THE END as an
  overlay. This means: in aggregator mode, local sensor cards ARE rendered, SSE/polling
  IS active, storage stats and telemetry DO load.

- **Separate Gateways section:** All aggregator render functions now target NEW DOM
  elements, NOT `#sensorGrid`:
  - `renderGatewaySelector()` → writes to `#gwSelectorContainer`
  - `renderAllGatewaysSummary()` → writes to `#gwGrid`
  - `renderGatewayDevices()` → writes to `#gwGrid`
  - `renderSettingsPanel()` → writes to `#gwGrid`
  - `initAggregatorDashboard()` → unhides `#hdr-gateways` and `#body-gateways`

- **The Gateways section (`#hdr-gateways` / `#body-gateways`)** is in `dashboard.html`
  ABOVE the SENSORS section. It is `display:none` by default and only shown when
  `initAggregatorDashboard()` runs.

- **Remote history suppression:** `renderGatewayDevices()` replaces `.minmax-line .waiting`
  content with "—" and hides `.minmax-toggle` after rendering satellite cards. No proxy
  history fetch occurs for remote satellite devices.

- **Board-aware About card (BUG-067 + BUG-068):** `updateBoardInfo()` hides `#gpioCard`,
  `#c3DescriptionBlock`, and updates `#aboutCardTitle` on non-C3 boards. This works
  because `render_sensor_config.py` now builds `gateway_meta` from the board profile's
  `chip_variant` (e.g., `esp32s3` → `ESP32-S3`) and passes it to `manifest_v2()`.

- **Environmental chart hiding (BUG-069):** After `initCharts()`, the boot path checks
  `SENSORS.some(function(s) { return !s.category || s.category === 'environmental'; })`.
  If false, `#hdr-realtime`, `#body-realtime`, `#divider-charts`, `#hdr-averages`, and
  `#body-averages` are hidden. IMPORTANT: `makeSensorConfig()` does NOT set `.category`
  on environmental sensors — absence means environmental. Only `makeNetworkSensorConfig()`
  sets `.category` explicitly. The check uses `!s.category ||` to handle this.

- **`DEFAULT_SENSOR_META` is generator-managed:** Lines 196–202 of `dashboard.js` contain
  `DEFAULT_SENSOR_META` between `SENSOR_MANIFEST:DEFAULT_SENSOR_META_BEGIN/END` markers.
  The generator populates this array from `config/sensors.json`. When running with the C3
  default config (4 sensors), it contains 3 ThermoPro entries. When running with the S3
  aggregator config (wan_ping only), it's empty. The CI fixtures expect the C3 version.
  **Do NOT hand-edit this array — it is regenerated by `render_sensor_config.py --write`.**

- **Note on rendering:** The main prompt says functions "all use createElement/textContent."
  This is partially incorrect — the functions use `escHtml()` and `escAttr()` helper
  functions with innerHTML/insertAdjacentHTML. The `createElement/textContent` approach
  was applied to specific elements (gateway tab buttons via addEventListener). Test
  selectors using `data-gw` attributes remain correct.

## Override 5: Critical generator/CI interaction

**When creating or modifying fixtures, you MUST understand this:**

`render_sensor_config.py --write` and `--check` read `config/gateway.json` and
`config/aggregator.json` when present. These files change what the generator produces:
- With `gateway.json` (S3 board + `sensors_file`): generates for 1 sensor (wan_ping only)
- Without `gateway.json`: generates for 4 sensors (3 ThermoPro + wan_ping) — C3 default

CI does NOT have `gateway.json`. CI expects the C3 4-sensor output. If you run
`--write` while `gateway.json` exists, you'll produce S3 fixtures that fail CI.

**Rule: Always verify `config/gateway.json` and `config/aggregator.json` are absent
before running `--write` or `--check` for CI validation purposes.**

This does NOT affect v7.5.5.4 directly (you're creating a new `aggregator` fixture
variant, not modifying the root fixtures). But if you touch `render_sensor_config.py`
or regenerate root fixtures for any reason, this rule applies.
