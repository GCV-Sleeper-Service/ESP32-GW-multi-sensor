## Override 1: §2 Required Reading — Item 7 (dashboard.js) additions

Add these observations to the Required Reading for `dashboard/dashboard.js`:

- **Unified boot path (LESSON-OPS-074):** `App.Boot.start()` is NO LONGER a forked
  if/else between satellite and aggregator. Both roles run the full satellite pipeline
  (manifest → sensors → cards → charts → SSE/polling → status → storage stats →
  history). If `isAggregator`, `initAggregatorDashboard()` is called AT THE END as an
  overlay. This means: in aggregator mode, local sensor cards ARE rendered, SSE/polling
  IS active, storage stats and telemetry DO load.

- **Separate Gateways section:** All aggregator render functions now target NEW DOM
  elements, NOT `#sensorGrid`:
  - `renderGatewaySelector()` → writes to `#gwSelectorContainer`
  - `renderAllGatewaysSummary()` → writes to `#gwGrid`
  - `renderGatewayDevices()` → writes to `#gwGrid`
  - `renderSettingsPanel()` → writes to `#gwGrid`
  - `initAggregatorDashboard()` → unhides `#hdr-gateways` and `#body-gateways`

- **The Gateways section (`#hdr-gateways` / `#body-gateways`)** is in `dashboard.html`
  ABOVE the SENSORS section. It is `display:none` by default and only shown when
  `initAggregatorDashboard()` runs.

- **Remote history suppression:** `renderGatewayDevices()` replaces `.minmax-line .waiting`
  content with "—" and hides `.minmax-toggle` after rendering satellite cards. No proxy
  history fetch occurs for remote satellite devices.

- **Board-aware About card:** `updateBoardInfo()` now hides `#gpioCard`,
  `#c3DescriptionBlock`, and updates `#aboutCardTitle` on non-C3 boards.

- **Note on rendering:** The main prompt says functions "all use createElement/textContent."
  This is partially incorrect — the functions use `escHtml()` and `escAttr()` helper
  functions with innerHTML/insertAdjacentHTML. The `createElement/textContent` approach
  was applied to specific elements (gateway tab buttons via addEventListener). Test
  selectors using `data-gw` attributes remain correct.

## Override 3: §5c Test Updates

### Additional test: Gateways section is separate from SENSORS

Add this test to the aggregator group:

```js
test('Gateways section is visible and separate from SENSORS section', async ({ page }) => {
  await page.goto('/', { waitUntil: 'domcontentloaded' });
  await waitForAggregatorReady(page);
  // Gateways section should be visible (unhidden by initAggregatorDashboard)
  const gwBody = page.locator('#body-gateways');
  await expect(gwBody).toBeVisible();
  // gwSelector should be inside gwSelectorContainer, NOT before sensorGrid
  const gwSelector = page.locator('#gwSelectorContainer #gwSelector');
  await expect(gwSelector).toBeVisible();
  // Gateway summary cards should be in gwGrid, NOT sensorGrid
  const gwGridCards = page.locator('#gwGrid .gw-summary-card');
  await expect(gwGridCards).toHaveCount(2);
  // sensorGrid should be empty or have local sensor cards only (not gateway content)
  const sensorGridGwCards = page.locator('#sensorGrid .gw-summary-card');
  await expect(sensorGridGwCards).toHaveCount(0);
});
```

### Additional test: Local sensors render in aggregator mode

Since the boot path is now unified, local sensor cards appear in aggregator mode too:

```js
test('local sensor cards rendered in aggregator mode (unified boot)', async ({ page }) => {
  await page.goto('/', { waitUntil: 'domcontentloaded' });
  await waitForAggregatorReady(page);
  // If the aggregator fixture has local sensors (e.g., wan_ping),
  // they should appear in #sensorGrid (the SENSORS section).
  // If fixture has 0 local sensors, sensorGrid will be empty — that's also valid.
  // This test confirms the satellite pipeline ran (no "connecting" state).
  const modeLabel = page.locator('#modeLabel');
  await expect(modeLabel).not.toHaveText('');
});
```

### Selector notes for existing tests

Tests 5-8 in the main prompt use selectors like `.sensor-card`, `.gw-summary-card`,
`.gw-tab[data-gw="gw-main"]`. These are correct — the CSS classes are the same,
they just live inside `#gwGrid` instead of `#sensorGrid`. Playwright finds elements
by class regardless of parent container, so no selector changes needed.
