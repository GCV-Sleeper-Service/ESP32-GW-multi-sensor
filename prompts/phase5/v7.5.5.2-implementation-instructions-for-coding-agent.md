## 4. Exact Scope — Aggregator API Endpoints

Expose aggregator-specific API endpoints that serve cached satellite data. All endpoints are conditionally compiled with `#if AGGREGATOR_ENABLED`.

### 4a. `GET /api/aggregator/gateways`

Returns list of configured satellites with cached status:

```json
{
  "gateways": [
    {
      "id": "gw-main",
      "name": "Main Gateway",
      "reachable": true,
      "last_seen": 1710264000,
      "consecutive_failures": 0,
      "manifest_cached": true,
      "live_cached": true
    }
  ]
}
```

Build from `SatelliteCache` array. Extract firmware_version, sensor_count, and free_heap from the cached `status_json` if available (parse with simple string search — no JSON library needed on ESP32, or use the cached string directly).

### 4b. `GET /api/aggregator/live`

Returns unified live values from all satellites:

```json
{
  "timestamp": 1710264000,
  "gateways": {
    "gw-main": {
      "reachable": true,
      "live": "<raw cached JSON from /api/v2/live>"
    }
  }
}
```

**Implementation note:** Rather than parsing and restructuring the cached live JSON, embed it as a raw string. The dashboard will parse the nested structure. This avoids implementing a JSON parser on the ESP32.

### 4c. `GET /api/aggregator/proxy/{gw_id}/history/{device}/{metric}`

On-demand history proxy. The aggregator fetches from the satellite and relays the response.

**⚠️ CRITICAL: LESSON-OPS-056 Compliance**

Satellite history responses can be 20KB+ (45 days × hourly points). You MUST:

1. Pre-reserve the response string: `std::string csv; csv.reserve(32768);`
2. Fetch from satellite using `esp_http_client`
3. Read response into the pre-reserved string
4. Send via zero-copy `beginResponse(200, "text/plain", csv.c_str(), csv.length())`
5. **NEVER** use `beginResponseStream` for the proxy response
6. Set a max response size of 32KB — if satellite response exceeds this, truncate and log a warning
7. If satellite is unreachable, return 502 (Bad Gateway)
8. If gateway ID is unknown, return 404

**URL parsing:** The proxy URL pattern is `/api/aggregator/proxy/{gw_id}/history/{device}/{metric}`. You need to extract `gw_id`, `device`, and `metric` from the URL path. Follow the existing path-parsing pattern in `handleRequest()` for the import endpoints.

### 4d. Route registration in `canHandle()` / `handleRequest()`

Add URL matching inside `#if AGGREGATOR_ENABLED` blocks:

```cpp
bool canHandle(AsyncWebServerRequest* request) override {
  // ... existing satellite routes ...
  
  #if AGGREGATOR_ENABLED
  if (request->url() == "/api/aggregator/gateways") return true;
  if (request->url() == "/api/aggregator/live") return true;
  if (request->url().startsWith("/api/aggregator/proxy/")) return true;
  #endif
  
  return false;
}
```

### 4e. Satellite firmware: ZERO changes

When `AGGREGATOR_ENABLED == 0`, none of the aggregator endpoints exist. The `canHandle()` paths are compiled out. Verify this by checking that satellite firmware compiles and runs identically.
