## Exact scope

Extend the dashboard with multi-gateway UI for aggregator mode while keeping satellite mode completely unaffected.

### Step-by-step:

1. **Aggregator mode detection** in boot flow:
   - After loading manifest, try `fetch('/api/aggregator/gateways')`
   - 404 → satellite mode (current behavior, no changes)
   - 200 → aggregator mode (new behavior below)

2. **Gateway selector bar:**
   - Horizontal tab bar or dropdown showing each satellite by name
   - "All Gateways" option for summary view
   - Selected gateway highlighted

3. **"All Gateways" summary view:**
   - One card per gateway showing: name, online/offline status indicator, device count, firmware version, uptime, free heap
   - Offline gateways visually dimmed/grayed

4. **Per-gateway view:**
   - Selecting a gateway shows its devices using existing `CARD_RENDERERS`
   - Device IDs namespaced with gateway prefix (e.g., `gw-main.office`) to avoid collisions
   - History charts fetch through the aggregator proxy: `/api/aggregator/proxy/{gw_id}/history/{device}/{metric}`

5. **Stale/unreachable indicators:**
   - Unreachable satellites: grayed-out cards with "Last seen: X minutes ago" overlay
   - Visual distinction between fresh and stale data

6. **Satellite-mode dashboard COMPLETELY UNAFFECTED:**
   - If aggregator detection returns 404, the entire aggregator UI code path is skipped
   - No new DOM elements created, no new CSS applied, no new fetch calls
   - All existing Playwright tests must pass unchanged

7. **Mirror all changes to `dashboard.html`** (LESSON-OPS-043)

8. **Regenerate `dashboard.h`** via `scripts/generate-header.sh` (gzip, LESSON-OPS-055)

9. **Update changelog, session log, bump to 7.5.5.3**

### Critical constraints:
- Dashboard.h is gzip-compressed — `generate-header.sh` handles this (LESSON-OPS-055)
- Satellite-mode dashboard must be PIXEL-IDENTICAL to v7.5.5.2
- Aggregator mode adds UI elements; satellite mode must not render them
- Use feature detection (API response), not build-time flags, for mode switching
