## Exact scope

Expose aggregator-specific API endpoints that serve cached satellite data.

### Endpoints to implement:

1. **`GET /api/aggregator/gateways`** — List all configured satellites with status:
   ```json
   {
     "gateways": [
       {
         "id": "gw-main",
         "name": "Main Gateway",
         "reachable": true,
         "last_poll": 1710264000,
         "consecutive_failures": 0,
         "firmware_version": "v7.5.4.4",
         "sensor_count": 4,
         "free_heap": 72000
       }
     ]
   }
   ```

2. **`GET /api/aggregator/live`** — Unified live values from all satellites:
   ```json
   {
     "timestamp": 1710264000,
     "gateways": {
       "gw-main": {
         "reachable": true,
         "devices": {
           "office": { "temp": 23.4, "hum": 45.2, ... },
           "wan_ping": { "ping_ms": 12.3, "success_pct": 100 }
         }
       }
     }
   }
   ```

3. **`GET /api/aggregator/proxy/{gw_id}/history/{device}/{metric}`** — Proxied history request:
   - Aggregator fetches `GET {satellite_base_url}/api/v2/history/{device}/{metric}` on demand
   - Returns the satellite's response directly to the client
   - 404 if gateway ID unknown

### Implementation:

- Add routes to `canHandle()` and `handleRequest()` in `HistoryWebHandler`
- Conditionally register routes only when `AGGREGATOR_ENABLED == 1`
- Read from `SatelliteCache` for gateways/live endpoints
- For history proxy: use `esp_http_client` to fetch from satellite and relay response

### ⚠️ CRITICAL: LESSON-OPS-056 Compliance

The history proxy endpoint forwards satellite history responses which can be 20KB+ (NVS data). You MUST:
- Use pre-reserved `std::string` with `csv.reserve(estimated_size)` for the proxied response
- Send via zero-copy `beginResponse(200, "text/plain", data, len)`
- **NEVER** use `beginResponseStream` for the proxy response
- Set a reasonable max response size (32KB) — reject larger responses with 413

## Device testing (for human, after merge)

### Prerequisites — pull, compile, flash aggregator

```bash
cd /config/ESP32-GW-multi-sensor
git pull origin main

cat VERSION
# Expected: 7.5.5.2

# Ensure config/aggregator.json exists and points to satellite:
cat config/aggregator.json
# Expected: satellite base_url matches your satellite IP

python3 scripts/render_sensor_config.py --write
esphome compile firmware/esp32-c3-multi-sensor.yaml
esphome run firmware/esp32-c3-multi-sensor.yaml --device <aggregator-ip-or-serial>
```

### Verification

```bash
# 1. Verify aggregator gateway list:
curl -s http://<aggregator-ip>/api/aggregator/gateways | python3 -m json.tool
# Expected: JSON with satellite(s), reachable: true, firmware_version, sensor_count

# 2. Verify aggregator unified live data:
curl -s http://<aggregator-ip>/api/aggregator/live | python3 -m json.tool
# Expected: gateway → devices → metric values from satellite

# 3. Verify history proxy:
curl -s "http://<aggregator-ip>/api/aggregator/proxy/gw-main/history/office/temp" | head -5
# Expected: CSV data (epoch,value lines) fetched from satellite

# 4. Verify 404 for unknown gateway:
curl -s -o /dev/null -w "%{http_code}" "http://<aggregator-ip>/api/aggregator/proxy/nonexistent/history/office/temp"
# Expected: 404

# 5. Verify satellite endpoints still work normally:
curl -s http://<satellite-ip>/api/v2/live | python3 -m json.tool
# Expected: Normal satellite response, unaffected

# 6. Check aggregator heap after proxy request:
curl -s http://<aggregator-ip>/api/status | grep free_heap
# Expected: Heap stable, recovers after proxy response
```

### Report results

Record: all API response shapes, heap values, proxy latency. ANY heap leak from proxy requests is a blocker.
