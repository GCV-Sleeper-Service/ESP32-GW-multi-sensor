### 5a. Create `tests/fixtures/variants/aggregator/` directory

This fixture set simulates an aggregator with 2 satellites: one reachable, one unreachable.

### 5b. Extend `tests/mock-server/server.js` for aggregator mode

Add routes that activate when `FIXTURE_SET=aggregator`:

```js
// Aggregator endpoints (only when FIXTURE_SET=aggregator)
if (process.env.FIXTURE_SET === 'aggregator') {
  app.get('/api/aggregator/gateways', (req, res) => {
    const fixture = loadFixture('aggregator-gateways.json');
    res.json(fixture);
  });
  
  app.get('/api/aggregator/live', (req, res) => {
    const fixture = loadFixture('aggregator-live.json');
    res.json(fixture);
  });
  
  app.get('/api/aggregator/proxy/:gwId/history/:device/:metric', (req, res) => {
    const { gwId, device, metric } = req.params;
    const filename = `history-${gwId}-${device}-${metric}.csv`;
    try {
      const csv = loadFixtureText(filename);
      res.type('text/plain').send(csv);
    } catch(e) {
      res.status(404).send('Not found');
    }
  });
}

// When NOT aggregator fixture set, /api/aggregator/gateways returns 404
// (this is what makes satellite-mode detection work)
if (process.env.FIXTURE_SET !== 'aggregator') {
  app.get('/api/aggregator/gateways', (req, res) => {
    res.status(404).send('Not found');
  });
}
```

**Critical:** When `FIXTURE_SET` is NOT `aggregator`, the `/api/aggregator/gateways` endpoint must return 404. This ensures satellite-mode dashboard tests work correctly — `detectAggregatorMode()` sees 404 and stays in satellite mode.

### 5b¾. Add `waitForAggregatorReady()` test helper

Add to `tests/browser/dashboard.spec.js` near the existing `waitForDashboardReady` function:

```js
async function waitForAggregatorReady(page, options = {}) {
    const timeout = options.timeout || 15000;
    await page.waitForFunction(() => window._aggregatorReady === true, { timeout });
}
```

**CRITICAL:** Aggregator test group tests use `waitForAggregatorReady(page)` instead of `loadDashboard(page)`. Do NOT call `loadDashboard()` in aggregator tests — it gates on `getSensors().length > 0` which is wrong in aggregator mode (the aggregator may have no local sensors, or `getSensors()` is not populated in the same way).

## ADDENDUM: Multi-Board and Zero-Sensor Awareness (added 2026-03-22)

### Aggregator fixture set design

The `aggregator` fixture set should simulate a pure aggregator with:
- Empty or minimal local sensor manifest (the aggregator may have zero local sensors)
- Valid `/api/aggregator/gateways` response with 2 mock satellites
- Valid `/api/aggregator/live` response with mock live data from both satellites
- Mock satellites showing a mix of environmental and network devices

**Fixture directory:** `tests/fixtures/variants/aggregator/`

Contents:
- `manifest.json` — empty devices array (pure aggregator) or minimal local-only manifest
- `aggregator-gateways.json` — mock satellite list with reachable/unreachable states
- `aggregator-live.json` — mock unified live values
- `sensors.json` — empty or minimal for aggregator role

### Test readiness signal

Aggregator-mode tests must wait for `window._aggregatorReady === true` instead of `App.State.getSensors().length > 0` (which may be 0 on a sensorless aggregator).

Add a `waitForAggregatorReady(page)` helper:
```js
async function waitForAggregatorReady(page) {
  await page.waitForFunction(() => window._aggregatorReady === true, { timeout: 10000 });
}
```

### BUG-057 / LESSON-OPS-068 awareness

If any test infrastructure needs to reference socket-level behavior, ensure all lwIP calls use `lwip_*()` prefixed functions. This is unlikely for Playwright tests (browser-side only) but relevant if mock server code touches sockets directly.
