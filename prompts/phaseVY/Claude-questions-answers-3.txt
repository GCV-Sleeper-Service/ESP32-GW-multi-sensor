This is a real process finding that should go into the Phase V closure analysis (Q6) and into future prompt-writing guidance. Line number references in step prompts decay every time a prior step merges, and the decay is worst in shared files like firmware/core/web-handler.h where every Phase V sub-phase added code. A few options for Phase 7 prompt authoring:

Prefer function/identifier anchors over line numbers. find the loop in handle_aggregator_gateways_ that iterates satellite_caches[] is stable across commits. line ~1431 is not.
When line numbers are used, tag them as-of-plan-write-date explicitly. E.g. line ~1431 (as of 2026-04-13) — at least makes the staleness visible.
Regenerate line references immediately before execution. A cheap script could grep -n the anchors the prompt cares about and patch the prompt right before the operator hands it to an agent. One line of work vs. full-session stall.
