### 4. New lessons or critical rules?

**Candidate Critical Rule 56 — Version bumps are out of scope for test-only PRs:**
When a prompt's scope is limited to test infrastructure changes (no dashboard source,
build scripts, or CSS), the version bump (VERSION file, App.version, fixtures, firmware
YAML) must NOT be performed. Version bumps belong in the step that delivers code changes.
_Source: v7.6.5.7 PR #148 — three agents attempted version bumps before revert._

**Candidate Critical Rule 57 — Pre-existing files in split targets must be audited for
helper deduplication:**
When splitting a monolithic test file into domain-scoped files, any pre-existing spec
file that receives new test groups must be audited for duplicate helper functions. If
the pre-existing file defines local copies of functions that now exist in the shared
helpers module, the local copies must be replaced with imports.
_Source: v7.6.5.7 PR #148 — `manifest.spec.js` had divergent local copies._

**LESSON-OPS-123 — Multi-agent remediation chains are error-prone:**
PR #148 involved 4 agent sessions across 2 platforms (Copilot, Claude). Each
remediation attempt introduced new issues (version mismatch → artifact regeneration
→ full revert needed). For future multi-session PRs, assign a single agent platform
and use a single remediation prompt rather than incremental fixes.

**LESSON-OPS-124 — Changelog per-file tables must include all Playwright-discovered
files, not just split deliverables:**
`sensor-count.spec.js` was pre-existing and not part of the split, but Playwright
discovers and runs it alongside the split files under `FIXTURE_SET=3sensor`. Any
summary table of per-file results must include ALL files that contribute to the
reported total, with a "(pre-existing)" annotation for non-deliverable files.
