### 4. New lessons or critical rules?

**Candidate LESSON-OPS-XXX-A** _(assign final number at next lessons update)_

> **"DO-NOT: change test files" constraints in prompts must exempt version stamp updates.** When a version bump is part of the step scope, fixture files that contain version strings (`api-status.json`, `manifest.json`, etc.) must be updated to reflect the new version or version-checking tests will fail. A blanket "DO-NOT: change test files" creates a false compliance violation. Future prompts should read: "DO NOT change test logic or test structure; fixture version stamps are updated as part of the standard version bump procedure."

**Candidate Critical Rule 47** _(for consideration)_

> **The `build-dashboard.sh` pipeline step must be added to `bump-version.sh` before the step that would otherwise leave `dashboard.html` out of sync.** Once `build-dashboard.sh` exists, `bump-version.sh` must call `build-dashboard.sh --write` after `render_sensor_config.py --write` and before any `--check` step. Failure to do this means `build-dashboard.sh --check` fails on every post-bump preflight run.

**LESSON-OPS-091 update** _(already in place from v7.6.5.1 — updated pipeline now includes Step 3)_

The canonical regeneration pipeline is now a 6-step sequence. Step 3 (`build-dashboard.sh --write`) was added at v7.6.5.2:

```
Step 1: bash scripts/bundle-dashboard.sh --write
Step 2: python3 scripts/render_sensor_config.py --write
Step 3: bash scripts/build-dashboard.sh --write          ← NEW at v7.6.5.2
Step 4: bash scripts/minify-dashboard.sh
Step 5: bash scripts/generate-header.sh
Step 6: python3 scripts/render_sensor_config.py --check
```

### 5. Context that carries forward to v7.6.5.3

### Was whitespace handling exact (no prettification, no encoding changes)?

**Yes.** The Python implementation uses `bytes.replace(placeholder, js, 1)` — pure binary exact-text substitution. No `import re`, no `import html`, no `import bs4`. All file I/O uses binary mode (`rb`/`wb`). The placeholder count guard (`placeholder_count != 1` → error) prevents silent multi-replace. This approach is correct and sufficient for Level 2.

### Does `bump-version.sh` now use the pipeline instead of `sed` on `dashboard.html`?

**Yes.** The redundant `sed -i "s/App\.version = 'v[0-9.]*'/App.version = 'v${NEW_VER}'/" dashboard/dashboard.html` line was removed from `bump-version.sh`. Version propagation to `dashboard.html` now flows through the canonical pipeline: `src/00-app-shell.js` → `bundle-dashboard.sh` → `dashboard.js` → `build-dashboard.sh` → `dashboard.html`. This resolves LESSON-OPS-043 (mirror problem) at the bump pipeline level.

### Did the `<!-- GENERATED -->` header get added to `dashboard.html` output?

**No — and this is correct at Level 2.** Adding a `<!-- GENERATED -->` comment to the output would have altered the first bytes of `dashboard.html`, causing the bit-for-bit gate to fail (the gate proves equivalence to the hand-maintained version). The header should be added at v7.6.5.3 when generated output becomes canonical and the equivalence constraint is lifted.
