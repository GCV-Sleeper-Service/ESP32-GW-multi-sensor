### 4. New lessons or critical rules?

**Candidate Critical Rule 51 — CRLF-tolerant marker replacement:**
`build-dashboard.sh` template-marker resolution must use
`re.sub(rb'{{COMPONENT:([a-z0-9-]+)}}\r?\n', ...)` — never `bytes.replace()` with a
hardcoded `\n`. On CRLF-checked repositories `bytes.replace(b'...\n', ...)` silently
produces un-assembled output (the literal marker string appears in the HTML). Use `re.sub`
with `\r?\n` throughout any file-assembly pipeline.
_Source: v7.6.5.5 PR #146 external review finding._

**Candidate Critical Rule 52 — `devDependencies` + `npx` for build tools:**
Build tool dependencies invoked from shell scripts must be declared as `devDependencies`
in `package.json` and called via `npx` in scripts — never as global-only requirements.
Global-only tooling causes silent CI mismatches on fresh installs where the tool may not
be present.
_Source: v7.6.5.5 PR #146 CODEX/GPT review finding._

**LESSON-OPS-119 — Non-contiguous DOM targets produce accepted exceptions:**
When the architecture plan lists multiple DOM identifiers as targets for a single component
template, verify that all listed identifiers form a contiguous DOM block before extraction.
If identifiers are non-contiguous (separated by other components' DOM), they must remain
in the shell and be documented as accepted exceptions. The plan's target table should be
updated after each level to reflect what actually lives in the shell vs. components.

**LESSON-OPS-120 — Accepted exceptions require dual documentation:**
Any justified deviation (accepted exception) must be documented in BOTH the session log
(§ Accepted Exceptions) AND the changelog (dedicated section) before closing the step.
A deviation documented in only one place is invisible to future operators reading the
other artifact.

### Issue classifications

**Security omission (High):** The prompt specified marker replacement but did not require
component-name validation or path confinement. The agent's initial implementation accepted
any string between `{{COMPONENT:` and `}}`. A malformed marker like
`{{COMPONENT:../../etc/passwd}}` could traverse outside `components/`. Fix: `^[a-z0-9-]+$`
regex guard + `os.path.realpath` / `os.path.commonpath` confinement added in `edf8d0d`.
**Prompt change that would prevent this:** Add a security constraint to §5 of the
coding agent prompt: "Component name must match `^[a-z0-9-]+$`. Validate with regex
before constructing any file path. Use `os.path.realpath` + `os.path.commonpath` to
confirm the resolved path is under `dashboard/components/`."

**Dependency placement (Medium):** `html-minifier-terser` is a build tool with no
runtime role. Placing it in `dependencies` causes it to be installed in production
environments. This was not specified in the original prompt — the agent reproduced the
existing placement without auditing it. Fix: moved to `devDependencies`; `minify-dashboard.sh`
updated to use `npx html-minifier-terser`.
**Prompt change that would prevent this:** Add to §8 Documentation Updates: "Verify that
any build-only tool added or used by the build scripts is declared in `devDependencies`,
not `dependencies`."

**CRLF fragility (Medium):** `bytes.replace(b'{{COMPONENT:name}}\n', component_bytes)`
silently fails on Windows-style CRLF line endings because the marker ends with `\r\n`,
not `\n`. The literal marker would appear in the assembled HTML unchanged. Fix: changed
to `re.sub(rb'\{\{COMPONENT:([a-z0-9-]+)\}\}\r?\n', ...)` in `c1ae068`.
**Prompt change that would prevent this:** Add to §5c: "Marker replacement must use
`re.sub` with `\r?\n` to handle both LF and CRLF line endings. Never use
`bytes.replace()` with a hardcoded `\n` for line-ending-aware replacement."
