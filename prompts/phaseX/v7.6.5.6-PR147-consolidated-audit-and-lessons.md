### 4. New lessons or critical rules?

**Candidate Critical Rule 53 — Lambda replacement for CSS/JS injection in `re.sub`:**
When using `re.sub()` or `re.subn()` with raw file contents as the replacement, always use
a lambda function — never pass raw bytes directly. CSS and JS commonly contain backslash
sequences (`\1`, `\2`, `\n`, etc.) that `re.sub` interprets as backreferences or special
sequences when the replacement is a plain string/bytes.
_Source: v7.6.5.6 PR #147 Gemini review finding (HIGH severity), fixed in commit 50562c9._

**Candidate Critical Rule 54 — Escalate contradictory acceptance criteria, never self-waive:**
When an acceptance criterion (e.g., "byte-identical output") is contradicted by another
requirement (e.g., "one file per component" when original source is interleaved), the agent
must stop and escalate to the operator. The agent must NOT silently waive the criterion and
proceed. Document the contradiction in the session log § Accepted Exceptions after operator
confirms the waiver.
_Source: v7.6.5.6 PR #147 — agent self-waived the output-identity gate without escalation._

**Candidate Critical Rule 55 — CSS partition by selector target, not source proximity:**
When extracting CSS from a monolithic stylesheet into per-component files, the assignment
rule is "by selector target" (which component does this rule style?) — never "by source
proximity" (which rules are adjacent in the original file?). Global responsive `@media`
rules that target selectors from multiple components belong in `core/base.css` regardless
of where they appear in the original source.
_Source: v7.6.5.6 PR #147 — global `@media` blocks initially misplaced in
`gateway-panel/styles.css`._

**LESSON-OPS-121 — Prompt example code is production code:**
The `re.sub` example in the v7.6.5.6 prompt (§5c) had a backreference vulnerability.
Agents copy prompt examples verbatim. All code examples in prompts must be reviewed
for correctness, security, and edge cases before publication.
_(Reinforces LESSON-OPS-084 from Phase 6 audit.)_

**LESSON-OPS-122 — Interleaved CSS cannot produce byte-identical per-component output:**
When original CSS rules for different components are physically interleaved (not grouped
by component), extracting into one-file-per-component necessarily changes the rule order.
Future CSS extraction steps must use "normalized semantic equivalence" as the diff gate,
not byte-identical comparison. The evidence must include: (a) sorted byte comparison
showing 0 difference, and (b) specificity analysis confirming cascade equivalence.

### Issue classifications

**Backreference corruption (High):** The prompt §5c example code showed
`re.sub(rb'...', css_bytes + b'\n', content)` — when `css_bytes` contains sequences
like `\1`, `re.sub` interprets them as backreferences, corrupting the output. Fix:
changed to `re.subn(pattern, lambda m: css_bytes + m.group(1), content, count=1)`.
**Prompt change required:** Update §5c example to use lambda replacement.

**Output-identity gate (Blocking → Accepted exception):** Byte-identical output is
mathematically impossible when original CSS is interleaved across component boundaries.
The prompt simultaneously requires (a) one CSS file per component and (b) byte-identical
concatenated output — these are mutually exclusive for interleaved source. Resolution:
normalized semantic equivalence accepted as the gate. All CSS bytes preserved; specificity
analysis confirms cascade equivalence.
**Prompt change required:** Future CSS/HTML extraction prompts should use "normalized
semantic equivalence" as the diff gate with defined evidence requirements.

**Global `@media` misplacement (Medium):** Agent grouped by source proximity (these
blocks appeared between the custom-range and gateway-panel CSS in the original file)
rather than by the prompt's selector-target rule. The three blocks target selectors from
6 different components. Fix: moved to `core/base.css`.
**Prompt change that would prevent this:** The §5a table already explicitly maps these
to `core/base.css`. The agent failed to follow the table. Adding a boldface warning
("VERIFY: no `@media` blocks in any component file that target selectors from other
components") to the post-implementation checks might help.
