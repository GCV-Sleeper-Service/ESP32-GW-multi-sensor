| Original item | Why removed |

## 4. Known Issues (Not Phase X Blockers)

### 4a. Hardcoded C3 Flash/SRAM in template

`dashboard/dashboard.tmpl.html` lines 715-716 contain:

```html
<span class="device-info-value">400 KB</span>           <!-- SRAM — wrong for S3 -->
<span class="device-info-value">4 MB (ESP32C3FN4)</span> <!-- Flash — wrong for S3 -->
```

These should either be made dynamic (populated via SSE like Chip/Cores/Features) or
injected from the board profile during the build. **File a bug** — this is pre-existing
and not caused by Phase X.

### 4b. SSE ERR_CONNECTION_RESET on S3 aggregator

The SSE `/events` stream drops shortly after connection. This prevents:
- Telemetry chart data flow
- Device info field population
- Live sensor value updates

Root cause is likely the HTTP server connection pool on the S3 being overwhelmed by
concurrent aggregator polling + SSE + dashboard requests. **File a bug** — this is a
firmware-level issue, not a dashboard JS problem.

### 4c. No visible version badge

`App.version` is set but has no dedicated DOM element. The version only appears in the
footer's `lastUpdate` span after data flows. Consider adding a `<span id="versionBadge">`
to the template in a future step. Not urgent.
