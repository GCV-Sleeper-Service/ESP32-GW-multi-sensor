## 5. Exact Scope

### 5a. Split `tests/browser/dashboard.spec.js` into domain-scoped test files

| Target file | Groups | Approx lines |
|-------------|--------|-------------|
| `tests/browser/boot-structure.spec.js` | 1–3 | ~80 |
| `tests/browser/sensor-cards.spec.js` | 2, 11, 17, 18 | ~200 |
| `tests/browser/history-charts.spec.js` | 4, 5, 13, 16 | ~300 |
| `tests/browser/theme-export.spec.js` | 6, 7, 8 | ~80 |
| `tests/browser/metric-formatters.spec.js` | 12 | ~60 |
| `tests/browser/regression.spec.js` | 14, 15 | ~200 |
| `tests/browser/aggregator.spec.js` | 19 | ~130 |
| `tests/browser/system-devices.spec.js` | 20 | ~60 |
| `tests/browser/satellite-management.spec.js` | 21 | ~210 |
| `tests/browser/test-helpers.js` | Shared setup, fixture detection, skip guards, `loadDashboard()` | ~100 |

**Note on group 2:** Groups that logically overlap (e.g., boot structure includes sensor card presence checks) may appear in multiple files. Determine group-to-file assignment by reading the test content, not just the group number. The plan's table is a starting point — adjust if needed to avoid splitting a single `test.describe` block across files.

**Note on manifests:** `tests/browser/manifest.spec.js` may already exist as a separate file (groups 9, 10). If so, leave it as-is and do not duplicate those groups.

### 5b. Extract shared helpers into `test-helpers.js`

Move shared utilities into `tests/browser/test-helpers.js`:
- `loadDashboard()` helper function
- Fixture detection logic
- Skip guard patterns (e.g., `test.skip(fixtureSet !== 'aggregator', ...)`)
- Any other shared setup used by multiple test files

Each domain test file imports from `test-helpers.js`:
```javascript
const { loadDashboard, getFixtureSet } = require('./test-helpers');
```

### 5c. Handle `dashboard.spec.js`

Two options:
- **Option A:** Remove `dashboard.spec.js` entirely if Playwright auto-discovers all `*.spec.js` files in the directory (check `playwright.config.js` `testMatch` setting).
- **Option B:** Keep `dashboard.spec.js` as an empty file or as a re-export that imports all sub-specs.

Prefer Option A if the config supports it.
