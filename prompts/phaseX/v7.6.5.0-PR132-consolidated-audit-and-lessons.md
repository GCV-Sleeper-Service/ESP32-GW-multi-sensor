### 4. New lessons or critical rules?

**Candidate LESSON-OPS-098** _(for LESSON-OPS register — assign final number at next lessons update)_

> **Bundle scripts must validate CLI flags strictly; lenient defaults can silently overwrite generated artifacts on typos.** A `--write` / `--check` flag script should reject any argument not in that set. Permissive argument parsing (e.g., ignoring unknown flags and defaulting to `--check`) creates a footgun: `--wirte` triggers a silent no-op check instead of the intended write, leaving the bundle stale without any error.

**Candidate LESSON-OPS-099** _(for LESSON-OPS register — assign final number at next lessons update)_

> **For Level 1 (HTML frozen), any version sourcing must be driven from the frozen HTML, and bump-version side effects on HTML must be reverted or blocked.** The preflight and all tooling must key off the frozen artifact (`dashboard.html`) to detect any unintended drift. If the build system writes to HTML during a version bump, that write must be reverted before the step is considered complete.

### 5. Context that carries forward to v7.6.5.1

- The canonical regeneration pipeline for all subsequent Phase X steps is: `bundle-dashboard.sh --write` → `render_sensor_config.py --write` → `generate-fixtures.js` → `minify-dashboard.sh` → `generate-header.sh` → `render_sensor_config.py --check`. The bundler must run first to avoid wiping generator markers.
- Identity gate (SHA-256 before = after bundle) remains the primary Level 1 acceptance check.
- `dashboard.html` stays unchanged at Level 1; all version sourcing must read from it.
- Bundler now requires explicit `--write` or `--check`; strict arg validation in place.
- External review pre-existing findings (escaping gaps, device/sensor count precedence, `safeJsonResponse` usage) are deferred to a follow-up PR — see pre-existing issues table in Section 3 below.
