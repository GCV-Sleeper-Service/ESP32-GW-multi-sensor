| `.gw-*`, `.settings-*` | `components/gateway-panel/styles.css` | |

**Rules for CSS extraction:**
- **Preserve cascade order.** The order CSS rules appear in the extracted files, when
  concatenated by the build script, must match the order they appear in the original
  `<style>` block.
- **If a CSS rule targets elements across component boundaries, keep it in `core/base.css`.**
- **Responsive `@media` rules that are component-specific** go with the component.
  Global breakpoints stay in `core/base.css`.
- **No minification, no autoprefixing, no prettification.** Extract exactly as written.
- **Shell-resident elements** (`.about-bar`, `.export-*`) — keep their CSS in
  `core/base.css` regardless of the component they are logically associated with.

### 5c. Update `scripts/build-dashboard.sh` for three-pass assembly

```
Pass 0: Concatenate core/base.css + components/*/styles.css in cascade order.
        Replace {{CSS_PLACEHOLDER}} in dashboard.tmpl.html.
        → Produces CSS-complete template.

Pass 1: Resolve {{COMPONENT:name}} template markers (existing — do not change).
        → Produces fully-assembled HTML shell.

Pass 2: Inject dashboard.js at {{JS_PLACEHOLDER}} (existing — do not change).
        → Produces final dashboard/dashboard.html.
```

**CRITICAL — Pass 0 marker replacement must use `re.sub` with `\r?\n`** (same CRLF-
tolerant pattern as the existing Pass 1). Never use `bytes.replace()` with a hardcoded
`\n`:

```python
# Correct
content = re.sub(rb'\{\{CSS_PLACEHOLDER\}}\r?\n', css_bytes + b'\n', content)

# Wrong — breaks on CRLF repos
content = content.replace(b'{{CSS_PLACEHOLDER}}\n', css_bytes + b'\n')
```

The CSS concatenation order in the build script must be explicit — no glob-based
discovery. List files in the order matching the original cascade.
