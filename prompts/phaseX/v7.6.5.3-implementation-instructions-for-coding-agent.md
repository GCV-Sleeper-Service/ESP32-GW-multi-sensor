### 5a. Add `build-dashboard.sh` step to CI workflow

In `.github/workflows/browser-tests.yml`, add `bash scripts/build-dashboard.sh --check` after the bundle check and before Playwright.

### 5b. Add `<!-- GENERATED -->` header to built `dashboard.html`

Modify `scripts/build-dashboard.sh` so the output starts with:

```html
<!-- GENERATED — Do not edit. Source: dashboard/src/*.js + dashboard.tmpl.html -->
```

This comment is added by the build script, NOT by editing `dashboard.tmpl.html`. The script prepends the comment to its output.

**IMPORTANT:** After adding this header, `dashboard.html` will no longer be byte-identical to the pre-Level-2 version (it has one extra line at the top). This is expected. The acceptance gate is now: `build-dashboard.sh --check` passes (generated matches committed). The old bit-for-bit gate against the hand-maintained original is retired.

### 5c. Update `scripts/bump-version.sh`

Find the `sed` command that operates on `dashboard.html` (approximately line 66). Replace it with a pipeline re-run:

```bash
# Old (remove):
# sed -i "s/v[0-9]*\.[0-9]*\.[0-9]*\.[0-9]*/v${VERSION}/" dashboard/dashboard.html

# New (add after the existing sed on dashboard.js and other source files):
```

The version bump now flows through the pipeline: `bump-version.sh` updates version strings in source modules → bundle → generator → build-html. No direct edits to `dashboard.html`.
