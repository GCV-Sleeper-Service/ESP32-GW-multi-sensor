## 5. Exact Scope

### 5a. Add `dashboard_js_bundle_sync` check to `scripts/preflight.sh`

Add a new check function that runs `bundle-dashboard.sh --check` and reports pass/fail. Place it in the existing check sequence, after the existing dashboard sync checks.

```bash
dashboard_js_bundle_sync() {
  echo "Checking dashboard.js bundle sync..."
  if bash scripts/bundle-dashboard.sh --check; then
    pass "dashboard.js matches source modules"
  else
    fail "dashboard.js is out of sync with source modules — run: bash scripts/bundle-dashboard.sh --write"
  fi
}
```

Add the function call to the main check sequence.

### 5b. Add bundle check to CI workflow

In `.github/workflows/browser-tests.yml`, add a step that runs `bash scripts/bundle-dashboard.sh --check` **before** the Playwright test step. This ensures any PR that edits a module without rebundling fails CI.

```yaml
      - name: Verify dashboard bundle sync
        run: bash scripts/bundle-dashboard.sh --check
```

Place this after the existing fixture generation / preflight steps and before Playwright.

### 5c. Update regeneration pipeline documentation

Update LESSON-OPS-091 in `Docs/lessons/build-pipeline.md` to include the bundle step. The canonical pipeline is now:

```
1. bash scripts/bundle-dashboard.sh --write

4. bash scripts/minify-dashboard.sh
5. bash scripts/generate-header.sh
6. python3 scripts/render_sensor_config.py --check
```

**Note:** Running the bundler first avoids wiping generator markers; the generator runs once immediately after bundling.
