## Exact scope

Add `/api/v2/history/{device_id}/{metric_key}` endpoint. This reads from `SensorEntity` history buffers (RAM only — no NVS reads).

**Key difference from legacy endpoint:** The legacy `/history/{id}/temp` reads NVS + RAM (synchronous, blocking, up to 1080 blob reads). The v2 endpoint reads RAM ring buffer ONLY. This is intentional — during dual-write, SensorEntity history buffers contain only post-boot data. Full NVS integration comes in v7.5.3.8.

**Changes:**
1. Add `handle_api_v2_history_()` method
2. URL parsing: extract `device_id` and `metric_key` from path after `/api/v2/history/`
3. Look up device by `id` in `devices[]` array, find metric index by matching `metric_defs[].key`
4. Return 404 if device not found, metric not found, or `history_enabled == false`
5. Stream from `metric_states[index].history` HistoryBuffer in `epoch,value\n` CSV format
6. Add route to `canHandle()` and `handleRequest()`
7. Add preflight check
8. Update changelog, session log, bump to `7.5.3.7`

**Response format:** Same `epoch,value\n` CSV as legacy endpoints.

## ⚠️ CRITICAL: BUG-043 LESSON-OPS-056 Compliance ⚠️

**The v2 history endpoint is RAM-only (96 entries max = ~2KB response), so `beginResponseStream` is technically safe. HOWEVER, to establish the correct pattern for when NVS integration is added in v7.5.3.8, you MUST use the pre-reserved string pattern:**

```cpp
void handle_api_v2_history_(AsyncWebServerRequest *request, const char *rest) const {
    // ... parse device_id, metric_key, find device/metric ...
    
    // Use pre-reserved string pattern (LESSON-OPS-056)
    std::string csv;
    csv.reserve(buf->count() * 20 + 64);
    buf->append_csv_to(csv);  // Use the string-based method, not stream_to()
    
    auto *resp = request->beginResponse(
        200, "text/plain",
        reinterpret_cast<const uint8_t *>(csv.data()), csv.size());
    resp->addHeader("Cache-Control", "no-store");
    request->send(resp);
}
```

**Do NOT use `beginResponseStream` + `stream_to()` — even though it would work for RAM-only data, it sets a bad precedent that will cause heap exhaustion when NVS data is added.**
