## Exact scope

Add the `/api/v2/live` endpoint to `sensor_history_multi.h`. This endpoint reads current values from `SensorEntity devices[]` (which is receiving data via dual-write since v7.5.3.3).

**Changes:**
1. Add `handle_api_v2_live_()` method to `HistoryWebHandler` class
2. Add route to `canHandle()`: `if (strcmp(p, "/api/v2/live") == 0) return true;`
3. Add dispatch to `handleRequest()`: `if (strcmp(p, "/api/v2/live") == 0) { handle_api_v2_live_(request); return; }`
4. Add preflight check: verify `/api/v2/live` route exists in source
5. Update `Docs/changelog.md`, create session log
6. Bump version to `7.5.3.6`

**Response format:**
```json
{"timestamp":1710264000,"devices":{"office":{"temp":23.4,"hum":45.2,"batt":87.0,"rssi":-62.0,"last_seen":1710263985},...}}
```

**Do NOT:** Change dashboard JS, remove SensorSlot, or proceed to v7.5.3.7.

---

## Critical rules

1. Use `::time(nullptr)` not `time(nullptr)` (ESPHome convention)
2. Use `resp->printf()` for formatted output
3. Handle `valid == false` metrics with `null` JSON value
4. Include `last_seen` per device
5. Follow existing endpoint patterns in `handle_status_()` and `handle_api_manifest_()`
6. Use `bump-version.sh 7.5.3.6`, regenerate artifacts, run preflight
