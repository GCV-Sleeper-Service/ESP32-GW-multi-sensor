### 4. New lessons or Critical Rules?

**LESSON-OPS (candidate for next index update):**

- **LESSON-OPS-NEW-A:** When a prompt checkpoint grep is broader than the intended verification target (e.g., `.h"` matches both module entries and other script strings), the agent should stop and report rather than self-adjusting the expected count. Prevention: derive checkpoint greps from anchored patterns (`^  "firmware/core/.*\.h"$`) or use `--list | grep -c` on the assembly script's own output. (Rule 64 reinforced.)
- **LESSON-OPS-NEW-B:** When a Playwright `--grep` argument is a common English word (e.g., `"System"`, `"Aggregator"`), it will over-match unrelated test names. Always use spec-file targeting for fixture-specific gate commands. Use `--grep` only when the string is unique to the intended suite.
- **LESSON-OPS-NEW-C:** ESPHome does not allow a per-tag log level to be more verbose than the global level. When firmware requires `ESP_LOGI` output, the global `logger.level` must be `INFO` or lower. Use per-tag suppressors (`wifi: ERROR`, `api: ERROR`) to control noise rather than relying on a `WARN` global.
- **LESSON-OPS-NEW-D:** `uxTaskGetStackHighWaterMark()` in this ESP-IDF fork returns stack watermark in **bytes**, not words. Do NOT multiply by `sizeof(StackType_t)`. Log the raw value directly.

**No new Critical Rules were added in this step** (Rules 65–67 were pre-populated from Phase 7 planning — this step merely confirmed them as correct).
