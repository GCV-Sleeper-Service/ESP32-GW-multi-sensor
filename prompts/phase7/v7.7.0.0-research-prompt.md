## Context

BUG-075 taught us that ESPHome's `HTTPD_DEFAULT_CONFIG()` hardcodes the httpd task stack at 4 KB — and `CONFIG_HTTPD_STACK_SIZE` in sdkconfig has zero runtime effect. This was only discovered after production crashes. The fix (local component override at `firmware/local_components/web_server_idf/`) took 3 PRs and produced 5 Critical Rules (38–42).

**The question this audit answers:** What other ESPHome component defaults could surprise us the same way?

## §2 — Audit Targets

Examine the ESPHome 2026.4.1 source code for each of these components. The ESPHome source is typically at `~/.esphome/` or can be browsed at `https://github.com/esphome/esphome` (tag `2026.4.1`).

### Target 1: Web Server (esp_http_server)

**Source paths:**
- `esphome/components/web_server_base/web_server_base.cpp`
- `esphome/components/web_server_base/web_server_base.h`
- ESP-IDF `esp_http_server` defaults in `HTTPD_DEFAULT_CONFIG()`

**Look for:**
- `max_uri_handlers` — how many URI handlers can be registered? Our project registers 15+ handlers.
- `max_resp_headers` — response header buffer limit.
- `recv_wait_timeout` / `send_wait_timeout` — socket timeouts.
- `max_open_sockets` — connection limit (relates to BUG-084).
- `backlog_conn` — TCP backlog depth.
- `lru_purge_enable` — whether least-recently-used connection purging is active.
- Any buffer sizes for request parsing, header parsing, or URI parsing.

### Target 2: WiFi Component

**Source paths:**
- `esphome/components/wifi/wifi_component.cpp`
- `esphome/components/wifi/wifi_component.h`
- ESP-IDF `wifi_init_config_t` defaults (`WIFI_INIT_CONFIG_DEFAULT()`)

**Look for:**
- `sta_scan_interval` / scan frequency — how often does ESPHome scan for networks?
- Reconnect behavior — backoff strategy, maximum retries.
- `wifi_tx_buf_type` / `wifi_rx_buf_num` — buffer allocation sizes.
- Power management settings.
- DHCP client timeout.

### Target 3: BLE Component

**Source paths:**
- `esphome/components/esp32_ble_tracker/esp32_ble_tracker.cpp`
- `esphome/components/esp32_ble_tracker/esp32_ble_tracker.h`

**Look for:**
- BLE scan window / interval — how aggressively does it scan?
- Advertisement processing task stack size.
- Maximum tracked devices.
- Scan duration before restart.
- Any task priorities that could compete with httpd.

### Target 4: NVS Component / Preferences

**Source paths:**
- `esphome/components/esp32/preferences.cpp`
- ESP-IDF NVS library defaults

**Look for:**
- Maximum namespace count per partition.
- Maximum entries per namespace.
- NVS page size and sector alignment.
- Commit frequency / write coalescing.
- Encryption defaults (if any).

### Target 5: OTA Component

**Source paths:**
- `esphome/components/esphome/ota/ota_esphome.cpp`
- `esphome/components/ota/`

**Look for:**
- OTA receive buffer size.
- Timeout values for OTA transfers.
- Task stack size for OTA processing.
- Whether OTA task competes with httpd task for heap.
