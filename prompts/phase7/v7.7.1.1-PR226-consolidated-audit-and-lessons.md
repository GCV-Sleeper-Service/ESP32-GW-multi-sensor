## 1. Objective

Replace CSV-in-RAM history handlers (`handle_history_()` and `handle_api_v2_history_()`) with `httpd_resp_send_chunk()` streaming, eliminating the heap-growth pattern that crashed C3 and WROOM boards after ~3 weeks of retained history (BUG-082).

**Root cause of BUG-082:** `std::string csv` with `csv.reserve()` allocates a worst-case heap block upfront. As NVS segment count grows after weeks of operation, the reservation size exceeds available heap on non-PSRAM boards (C3 SuperMini: ~58 KB free heap at boot). A single large history export could allocate and populate a >40 KB string before any bytes were sent, pushing `min_free_heap` below safe thresholds and triggering crashes.

**Fix:** Stream each NVS segment and each RAM buffer entry directly through `httpd_resp_send_chunk()` using ~512 B stack-local buffers. Peak heap cost per history request is now bounded by the stack frame, not by total history size.

## 4. Scope Deviations

Four files were modified outside the prompt's declared scope. All are warranted.

### 4.1 `firmware/core/aggregator-runtime.h`

**What:** Added `recv_exact_()`, `recv_crlf_line_()`, `read_chunked_body_()`, updated `fetch_to_buffer()` to detect and dechunk upstream `Transfer-Encoding: chunked` history responses. Case-insensitive token-based `Transfer-Encoding` parsing added. Truncation handling drains remainder before socket close.

**Why:** Converting `/api/v2/history` to chunked transfer changed what `fetch_to_buffer()` received over the wire. Without dechunking, the aggregator proxy would serve HTTP chunk-size framing lines as CSV data to dashboards — silent production breakage with no firmware crash to alert the operator.

**Scope rule intended to protect:** `handle_aggregator_proxy_()` handler logic. That function was not modified. Only `fetch_to_buffer()` was updated — the utility that reads raw socket bytes — making the rule's spirit intact.

**Validated:** Live `.191` proxy request after flashing aggregator to v7.7.1.1 returned `Content-Length: 1632` and plain CSV rows.

### 4.2 `scripts/render_sensor_config.py`

**What:** Now emits a generated `on_boot` step that calls `start_health_check_task_()` for production board YAML output.

**Why:** Without this, no `HEALTH:` line appears in generated WROOM/C3 YAML. NI-002 validation (required by the Phase 7 prompt) was permanently unverifiable — not a timing problem, a structural one.

### 4.3 `firmware/boards/esp32-wroom-32d.yaml`

**What:** Removed `logger.baud_rate: 0`.

**Why:** `baud_rate: 0` suppresses UART serial output. Serial capture is a required evidence channel for NI-001/NI-002. Without removing it, the board profile actively prevents the operator from collecting the evidence the prompt requires.

### 4.4 `AGENTS.md`

**What:** WROOM IP corrected from `192.168.120.190` to `192.168.120.170`.

**Why:** Stale IP. Every future operator validation step in Phase 7 would attempt to connect to a non-existent device.

## 8. Lessons for v7.7.1.2+

### 8.1 Prompt authoring

1. **State scope assumptions explicitly.** When a `⛔` exclusion is predicated on an assumption, write the assumption: _"Do not modify `aggregator-runtime.h` — the aggregator proxy is assumed to be encoding-transparent to `/api/v2/history`."_ If the assumption is falsified, the agent has a documented basis to deviate.

2. **Distinguish hard prohibitions from pragmatic exclusions.** Hard prohibitions (never touch dashboard source logic) should carry `⛔ HARD — do not cross regardless`. Pragmatic exclusions (don't touch this unless the core change breaks it) should carry `⛔ SOFT — document and justify any deviation in session log`.

3. **Audit encoding/format changes for all consumers.** When a step changes wire encoding (chunked, compressed, binary vs. text), list all known consumers of that endpoint in the prompt and either scope them in or state the transparency assumption explicitly.

4. **Whitelist version-bump side effects.** Prompts that require `bump-version.sh` should list all files the script modifies so agents do not face a false choice between running the canonical pipeline and violating the scope rule.

5. **Pair `--write` before `--check` in assembly gates.** Any checkpoint that follows a fragment edit should explicitly run `assemble-sensor-history.sh --write` before the identity `--check`. The current implicit ordering has caused repeated stops.

6. **Use current `tests/browser/*` spec paths.** Pre-split `tests/*.spec.js` paths in Playwright gate commands are stale. All Phase 7 prompts should reference `tests/browser/sensor-cards.spec.js`, `tests/browser/system-devices.spec.js`, `tests/browser/aggregator.spec.js`.

7. **Include production IP and YAML filename in every device-test section.** Hard-code `.170` (WROOM) and `esp32-wroom-32d-gw.yaml` in NI-001/NI-002 gates. Do not rely on AGENTS.md being read first.

### 8.2 Agent behaviour

1. When a scope rule is falsified by the change itself, stop, document in session log ("Stops and Recoveries"), apply minimum fix, call out in PR body under a dedicated heading.
2. Never run Playwright fixture suites in parallel when they share a configured `webServer.port`.
3. Before relying on serial-gate evidence, confirm: correct production IP, correct YAML target, `logger.level: INFO`, no `baud_rate: 0`, `start_health_check_task_()` in `on_boot`.

### 8.3 Review patterns to watch in Phase 7

- **Buffer boundary / dropped-data risk** — chunked streaming with fixed-size local buffers is inherently vulnerable to off-by-one flush thresholds. Future steps adding new streaming handlers should use `append_csv_line_chunk_()` as the established pattern.
- **Error-path termination** — any handler that starts a chunked response must call `finalize_chunked_response_()` on all exit paths. This pattern should be enforced in code review for all new streaming handlers.
- **Encoding transparency assumption** — any future step that changes wire encoding on an endpoint consumed by the aggregator must explicitly audit `fetch_to_buffer()` and its call chain.
