## 5. Exact Scope

### 5a. Add new persistence structs to `sensor_history_multi.h`

Add these AFTER the existing `SegmentSnapshot` struct definition and BEFORE the `allocate_snapshot_()` function. The old structs must remain untouched.

```cpp
// ─── Per-device persistence v2 (v7.7) ────────────────────────────

static constexpr uint32_t DEV_HIST_MAGIC = 0x44485632UL;   // "DHV2" — distinct from HISTORY_META_MAGIC
static constexpr uint16_t DEV_HIST_VERSION = 1;
static constexpr int MAX_PERSIST_METRICS = 6;

static_assert(MAX_PERSIST_METRICS >= 2,
              "MAX_PERSIST_METRICS must cover at least temp+hum for ThermoPro");

struct DeviceHistoryMeta {
  uint32_t magic = DEV_HIST_MAGIC;
  uint16_t version = DEV_HIST_VERSION;
  uint16_t metric_count;
  uint16_t points_per_segment = PERSIST_POINTS_PER_SEGMENT;
  uint16_t max_slots;
  uint16_t valid_segments = 0;
  uint16_t next_slot = 0;
  uint16_t last_written_slot = 0xFFFF;
  uint32_t last_persist_epoch = 0;
  char     device_id[16] = {};
};

static_assert(sizeof(DeviceHistoryMeta) == 36, "DeviceHistoryMeta size must be exactly 36 bytes");

struct DeviceSegmentHeader {
  uint32_t magic = DEV_HIST_MAGIC;
  uint16_t version = DEV_HIST_VERSION;
  uint16_t metric_count;
  uint16_t points_per_segment = PERSIST_POINTS_PER_SEGMENT;
  uint32_t saved_at_epoch = 0;
  uint32_t first_epoch = 0;
  uint32_t last_epoch = 0;
};

struct DeviceSegment {
  DeviceSegmentHeader header;
  uint16_t counts[MAX_PERSIST_METRICS] = {};
  HistEntry data[MAX_PERSIST_METRICS][PERSIST_POINTS_PER_SEGMENT] = {};
};

static_assert(sizeof(DeviceSegment) == 226, "DeviceSegment size must be exactly 226 bytes");
```

**CRITICAL:** Verify both `static_assert` lines compile. If the sizes don't match 36 and 226, there is a struct packing issue — add `__attribute__((packed))` if needed, but check ESP-IDF alignment requirements first. Packed structs on ESP32 can cause unaligned access faults for 32-bit members.

### 5b. Add FNV-1a hash function and key helpers

```cpp
static uint32_t device_id_hash_(const char *id) {
  if (id == nullptr) return 0;
  uint32_t h = 0x811c9dc5;
  for (const char *p = id; *p; p++) {
    h ^= (uint8_t)*p;
    h *= 0x01000193;
  }
  return h;
}

// dm_HHHHHHHH  (11 chars + null = 12)
static void make_device_meta_key_(const char *device_id, char *key, size_t key_len) {
  if (key == nullptr || key_len < 12) return;
  uint32_t h = device_id_hash_(device_id);
  snprintf(key, key_len, "dm_%08x", h);
}

// ds_HHHHHHHH_NNN  (15 chars + null = 16)
static void make_device_segment_key_(const char *device_id, int slot, char *key, size_t key_len) {
  if (key == nullptr || key_len < 16) return;
  uint32_t h = device_id_hash_(device_id);
  snprintf(key, key_len, "ds_%08x_%03d", h, slot % 1000);
}
```

**VERIFY KEY LENGTHS:** The NVS key limit is 15 characters. `dm_a3f7b2c1` is 11 chars (OK). `ds_a3f7b2c1_000` is 15 chars (exactly at limit — OK). Add a `static_assert` or compile-time check if possible. At minimum, add a comment documenting the lengths.

# Validate persist block
persist = sensor.get("persist", {})
backend = persist.get("backend")
if backend is None:
    # Default based on category
    category = sensor.get("category", "environmental")
    if category == "environmental":
        backend = "flash"
        persist = {"backend": "flash", "priority": "high"}
    elif category == "network":
        backend = "flash"
        persist = {"backend": "flash", "priority": "low"}
    else:
        backend = "ram_only"
        persist = {"backend": "ram_only"}
    sensor["persist"] = persist

    raise ManifestError(f'Device "{name}": persist.backend must be "flash" or "ram_only"')

if backend == "flash":
    priority = persist.get("priority", "high")
    if priority not in ("high", "normal", "low"):
        raise ManifestError(f'Device "{name}": persist.priority must be high/normal/low')
    persist["priority"] = priority

## ADDENDUM: Post-Phase-5/6 Codebase Context (added 2026-03-22)

**Multi-board infrastructure exists.** Board profiles (`firmware/boards/*.yaml`), gateway config (`config/gateway.json`), and per-board partition tables are in the codebase. Phase 7 persistence changes are board-agnostic — `DeviceSegment` and `DeviceHistoryMeta` blobs are the same byte layout on all ESP32 variants. The partition SIZE differs (512KB on C3, 4MB on S3), which affects the retention budget calculation. The budget calculator already uses `esp_partition_find_first()` to read the actual partition size at runtime — no hardcoded sizes.

**Aggregator code exists in `sensor_history_multi.h`.** The `#if AGGREGATOR_ENABLED` block contains ~330 lines of aggregator infrastructure (SatelliteCache, polling task, API endpoints). Phase 7 persistence changes must NOT break the aggregator code. Specifically:
- The new `persist_device_segment_()` and `restore_device_()` functions operate on `devices[]` array entries. The aggregator doesn't persist satellite data locally — it caches JSON strings. No conflict.
- The new `/api/storage-stats` v2 response must work for both satellite (shows per-device persistence stats) and aggregator (shows local device persistence stats, if any local devices exist).
- If the aggregator has zero local persistent devices (`PERSIST_DEVICE_COUNT == 0`), the persist/restore loops execute zero iterations. Verify this.

**`esp_http_client.h` is NOT available.** Phase 7 is persistence-only (NVS reads/writes) — no HTTP client needed. But if any debugging/testing code needs HTTP, use `fetch_to_buffer()` with `lwip_*()` prefixed functions (LESSON-OPS-068).

**Zero-sensor configurations exist.** The generator can produce `NUM_DEVICES = 0`. Phase 7 code must handle:
- `PERSIST_DEVICE_COUNT = 0` — no devices to persist, budget calculator returns immediately
- Empty `PERSIST_DEVICE_IDS[]` array — restore loop iterates zero times
- `/api/storage-stats` returns a valid but empty `devices: {}` object
- Per-device delete API returns 404 for unknown device IDs (no devices = all IDs unknown)

**S3 partition gives 4MB history.** The retention budget calculation with a 4MB partition and 3 ThermoPro + 1 ping produces ~132 days per high-priority device vs ~19 days on C3's 512KB. The budget scenarios in the persistence architecture doc (Section 7.3) should be validated with the S3 partition size as well.
