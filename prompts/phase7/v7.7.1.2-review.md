## Checks of this step

```text
S1. Layout. The structs of S1 have no implicit padding: each measured size equals the sum of its
    members, and the five size assertions carry the numbers that the block measure printed (the
    session log holds its output). The same assertions compile on the C3 (RISC-V) and the WROOM
    (Xtensa) builds.
S2. EventLog. The class meets item 1.3 of the prompt: members, order, constexpr, behaviour at the
    edges (empty, full, out of range, null pointers, zero epochs). T1 passes because the class
    behaves, not because the test was weakened: T1 is byte-identical to the prompt.
S3. Keys. device_id_hash_ is FNV-1a 32-bit; the keys are lowercase hex, 11 and 15 characters;
    "no key" for a null or empty id and for a slot outside 0 to 4,095. T2 is byte-identical to the
    prompt. No snprintf, no #include, no allocation in the new code.
S4. Generator. The generated lines equal item 3.1 for config/sensors.json; a system device is not
    listed; the order is the manifest order; a manifest with no listed device gives count 0 and the
    three placeholders. The fragment and the assembled header hold the same generated block.
    manifest_v2() and the served manifest are unchanged.
S5. Nothing else changed: no existing struct, class, function or constant; no fragment added; the
    old engine (SegmentSnapshot, HistoryMeta, PERSIST_SLOTS) untouched; the side effects of
    bump-version.sh and the pipeline only where section 3 lists them.
S6. Device evidence. The outputs of the blocks dev for .189 and .170 (before and after the
    upload), c3heap within 2,048 B of 52,080 B, the 24-hour reading of wroom24, the image size of
    the C3 build against its OTA slot. Each output is verbatim in the PR body and the session log.
S7. Documents. CURRENT-STATE.md (version, Last verified, What Just Shipped, Next action, the two
    fleet rows, the row "WROOM heap", the stale-document row), the plan of record (row 8, "You
    are here"), the changelog entry with the measured sizes, the two notes in the architecture
    doc, the session log (Rule 63) and the record with its five process metrics.
S8. No login. The blocks dev and wroom24 read $ESP_USER and $ESP_PASS inside python3; no command,
    file, log or comment of the PR holds a login value.
```
