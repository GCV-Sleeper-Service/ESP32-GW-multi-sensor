#### 1a. `firmware/boards/esp32-s3-supermini-4m.yaml`

```yaml
# ESP32-S3 SuperMini — Board Profile
# Small-form S3 satellite with 2MB PSRAM. Tests small-PSRAM satellite role.
# Same chip as the S3 DevKitC aggregator but with less PSRAM (2MB vs 8MB) and less flash (4MB vs 16MB).
board_id: "esp32-s3-supermini-4m"
chip_variant: "esp32s3"
esphome_board: "esp32-s3-devkitc-1"
flash_size: "4MB"
partitions: "../partitions/esp32-s3-4m-multi-partitions.csv"
framework:
  type: "esp-idf"
sdkconfig_options:
  CONFIG_LWIP_MAX_SOCKETS: "15"
psram:
  mode: "quad"
  speed: "80MHz"
capabilities:
  ble: true
  psram: true
  dual_core: true
  ram_kb: 512
external_components:
  - source:
      type: local
      path: local_components
    components: [web_server_idf]
notes: "Small-form S3 satellite. 2MB quad PSRAM, 4MB flash. Same partition budget as C3/WROOM."
```

#### 1b. `firmware/boards/esp32-c6-supermini-4m.yaml`

```yaml
# ESP32-C6 SuperMini — Board Profile

board_id: "esp32-c6-supermini-4m"

```

#### 1c. `firmware/boards/esp32-c5-wroom1u-8m.yaml`

```yaml
# ESP32-C5-WROOM-1U (MCN8R8) — Board Profile
# First C5 in fleet. RISC-V single core 240 MHz, WiFi 6 dual-band (2.4 + 5 GHz),
# BLE 5.0, 802.15.4 (Zigbee/Thread). 8 MB flash, 8 MB PSRAM.
board_id: "esp32-c5-wroom1u-8m"
chip_variant: "esp32c5"
esphome_board: "esp32-c5-devkitc-1"
flash_size: "8MB"
partitions: "../partitions/esp32-c5-multi-partitions.csv"
framework:
  type: "esp-idf"
sdkconfig_options:
  CONFIG_LWIP_MAX_SOCKETS: "15"
  CONFIG_XTAL_FREQ_48: "y"
psram:
  mode: "quad"
  speed: "80MHz"
capabilities:
  ble: true
  psram: true
  dual_core: false
  ram_kb: 384
external_components:
  - source:
      type: local
      path: local_components
    components: [web_server_idf]
notes: "First C5 satellite. Dual-band WiFi 6 + Zigbee/Thread. 8MB PSRAM, 8MB flash. CONFIG_XTAL_FREQ_48 required for this board's 48 MHz crystal."
```

⚠️ **Critical: `CONFIG_XTAL_FREQ_48: 'y'`** — the C5-WROOM-1U uses a 48 MHz crystal. Without this, esptool shows crystal mismatch warnings and clock-dependent features may malfunction. The `'y'` value is a Kconfig boolean, not a string — but ESPHome sdkconfig_options pass it as YAML strings to the build system.

```csv
otadata,    data, ota,      0xD000,   0x2000,
```
