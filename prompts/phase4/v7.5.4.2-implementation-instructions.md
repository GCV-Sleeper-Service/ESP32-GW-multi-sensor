## Exact scope

Add `CARD_RENDERERS.network` to the dashboard to render the WAN ping probe as a network card.

### Step-by-step:

1. **Implement `buildNetworkCard(device)` function** in `dashboard.js`:
   - Card header: device name (e.g., "WAN Latency")
   - Current latency value with unit (e.g., "12.3 ms")
   - Success rate percentage (e.g., "100%")
   - Target host display (from manifest `source.target`)
   - Last seen indicator
   - Keep card styling consistent with environmental cards but visually distinct (different accent color or icon)

2. **Register `CARD_RENDERERS.network = buildNetworkCard`** in the renderer registry.

3. **Add metric formatters:**
   - `METRIC_FORMATTERS.ping_latency = function(value, unit) { return value.toFixed(0) + ' ' + unit; }`
   - `METRIC_FORMATTERS.success_rate = function(value) { return value.toFixed(0) + '%'; }`

4. **Update `handleState()` / state update flow** to recognize non-environmental polling state updates for the network device. The existing SSE/polling flow may need adjustment to handle the ping device's state updates.

5. **Add network card CSS** — styles for the network card layout. Keep consistent with existing card dimensions and theming (dark/light mode).

6. **Mirror changes to `dashboard.html`** (LESSON-OPS-043) — copy the updated JS and CSS into dashboard.html.

7. **Regenerate `dashboard.h`** via `scripts/generate-header.sh` (gzip-compressed, LESSON-OPS-055).

8. **Update changelog, session log, bump to 7.5.4.2**

### Critical regression constraint:

**Environmental cards must be PIXEL-IDENTICAL to pre-Phase-4.** ThermoPro card layout, values, formatting, dew point, comfort estimate, min/max, battery, RSSI — all unchanged. Test this visually on the real device.
