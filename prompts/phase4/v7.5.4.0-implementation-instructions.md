## Exact scope

Add ping probe device to manifest and generator. **No firmware adapter yet** — the ping device exists in the data model but produces no data at runtime.

### Step-by-step:

1. **Upgrade `config/sensors.json` to v2 schema** — Add `schema_version: 2`, convert existing sensors to v2 format with `category: "environmental"`, `adapter: "thermopro_ble"`. Add `wan_ping` device with `category: "network"`, `adapter: "icmp_ping"`, `source: { "target": "8.8.8.8" }`.

2. **Extend `sensor_manifest_lib.py` validation:**
   - `mac` field required only when `adapter == "thermopro_ble"` (or other BLE adapters)
   - `source.target` required when `adapter == "icmp_ping"`
   - Accept both v1 and v2 schema (existing `to_manifest_v2()` still works for v1 input)
   - Validate `category` is one of: `environmental`, `network`, `system`

3. **Extend `render_sensor_config.py`:**
   - Generate separate `MetricDef` arrays per device category (`metrics_thermopro[]`, `metrics_ping[]`)
   - Generate `SensorEntity` for ping device with RAM-only history (`history_enabled: true` but no NVS persistence)
   - Ping device gets 2 metrics: `ping_ms` (latency, analog, ms) and `success_pct` (success rate, analog, %)
   - Update `NUM_DEVICES` to include ping device

4. **Regenerate all artifacts:**
   - `dashboard/sensor_history_multi.h` — now has 4th SensorEntity (3 ThermoPro + 1 ping)
   - `src/gateway_manifest.h` — v2 manifest JSON includes wan_ping device
   - `tests/fixtures/manifest.json` — regenerated with mixed-category data
   - `tests/fixtures/sensors.json` — regenerated

5. **Update test fixtures:**
   - `tests/fixtures/generate-fixtures.js` — handle mixed-category manifest generation
   - Add `tests/fixtures/history-wan_ping-ping_ms.csv` and `history-wan_ping-success_pct.csv` (empty or minimal stub data)

6. **Update `scripts/preflight.sh`** — Add check that manifest contains at least one network-category device (conditional, only when v2 schema with network devices is used)

7. **Update docs:** `Docs/changelog.md` — v7.5.4.0 entry. Create session log.

8. **Bump version** to `7.5.4.0` via `scripts/bump-version.sh`

### Critical constraints:
- Ping device exists in data model but produces no data. `/api/v2/live` should show `null` values for ping metrics.
- All environmental behavior unchanged — ThermoPro cards, history, persistence, import/export all identical.
- `SegmentSnapshot` format unchanged — ping device has no flash persistence.
- Use `::time(nullptr)` not `time(nullptr)` in any C++ code (ESPHome convention)

## Device testing (for human, after merge)

### Prerequisites — pull, compile, flash

```bash
# On your local machine / ESPHome LXC container:
cd /config/ESP32-GW-multi-sensor    # or wherever your local clone lives
git pull origin main

# Verify the version file updated:
cat VERSION
# Expected: 7.5.4.0

# Compile (this validates the generated C++ compiles on ESP-IDF):
esphome compile firmware/esp32-c3-multi-sensor.yaml
# Expected: Compilation successful. Look for "4 devices" or similar in the build output.

# OTA flash to your device:
esphome run firmware/esp32-c3-multi-sensor.yaml
# Wait for "Successfully uploaded" and device reboot.
```
