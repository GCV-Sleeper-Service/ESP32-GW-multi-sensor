## 5. Exact Scope — ICMP Ping Adapter

Implement ICMP ping adapter as a periodic RTOS task that feeds data into the `wan_ping` SensorEntity.

### 5a. Add ping adapter code

Add a `PingAdapter` class to `dashboard/sensor_history_multi.h` (below the `SensorEntity` struct, before the endpoint handlers):

- Use ESP-IDF `ping/ping_sock.h` API (not raw ICMP sockets — the ping API handles LWIP integration)
- Create a FreeRTOS task that runs every 60 seconds
- Per cycle: send 3 ICMP pings to configured target (default: 8.8.8.8), 200ms spacing
- Compute average RTT (ms) and success rate (%)
- Call `devices[PING_DEVICE_INDEX].add_sample(0, avg_rtt)` for ping_ms
- Call `devices[PING_DEVICE_INDEX].add_sample(1, success_pct)` for success_pct
- Call `devices[PING_DEVICE_INDEX].mark_seen(::time(nullptr))`
- Handle DNS resolution failure gracefully — mark metrics invalid, don't crash
- Handle WiFi-down gracefully — skip ping cycle, log warning

### 5b. Compile-time ping device index and target

The generator (`render_sensor_config.py`) must produce:
- `#define PING_DEVICE_INDEX N` — the 0-based index of the `icmp_ping` device in `devices[]`
- `#define PING_TARGET "8.8.8.8"` — from `source.target` in the manifest
- Only generate these defines if an `icmp_ping` device exists in the manifest

Add these to `render_entity_block()`, after the `NUM_SENSORS` line:


### 5c. ⚠️ CRITICAL: Add `compute_averages()` call for ping device in YAML interval lambda

**This is the most important implementation detail.** The current YAML `interval:` lambda (inside the `SENSOR_MANIFEST:AVERAGING_BEGIN/END` marker block) only calls `compute_and_format()` for ThermoPro devices. The ping device's `HistoryBuffer` will never receive data unless `compute_averages()` is called on the same 15-minute cycle.

You must update `render_sensor_config.py` to extend the averaging block:

In `render_yaml_averaging()` (or a new companion function), after the ThermoPro averaging lines, add a call for each non-ThermoPro device that has history-enabled metrics:

```python
def render_yaml_averaging(sensors: List[Dict[str, str]], all_sensors: List[Dict] = None) -> str:
    """Generate the interval averaging lambda. 
    sensors = ThermoPro-only (existing behavior).
    all_sensors = full list including ping devices (new)."""
    lines = [YAML_AVG_BEGIN]
    for idx, sensor in enumerate(sensors):
        lines.extend(avg_lines(sensor, idx))
    
    # Add compute_averages() for non-ThermoPro devices
    if all_sensors:
        for i, s in enumerate(all_sensors):
            if s.get("adapter") != "thermopro_ble" and s.get("adapter") == "icmp_ping":
                sid = s["id"]
                lines.extend([
                    f" // ── {s['name']} (network) ──────────────────────────────",
                    f" devices[{i}].compute_averages(epoch);",
                    "",
                ])
    
    while lines and lines[-1] == "":
        lines.pop()
    lines.append(YAML_AVG_END)
    return "\n".join(lines)
```

Update the call site (around line 445) to pass the full sensor list:

```python
text = apply_yaml_marker_block(text, YAML_AVG_BEGIN, YAML_AVG_END,
    unwrap_marker_body(render_yaml_averaging(ble_sensors, all_sensors=sensors), 
                       YAML_AVG_BEGIN, YAML_AVG_END))
```

**Why this matters:** Without this change, `devices[3].metric_states[0].history` (ping_ms HistoryBuffer) and `devices[3].metric_states[1].history` (success_pct HistoryBuffer) will never receive averaged entries from the accumulator. The `add_sample()` calls from the adapter populate the accumulator, but `compute_averages()` is what transfers the averaged value into the HistoryBuffer. If you skip this, `/api/v2/history/wan_ping/ping_ms` will return empty data forever.

### 5d. YAML adapter initialization

Add adapter initialization in the YAML `on_boot:` lambda (priority 600 or later, after WiFi):

```yaml
on_boot:
  priority: 600
  then:
    - lambda: |-
        #ifdef PING_DEVICE_INDEX
        static PingAdapter ping_adapter;
        ping_adapter.start(PING_DEVICE_INDEX, PING_TARGET);
        #endif
```

The `PingAdapter::start()` method should call `xTaskCreate()`:
- Stack size: 4096 bytes
- Priority: `tskIDLE_PRIORITY + 1` (lowest non-idle)
- The task function should be a static method

### 5e. Critical single-core constraints (from BUG-043 lessons)

- The ESP32-C3 is **single-core**. The ping task MUST `vTaskDelay()` between pings to yield to BLE/WiFi/HTTP
- Total ping cycle execution: ~600ms (3 pings × 200ms). Acceptable if it yields between pings
- Do NOT run pings from the main loop or a timer lambda — use a dedicated low-priority RTOS task
- Stack size: 4096 bytes minimum for the ping task (LWIP needs buffer space)
- Priority: `tskIDLE_PRIORITY + 1` (lowest non-idle) or `tskIDLE_PRIORITY + 2` max
- The task must NOT hold mutexes during ping waits

### 5f. Error handling

- If DNS resolution fails: log once, set metrics to `NAN`, mark `valid = false`, retry next cycle
- If WiFi is down: skip cycle entirely, `vTaskDelay(60000 / portTICK_PERIOD_MS)`, try again next cycle
- If ping times out (>3000ms): count as failure for success_pct, exclude from avg_rtt
- If all 3 pings fail: set `ping_ms = NAN` (invalid), `success_pct = 0.0`
