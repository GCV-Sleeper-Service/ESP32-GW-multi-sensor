## 5. Exact Scope — Mixed-Category Test Fixtures + Playwright Tests

Create mixed-category test fixtures and add Playwright tests validating that the dashboard correctly renders both environmental and network device categories simultaneously.

### 5a. Create `tests/fixtures/variants/mixed/` directory

Create fixture files for a mixed-category deployment with 2 ThermoPro + 1 ping device:

| File | Content |
|------|---------|
| `sensors.json` | v1 projection: 2 ThermoPro sensors only (legacy compat — `[{id:"office",name:"Office"},{id:"first_floor",name:"First Floor"}]`) |
| `manifest.json` | Full v2 manifest: 2 ThermoPro + 1 wan_ping device |
| `api-status.json` | Gateway status (same structure as root fixture, version bumped to 7.5.4.3) |
| `storage-stats.json` | Storage stats (same structure as root fixture) |
| `history-office-temp.csv` | ThermoPro temp history (10+ data points, epoch,value format) |
| `history-office-hum.csv` | ThermoPro humidity history (10+ data points) |
| `history-first_floor-temp.csv` | ThermoPro temp history |
| `history-first_floor-hum.csv` | ThermoPro humidity history |
| `history-wan_ping-ping_ms.csv` | Ping latency history (10-20 data points, realistic values 5-50ms) |
| `history-wan_ping-success_pct.csv` | Ping success history (10-20 data points, 95-100%) |

**Critical details for `manifest.json`:**
- Must have `schema_version: 2`
- Environmental sensors: `category: "environmental"`, `adapter: "thermopro_ble"`, each with `measurements` array containing `{key: "temp", history_url: "/history/{id}/temp"}` and `{key: "hum", history_url: "/history/{id}/hum"}`
- Network sensor: `category: "network"`, `adapter: "icmp_ping"`, `source: { target: "8.8.8.8" }`, `measurements` with `{key: "ping_ms", history_url: "/api/v2/history/wan_ping/ping_ms"}` and `{key: "success_pct", history_url: "/api/v2/history/wan_ping/success_pct"}`
- Follow the exact structure produced by `sensor_manifest_lib.py:manifest_v2()` — look at `tests/fixtures/manifest.json` (root) as a reference

**Critical details for history CSV files:**
- Format: `epoch,value\n` per line (no header)
- Timestamps should be recent-ish (within last 24h) and monotonically increasing
- 900-second (15-minute) intervals between points
- Ping latency values: 5-50ms range, realistic
- Success rate values: 95-100%, realistic

### 5d. Add Playwright test Group 17: Mixed-Category Rendering

**Verify the actual next group number** by reading the last `test.describe()` in `dashboard.spec.js`. If Group 16 is the last, use Group 17.

Add to `tests/browser/dashboard.spec.js`:

```js
// ── 17. Mixed-Category Rendering (Phase 4) ─────────────────────
test.describe('17. Mixed-Category Rendering', () => {

  test('mixed manifest renders correct total card count', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 3 }); // 2 env + 1 network
    const cards = page.locator('.sensor-card');
    await expect(cards).toHaveCount(3);
  });

  test('environmental cards have full ThermoPro layout elements', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 3 });
    // Check that environmental cards have temp, hum, dewpoint, comfort elements
    const envCards = page.locator('.sensor-card:not(.network-card)');
    await expect(envCards).toHaveCount(2);
    // Each should have reading-label "Temperature"
    const tempLabels = page.locator('.sensor-card:not(.network-card) .reading-label:text("Temperature")');
    await expect(tempLabels).toHaveCount(2);
  });

  test('network card renders with latency and success rate elements', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 3 });
    const netCard = page.locator('.network-card');
    await expect(netCard).toHaveCount(1);
    // Check for latency element
    await expect(page.locator('#net-ping-wan_ping')).toBeVisible();
    // Check for success rate element
    await expect(page.locator('#net-success-wan_ping')).toBeVisible();
  });

  test('CARD_RENDERERS dispatches correctly by category', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 3 });
    const hasNetworkRenderer = await page.evaluate(() => {
      return typeof CARD_RENDERERS.network === 'function';
    });
    expect(hasNetworkRenderer).toBe(true);
  });

  test('chart canvases exist for environmental devices', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 3 });
    // Environmental devices should have chart canvases
    const tempCanvas = page.locator('#tempChart');
    await expect(tempCanvas).toBeVisible();
  });

  test('/api/v2/live returns data for both device categories', async ({ page, request }) => {
    const response = await request.get('/api/v2/live');
    expect(response.ok()).toBeTruthy();
    const data = await response.json();
    expect(data.devices).toBeDefined();
    expect(data.devices.office).toBeDefined();
    expect(data.devices.wan_ping).toBeDefined();
    expect(data.devices.wan_ping.ping_ms).toBeDefined();
  });

  test('manifest v2 contains both environmental and network devices', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 3 });
    const categories = await page.evaluate(() => {
      if (!window._manifest || !window._manifest.sensors) return [];
      return window._manifest.sensors.map(function(s) { return s.category; });
    });
    expect(categories).toContain('environmental');
    expect(categories).toContain('network');
  });
});
```

**Note on `expectedSensorCount`:** The mixed fixture has 2 ThermoPro + 1 ping = 3 total in SENSORS (since v7.5.4.2 includes all categories). Adjust if needed based on actual implementation.

### Firefox compatibility requirements for ALL new tests:

1. Use the shared `loadDashboard()` / `waitForDashboardReady()` helpers
2. Do NOT add any new `afterEach` hooks — use the existing file-level one
3. Do NOT use `page.goto('about:blank')` anywhere
4. Wait for DOM elements before asserting counts (use `await expect(...).toHaveCount(N)` which auto-retries)
5. For `page.evaluate()` calls, ensure the function checks for null/undefined before accessing properties
6. For test groups that exercise async boot or SSE connections, use `test.setTimeout(90000)` and `loadDashboard(page, { timeout: 30000 })` — Firefox's SSE teardown can block `browserContext.close()` for ~49s (BUG-049)
7. The `stopDashboardNetwork()` helper nulls out EventSource callbacks before `.close()` — do NOT bypass this pattern with direct `evtSource.close()` calls in tests
