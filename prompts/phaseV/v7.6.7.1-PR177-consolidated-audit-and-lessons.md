## 4. Lessons Learned

### LESSON-V1D-001: Multi-sensor import path still blocks on httpd for `clear_persisted_history_()`

**Observation:** The Rule 40 deferred-task fix was correctly scoped to the single-sensor path (`build_import_epoch_map_()`). The multi-sensor path's `clear_persisted_history_()` still runs synchronously on the httpd task. This is the pre-existing behaviour and was not regressions — `nvs_erase_all()` on a single namespace is faster than scanning all segments. However, on a heavily loaded partition it could still stall the httpd task beyond 30 ms.

**Recommendation for V2 backlog:** Consider whether multi-sensor clear also warrants a deferred task. Add as a tracking note in `SEC-ADR-001` or the V2 planning doc. Not v7.6.7.2 scope.

### LESSON-V1D-002: `waitForImportReady()` polling scoped to single-mode path only — correct design

**Observation:** Dashboard JS correctly omits the status-poll loop for multi-sensor mode, because `s_import_ready` is set synchronously (true) before the HTTP response is sent in the multi-sensor path. This is an intentional asymmetry that reviewers should be aware of — it is correct, not a bug.

### LESSON-V1D-003: `/api/import/status` no-auth gate is a deliberate policy decision

**Observation:** The status endpoint returns only a boolean and exposes zero sensitive data. Keeping it public avoids credential exposure in polling loops and is consistent with the principle of minimum necessary auth surface. Document in `SEC-ADR-001` as an explicit approved exception.

### LESSON-V1D-004: Free-heap floor revised upward

**Observation:** Post-import-begin heap reading (70,568 bytes) is well above the 65 KB gate and above the v7.6.7.0 baseline (58,200 bytes). The improvement is explained by the deferred task allocating the epoch map on its own stack + heap outside the httpd path, and by the v7.6.7.0 NAS history disable saving ~2.3 KB. The 65 KB floor for v7.6.7.2 is confirmed safe.
