**Note on proxy 404 responses:** Both proxy curl commands returned `404` regardless of satellite reachability. This is a **pre-existing routing gap**: the proxy handler is not registered for the `/api/aggregator/proxy/…` path in the current firmware version. This is unrelated to v7.6.7.0 code changes (which implemented the internal proxy logic correctly per Playwright validation). The route registration gap was present before this PR and is a separate defect. The `502 + JSON` and `200 + empty body` paths are confirmed correct by Playwright (`aggregator` fixture set: 11 passed / 1 skipped) but were not exercised at device level in this session due to the routing gap.

## 4. Autonomous Decisions — Back-Ported to Prompt Template

Five autonomous decisions were identified across the two reviewer rounds and have been documented here for back-porting into future agent prompts:

| # | Decision | Correct behaviour to specify explicitly |
|---|----------|-----------------------------------------|
| AD-1 | Agent treated `fetch_to_buffer()` returning `false` for HTTP 200 / zero-byte body as correct — it was not | Explicitly state: HTTP 200 + empty body MUST return success with `*out_len = 0`; only non-200 responses are failure |
| AD-2 | Agent disabled NAS history in runtime data model but did not update manifest/generator/fixtures | When disabling metric history, manifest, generator, and fixture contract MUST be updated in the same step |
| AD-3 | Agent built proxy JSON error into a fixed 192-byte buffer with unescaped URL | Proxy diagnostic JSON MUST use safe construction — escape URL or omit URL field; no fixed small buffer |
| AD-4 | Agent ran `render_sensor_config.py` and modified fixture outputs despite prompt exclusion language | If generator changes are needed for reproducibility, put `scripts/render_sensor_config.py` in scope explicitly; do not prohibit and then require it implicitly |
| AD-5 | Agent omitted changelog + session log deliverables in first commit | Session log and changelog entry are non-optional; list them as explicit acceptance criteria with `[ ]` checkboxes in §6 |

## 6. Lessons Learned

### L-001 — Helper return semantics must be stated at the call-site level

When a helper function's success/failure contract changes (here: empty body ≠ failure), the calling code must be explicitly audited. The agent fixed the helper but not the gate in the caller. Future prompts should specify: _"verify that the gate `if (!fetch_to_buffer(…))` is evaluated against the new contract."_

### L-002 — Manifest/runtime changes are always a two-part operation

Disabling a feature in runtime code without updating the manifest is a common agent omission. Pattern: whenever a `history_enabled` flag flips, the same prompt step must include: grep manifest for the metric ID + remove/update the history URL entry.

### L-003 — Two-round reviews are expected for medium-complexity proxy changes

Proxy logic (timeout, status code, body semantics, error JSON) has enough interacting parts that a first-pass agent implementation is unlikely to be correct in all four dimensions simultaneously. Budget one fix round in the PR timeline.

### L-004 — Proxy route registration is a separate concern from proxy internal logic

The device tests revealed a routing gap (`404` on proxy endpoint) that is orthogonal to the internal proxy logic fixes. Route registration must be verified as a device-test checkpoint, not just confirmed via Playwright.
