## Accepted Deviations (no action required)

### D1 — Badge population outside `App.Boot.start()`
**Spec:** First action in `App.Boot.start()`.
**Actual:** `App.Boot.populateVersionBadge()` fires on `DOMContentLoaded` (or immediately if DOM already ready), before `App.Boot.start()` is called.
**Outcome:** Fires *earlier* than spec required. `App.version` is already `'v7.6.7.2'` so the `'v' +` prefix is not missing from the rendered string.
**Lesson:** When the spec intent is "badge visible before transport", a `DOMContentLoaded` guard is strictly better than waiting for `App.Boot.start()`. Future prompts should use this pattern directly.

### D2 — `check_contains_regex` in preflight
**Spec:** `check_contains` (fixed string).
**Actual:** `check_contains_regex 'id="?versionBadge"?'` — handles both quoted and unquoted attribute serialisation.
**Outcome:** More resilient to minifier behaviour. Zero false-negative risk.
**Lesson:** Preflight badge checks should use `check_contains_regex` by default when the target is an HTML attribute, since minifiers may or may not quote attribute values.

## Lessons Learned

### LESSON-REVIEW-001 — `.esphome/build/` grep hits are expected noise
When running `grep -rn` against the full `firmware/` tree after deleting symbols, hits under `firmware/.esphome/build/` are generated ESPHome build artefacts — **not** tracked source. Future prompts should specify:
```bash
grep -rn --exclude-dir=.esphome "pattern" firmware/
```
or equivalently note that `.esphome/build/` hits do not constitute a violation. Add this to the dead-code deletion gate in future agent prompts.

### LESSON-REVIEW-002 — Dashboard badge population: DOMContentLoaded guard preferred over App.Boot.start() injection
For any visual badge/indicator that must appear before network activity starts, the `DOMContentLoaded` guard pattern in `app-shell.js` is the correct integration point — not `App.Boot.start()`. The badge is pure DOM surgery with no dependencies; tying it to the boot sequence unnecessarily couples two orthogonal concerns.

### LESSON-REVIEW-003 — Version in App.version already includes 'v' prefix
`App.version` is defined as `'v7.6.7.2'` (string includes `v`). Code using `badge.textContent = App.version` produces the correct rendered string. Code using `badge.textContent = 'v' + App.version` would produce `vv7.6.7.2`. Future prompts specifying badge population should say `badge.textContent = App.version` — not `'v' + App.version`.

### LESSON-REVIEW-004 — V1 complete; heap floor confirmed for V2 gate decisions
V1 Operator Measurement Protocol steps 1–7 completed on physical C3 running v7.6.7.2. Runtime RAM is 16.5% used (54,128 / 327,680 B). Flash is 82.7% used (1,463,744 / 1,769,472 B). The 65 KB heap floor from v7.6.7.1 remains valid. V2-H/I/J gated optimisation decisions may proceed using these baselines.
