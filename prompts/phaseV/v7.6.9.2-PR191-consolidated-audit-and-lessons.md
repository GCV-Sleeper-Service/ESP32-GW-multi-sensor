## Lessons

1. **Manifest-driven > static arrays.** Replacing `EXPORT_SENSOR_SUFFIXES` with a manifest iterator eliminates the need to update a hardcoded list whenever a new sensor type is added. The pattern generalises cleanly.
2. **Fallback is mandatory.** When manifest is unavailable (first render, offline), the `return ['temp', 'hum']` fallback keeps env sensors working without special-casing. This is the correct backward-compat idiom for manifest-dependent functions.
3. **ADR commit path must be exact.** `Docs/decisions/` (capital D) is the canonical path. Agent prompts should specify the full path explicitly to prevent case-variation errors.
4. **Issue closure accounting.** When an issue was closed by a prior PR in the same phase, document it explicitly in the agent prompt and review checklist rather than expecting the agent to re-close it — this avoids confusion in the PR audit.
5. **Ping and system fixture sets are now first-class.** With manifest-driven columns, `FIXTURE_SET=ping` and `FIXTURE_SET=system` are stable test vectors. Include them in the PRE-PR GATE for all future export-touching steps.
