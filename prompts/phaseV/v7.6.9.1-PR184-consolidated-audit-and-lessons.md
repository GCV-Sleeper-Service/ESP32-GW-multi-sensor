## Findings & Dispositions

### F-01 — `buildMergedSensorCsv()` role heuristic
**Finding:** Role in merged CSV uses `sensors.some(s => s._gwId !== manifest.gateway.id)` heuristic — if any sensor in the batch is from a satellite, the entire row group gets `role='satellite'`. Not per-row resolution.  
**Disposition:** Correct for V3-C scope. The merged export covers a single-gateway-context batch. Per-row manifest-driven role resolution is V3-D scope.  
**Action:** Flag for `v7.6.9.2` agent prompt Do-NOT-change list; add V3-D tracking note.

## Breaking Change Record

**CSV format change — role column inserted at position 3 (index 2)**

Before v7.6.9.1:
```
gateway_host,gateway_ip,timestamp,datetime_utc,...
```

After v7.6.9.1:
```
gateway_host,gateway_ip,role,timestamp,datetime_utc,...
```

Positional parsers that assume `timestamp` at index 2 will break. Named-column parsers are unaffected. Documented in `Docs/changelog.md` and PR #184 description.

## Lessons

1. **Assemble before bump.** `assemble-sensor-history.sh --write` must precede `bump-version.sh`. The version check reads the assembled header, not the fragment.
2. **Scope the JSON search.** `hostname` extraction must be bounded to the `"gateway":{...}` substring pointer — never `strstr` the full manifest. Prevents false matches on nested sensor name fields.
3. **`||` fallback pattern is the correct idiom.** `hostname || name` ensures backward compatibility with satellites that don't yet emit `hostname`. Applied consistently across selector, summary, and settings.
4. **Breaking changes need two-point documentation.** Both changelog entry and PR description required. Session log alone is insufficient.
5. **Per-row vs. batch role resolution.** V3-C merged export uses batch heuristic (correct). V3-D will need per-row resolution if multi-gateway exports per-row roles diverge. Do not pre-implement.
