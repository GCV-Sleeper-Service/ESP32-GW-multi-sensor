## §5 — Implementation Instructions

### Task Group 1: V3-B — Satellite Hostname and IP in Gateways Response

**Step 1.1 — Firmware: extract hostname from manifest**

In `firmware/core/web-handler.h`, in `handle_aggregator_gateways_()`, after constructing the gateways JSON for each satellite:

1. Extract `hostname` from `sat.manifest_json` — search within the `"gateway":{` object only (avoid false matches in sensor names). Use simple string search, not a full JSON parser.
2. Extract `ip` from `sat.base_url` — strip `http://` prefix, take host portion before any port or path.
3. Emit `,\"hostname\":\"...\"` and `,\"ip\":\"...\"` in the JSON response for each satellite.

After edits: `bash scripts/assemble-sensor-history.sh --write`

**Step 1.2 — Dashboard: display hostname and IP**

In `dashboard/components/gateway-panel/index.js`:

- `renderAllGatewaysSummary()`: use `gw.hostname || gw.name` as display name; add IP row
- `renderGatewaySelector()`: use `hostname || name` as tab label
- `renderSettingsPanel()`: add hostname and IP to satellite settings cards

### Task Group 2: V3-C — CSV Export Role Column

**⚠️ BREAKING CHANGE:** The `role` column is inserted at position 3 (after `timestamp`, `sensor_id`). Any existing positional CSV parser will break. This is accepted — document in changelog.

**Step 2.1 — Update `dashboard/core/sensor-defs.js`**

Add `role` to shared columns and create the role getter:

```javascript
var EXPORT_SHARED_COLUMNS = ['timestamp', 'sensor_id', 'role'];

function getExportRole(sensor, manifest) {
  if (!manifest || !manifest.gateway) return 'unknown';
  return manifest.gateway.role || 'satellite';
}
```

**Step 2.2 — Update `dashboard/core/history.js`**

In `buildSingleSensorCsv()`: add `role` column populated by `getExportRole()`.

In `buildMergedSensorCsv()`: add `role` column; apply `sensorSlug(satellite_name) + '_'` prefix to satellite sensor columns in aggregator export.
