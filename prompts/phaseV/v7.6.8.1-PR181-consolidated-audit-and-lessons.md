## 2. Gate-by-Gate Audit Results

### V2-E — History Endpoint Auth + Heap Cap

**`handle_history_()`**
`authenticate_management_(request)` is the first executable line. Comment above it reads:
`// Auth: REQUIRED - large-allocation endpoint, prevents anonymous heap exhaustion (SEC-05)`
This satisfies both the code requirement and LESSON-OPS-110 (auth decision comment mandatory).

**`handle_api_v2_history_()`**
Same pattern — auth guard as first line with matching comment. Consistent with V2-E spec.

**`csv.reserve()` cap**
Both handlers use:
```cpp
csv.reserve(std::min(est_bytes, (size_t)60000));
```
Exact expression matches the gate requirement. The 60 KB cap prevents a single anonymous
request from exhausting the ESP32-C3's ~55 KB free heap. The pre-reservation pattern
(LESSON-OPS-056) is correctly applied — single allocation upfront, no reallocation cascade.

**Rule 8 compliance**
Both handlers use `request->beginResponse(200, "text/plain", reinterpret_cast<const uint8_t*>(csv.data()), csv.size())` —
the raw-bytes overload. No `beginResponseStream` introduced. Rule 8 holds.

---

### V2-F — Per-URL DoS Cooldown on `add-satellite`

**Static array implementation**
Cooldown state declared at file scope in `web-handler.h`:
```cpp
static constexpr int MAX_PROBE_COOLDOWN = MAX_SATELLITES;
static uint32_t s_last_probe_fail_epoch[MAX_PROBE_COOLDOWN] = {};
static char s_last_probe_fail_url[MAX_PROBE_COOLDOWN] = {};
```
- Zero heap allocation — both arrays are in BSS (zeroed at boot)
- Sized to `MAX_SATELLITES` — correct upper bound; no overflow risk
- No `std::map`, no `std::vector`, no `new` — V2-F static-array gate satisfied

**60-second window**
Last-fail epoch stored per URL slot. Re-probe blocked until `now_epoch - s_last_probe_fail_epoch[i] >= 60`. Window is correct.

**429 response**
`send_json_error_(request, 429, ...)` used. The `Retry-After` header path in `send_json_error_()` is wired and will emit the remaining cooldown seconds. Response body includes `{"ok":false,"message":"...","status":429}`.

Neither the `assemble-sensor-history.sh --write` preflight log nor Playwright test output
was attached or linked in the PR description or comments. Reviewer had to flag both as
UNVERIFIED and request author confirmation. **Add preflight + Playwright log attachment
as a required PR checklist item from v7.6.8.2 onward.**

### OBS-3 · Cooldown array placed in `web-handler.h` file scope
The `s_last_probe_fail_epoch` and `s_last_probe_fail_url` arrays are declared at file scope
in `web-handler.h` alongside other handler-local statics (e.g., `s_import_ready`,
`s_delete_data_in_progress`). This is consistent with the existing pattern in the file
and is correct for the ESP32 single-threaded HTTP handler model. No concern.

### OBS-4 · `MAX_PROBE_COOLDOWN == MAX_SATELLITES` sizing
Using `MAX_SATELLITES` as the cooldown array bound is correct and safe — you cannot have
more URLs in cooldown than the maximum number of satellites. No off-by-one risk.

### OBS-5 · Auth comment style consistent with LESSON-OPS-110
Both `handle_history_()` and `handle_api_v2_history_()` carry the `// Auth: REQUIRED - ...`
comment immediately above the guard. Pattern is consistent with `handle_api_ingest_()`,
`handle_status_full_()`, `handle_aggregator_gateways_()`, and other auth-gated handlers
added in V2-A through V2-D. Good hygiene maintained.

## 5. Lessons

### LESSON-REVIEW-001 (new)
**Process gate evidence must be attached to the PR before review begins.**
Preflight script output and Playwright test results cannot be verified from source diff alone.
Add a required PR checklist item: *"Attach `scripts/preflight.sh` output and Playwright
test run log as PR comment or CI artifact before requesting review."*

### LESSON-OPS-088 (reinforced)
**Instruction Compliance Output table is mandatory in every PR description.**
It was missing from PR #180 (flagged), carried forward as a hard requirement for PR #181,
and still absent. Add it as a ⛔ PRE-PR GATE in the v7.6.8.2 agent prompt — block PR
creation until the table is present.

### LESSON-SEC-002 (new)
**DoS cooldown arrays belong at file scope, not inside the class.**
Placing `s_last_probe_fail_epoch` and `s_last_probe_fail_url` at file scope (alongside
other handler-local statics) keeps them out of the class instance and avoids any risk of
accidental copy construction. This pattern should be followed for any future rate-limiting
or cooldown state.

### LESSON-OPS-056 (reinforced)
**`csv.reserve(std::min(est_bytes, CAP))` is now the canonical heap-safe CSV pattern.**
Both `handle_history_()` and `handle_api_v2_history_()` use it. Any future handler that
builds a CSV or large string response must use this pattern with the 60 KB cap.
