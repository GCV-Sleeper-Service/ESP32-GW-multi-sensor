## 2. Gate-by-Gate Audit Results

### V2-H — LWIP Socket Reduction

`CONFIG_LWIP_MAX_SOCKETS` changed from `18` to `"15"` in `firmware/esp32-c3-multi-sensor.yaml`. The string-quoted form `"15"` is correct ESPHome YAML for integer board-level config overrides.

**Floor compliance (LESSON-OPS-051):** Value is `15`, which is above the hard floor of `13`. Gate passes.

**Stability evidence:** Session log documents a 5-minute two-tab test (dashboard + API polling simultaneously) with zero `ENFILE` errors. This satisfies the V1 Operator Measurement prerequisite for V2-H.

**EADDRINUSE collision during Playwright:** Parallel fixture sets triggered a port conflict on the first run. Sequential rerun produced clean results across all five fixture sets. This is a known CI environment issue, not a code defect.

***

### V2-I — ping_adapter Stack Reduction (BLOCKED)

**Watermark reading:** 2,160 B unused out of 4,096 B stack.
**Peak usage:** 4,096 − 2,160 = **1,936 B used**.
**Minimum safe stack:** 1,936 + 2,048 = **3,984 B**.
**Current stack:** 4,096 B.
**Available reduction:** 4,096 − 3,984 = **112 B** — below the 2,048 B headroom gate.

`ping-adapter.h` is correctly absent from the diff. No change made. V2-I remains BLOCKED pending a new measurement showing ≥ 2,048 B headroom.

***

### V2-J — httpd Stack Reduction (BLOCKED)

**Watermark reading:** 260 B unused out of 16,384 B stack.
**Peak usage:** 16,384 − 260 = **16,124 B used**.
**Minimum safe stack:** 16,124 + 2,048 = **18,172 B** — which is *larger* than the current 16,384 B stack.
**Conclusion:** Any reduction would leave negative headroom. `web_server_idf.cpp` and `patch-esphome-httpd-stack.sh` are correctly absent from the diff.

This watermark result is a strong signal that the httpd task encounters significant stack pressure. V2-J is deferred indefinitely until a firmware change produces substantially lower peak usage.

## 3. Observations

### OBS-1 · Instruction Compliance Output table — now present

The mandatory Instruction Compliance Output table was absent from PR \#181 (flagged as OBS-1 there, carried as a ⛔ PRE-PR GATE into this step). It is present in this PR. The enforcement mechanism worked. Carry this gate forward to all future agent prompts.

### OBS-2 · Playwright port collision — sequential rerun pattern

The EADDRINUSE collision occurs when Playwright fixture sets are launched in rapid parallel. The correct fix (sequential launch) is now documented in the session log. Add a note to future agent prompts that Playwright commands must be run sequentially, not backgrounded.

### OBS-3 · V2-J httpd watermark signals stack pressure

260 B of headroom on a 16,384 B httpd stack is worth monitoring. If firmware complexity grows, a stack overflow crash on the httpd task is plausible. Consider making `free_heap_internal` and httpd watermark part of the post-flash device test protocol for every future firmware change.

### OBS-4 · V2-I reduction may never open

At 112 B margin, the ping adapter stack is working at nearly full capacity. The reduction gate may remain blocked for multiple versions. If the `ping_adapter` task can be profiled more granularly (e.g., by removing unused ping result processing), there may be room to reduce peak usage rather than waiting for natural headroom.

### OBS-5 · No-change compliance cleanly enforced

The blocked-gate no-change pattern worked exactly as designed: V2-I and V2-J diff sections were absent, not commented out. This is the correct protocol and should be referenced in future handoffs as the precedent.

## 4. Lessons

### LESSON-OPS-051 (reinforced)

**`CONFIG_LWIP_MAX_SOCKETS` must never be set below 13.**
Value `15` is safe. If a future step reduces further, the floor of `13` is a hard gate. Document this floor in any agent prompt that touches LWIP configuration.

### LESSON-OPS-052 (new)

**Playwright fixture sets must be run sequentially, not in parallel.**
Parallel runs cause EADDRINUSE port collisions in the test environment. Always run the five fixture commands one at a time. Add this as an explicit note in §4 of future agent prompts.

### LESSON-OPS-053 (new)

**Blocked gate → absent diff section (not commented out).**
When a gate is BLOCKED due to insufficient measurement headroom, the corresponding code change must be completely absent from the diff. Commenting out the change is not acceptable — it pollutes the diff and creates risk of accidental re-enable. V2-I and V2-J demonstrate the correct pattern.

### LESSON-OPS-054 (new)

**httpd stack watermark < 1 KB is a canary for stack overflow risk.**
The 260 B reading on V2-J means the httpd task is running within 1.6% of its stack ceiling. Any firmware addition that deepens the httpd call stack (new endpoint, new response serialization, new middleware) should be stress-tested with watermark measurement before merge. Add an explicit httpd watermark check to the post-device-test protocol.

### LESSON-REVIEW-001 (reinforced from v7.6.8.1)

**Process gate evidence must be attached to the PR before review begins.**
Preflight output and Playwright results were present in the session log for this PR. Pattern is now established — maintain it.
