## 3. Findings & Dispositions

### FINDING-V769-01: `update_interval: never` on static text sensors
- **Severity:** High (would have caused blank dashboard fields on initial load)
- **Root cause:** Agent prompt §2.1 specified `update_interval: never` for Flash/SRAM text_sensors. ESPHome does not publish an initial state with `never` — dashboard fields render blank until a manual trigger.
- **Fix:** Changed to `update_interval: 60s`. Static values compute once per minute; negligible overhead.
- **Status:** ✅ Resolved in PR #183
- **Lesson:** For text_sensors returning static compile-time values, `update_interval: 60s` is always safer than `never`. `never` is appropriate only when the value is truly event-driven (e.g., populated via `publish_state()` from a button or automation).

### FINDING-V769-02: Runtime SRAM API returns allocator budget, not total SRAM
- **Severity:** Medium (correct value, misleading label)
- **Root cause:** `heap_caps_get_total_size(MALLOC_CAP_INTERNAL)` returns the allocator-visible heap budget (~255 KB on C3), not the total SRAM die size (400 KB). The difference is caused by memory reserved for the ROM, stack, and other allocators.
- **Fix:** Static strings per chip_variant (C3: `"400 KB"`, WROOM: `"520 KB"`, S3: `"512 KB"`). These match the datasheet values and match user expectations.
- **Status:** ✅ Resolved in PR #183
- **Lesson:** Never use heap allocator APIs to populate "SRAM Size" display fields. Use datasheet values as static strings per board profile.

### FINDING-V769-03: `credentials: 'same-origin'` on `/api/status/full` fails over Cloudflare Tunnel
- **Severity:** Low (known operational limitation, not a code defect)
- **Root cause:** Cloudflare Tunnel strips or rejects cookie credentials on cross-origin requests to the `.trycloudflare.com` domain, causing `loadStatusSnapshot()` to fail when accessed via Tunnel.
- **Fix:** Tracked for v7.6.9.6. No change to current implementation — `credentials: 'same-origin'` is correct for local/LAN access.
- **Status:** ⚠️ Deferred to v7.6.9.6. Documented in release notes.
- **Lesson:** Cloudflare Tunnel access pattern must be tested separately from LAN access pattern for any endpoint that uses cookie-based credentials.

### FINDING-V769-04: History endpoints are public GET (no `authenticate_management_()`)
- **Severity:** Informational (deliberate trade-off)
- **Root cause:** `handle_history_()` and `handle_api_v2_history_()` do not call `authenticate_management_()`. This was a deliberate decision — read-only history is exposed publicly for operational convenience.
- **Fix:** None required. Mutation paths remain auth-gated. Trade-off accepted by Copilot review. SEC-ADR not updated (trade-off is already documented in V2 SEC-ADR).
- **Status:** ✅ Closed — no action required.
