## §5 — Implementation Instructions

### V2-H — CONFIG_LWIP_MAX_SOCKETS (Gate: device validation)

**Gate condition:** Real-device 5-minute test with two browser tabs (SSE + polling). Zero `httpd_accept_conn: error in accept (23)` messages.

**If gate PASSES:**
Change in `firmware/esp32-c3-multi-sensor.yaml`:
```yaml
CONFIG_LWIP_MAX_SOCKETS: "15"
```

**If gate FAILS or not tested:** No change. Document in #165.

**HARD RULE:** Never reduce below "13" (LESSON-OPS-051).

### V2-I — Ping Adapter Stack (Gate: watermark ≥ 512 B headroom)

**Gate condition:** Step 7 watermark shows `4096 - peak_usage ≥ 512`.

**If gate PASSES:**
In `firmware/core/ping-adapter.h`, change:
```cpp
xTaskCreate(ping_task_, "ping_adapter", 2048, ...);
```
Then: `bash scripts/assemble-sensor-history.sh --write`

**If gate FAILS:** No change. Document in #165.

### V2-J — httpd Task Stack (Gate: Step 6 watermark)

**Decision table:**

| Headroom (16384 - peak) | New stack size | Action |
|---|---|---|
| ≥ 6,144 B | 10,240 B | Change |
| ≥ 4,096 B | 12,288 B | Change |
| ≥ 2,048 B | 14,336 B | Change |
| < 2,048 B | 16,384 B | No change |

**HARD RULE:** Never set below `measured_peak + 2,048 B`.

**If change needed:**
1. Edit `firmware/local_components/web_server_idf/web_server_idf.cpp` line ~124: change `config.stack_size = <new_value>`
2. Edit `scripts/patch-esphome-httpd-stack.sh`: update the patched value so future ESPHome upgrades apply the correct size

**If no change:** Document measurement result in #164 and #165.
