## Key Codebase Facts for v7.5.6.1

### Firmware architecture

- `dashboard/sensor_history_multi.h` is the main firmware file (~3270 lines after v7.5.6.0). All API endpoints, `SensorEntity` model, history persistence, aggregator, and now ingest logic live here.
- `SensorEntity.category_id`: 0=environmental, 1=system (unused so far), 2=network. Step 1 adds `category_id=1` devices.
- `config/sensors.json` is the source of truth for all devices. New system devices must be added here.
- `gateway_manifest.h` contains the static JSON manifest — regenerated by `render_sensor_config.py --write`.
- `/api/manifest` serves `GATEWAY_MANIFEST_JSON` (from `gateway_manifest.h`).
- `/api/v2/live` iterates all `NUM_DEVICES` entries — system devices will automatically appear.
- The ingest endpoint (`/api/ingest/`) already works for any registered device+metric — no firmware changes needed for ingest to work with new system devices once they're in the manifest.

### What v7.5.6.1 needs to do

1. Add system device definitions to `config/sensors.json` (e.g., `cpu_pct`, `ram_pct`, `disk_pct` with `category_id: 1` and `adapter: "external_push"`)
2. Define `MetricDef` arrays for system devices (e.g., `metrics_system[]`)
3. Add `SensorEntity` entries in the `devices[]` array with `category_id = 1`
4. Update `NUM_DEVICES` count
5. Run full generator pipeline (Critical Rule 28)
6. Verify `/api/manifest` includes system devices
7. Verify `/api/v2/live` shows system device metrics (as `null` before any ingest)
8. Verify `POST /api/ingest/<system_device>/<metric>?val=<float>` works

### Dashboard architecture

- `CARD_RENDERERS` registry dispatches card rendering by device category.
- `pollV2Live()` polls `/api/v2/live` every 15 seconds — system devices will need a `CARD_RENDERERS.system` renderer (Step 2).
- Step 1 only adds the firmware/manifest side — dashboard rendering is Step 2.

### Generator pipeline

- `config/sensors.json` is the source of truth.
- `render_sensor_config.py --write` produces: `sensor_history_multi.h` entities, `gateway_manifest.h`, `dashboard.js` defaults, test fixtures, YAML blocks.
- Version bumps require BOTH generators (Critical Rule 28):
  ```bash
  bash scripts/bump-version.sh 7.5.6.1
  python3 scripts/render_sensor_config.py --write
  node tests/fixtures/generate-fixtures.js
  bash scripts/generate-header.sh
  python3 scripts/render_sensor_config.py --check
  grep -q "free_heap" tests/fixtures/api-status.json
  bash scripts/preflight.sh
  ```

### CI workaround

`config/gateway.json` and `config/aggregator.json` are gitignored deployment configs. Move them before running generators/tests:
```bash
mv config/gateway.json config/gateway.json.bak 2>/dev/null
mv config/aggregator.json config/aggregator.json.bak 2>/dev/null
# ... run checks ...
mv config/gateway.json.bak config/gateway.json 2>/dev/null
mv config/aggregator.json.bak config/aggregator.json 2>/dev/null
```
