### Critical prompt defects

#### A1 — Internal contradiction: "Do NOT change dashboard JS/HTML" vs mandatory version bump pipeline (Severity: LOW — caused no functional defect but creates ambiguity)

**§6** says "Do NOT change any dashboard JavaScript or HTML"  
**§5d** requires `bash scripts/bump-version.sh 7.5.7.0` which necessarily updates `App.version` in `dashboard.js` and `dashboard.html`

The agent correctly ran the bump (version churn is expected), but the contradiction makes the Do-NOT list technically violated by the agent's correct action.

**Prevention:** Future prompts should say: "No *functional* dashboard JavaScript or HTML changes. Version bump regeneration churn is expected and does not violate this rule."

---

#### A2 — Hardcoded magic number `8192` in prompt-provided Python code block (Severity: LOW — caught by Gemini reviewer, fixed in fixup commit)

**§5c** provides the full `generate_aggregator_config_h()` implementation with `board_cap = 8` and `f"#define AGG_MANIFEST_BUF_SIZE 8192\n"` as literal values.

The prompt emphasizes avoiding magic numbers in the C++ path but provides magic numbers in its own Python code block. Gemini reviewer flagged this; it was fixed in the fixup commit by extracting `SATELLITE_CAP_PSRAM = 8` and `AGG_MANIFEST_BUF_SIZE_BYTES = 8192` as module-level constants.

**Prevention:** Apply Guide §3.13 (prompt code quality gates) to Python snippets equally. When a prompt defines a named constant in one language (C++ `AGG_MANIFEST_BUF_SIZE`), the same value should use a named constant in the other language too.

---

#### A3 — Missing Instruction Compliance Output table in initial delivery (Severity: MEDIUM — caught by Codex review, required fixup commit)

**§8b** requires an "Instruction Compliance Output" table as a mandatory deliverable. The agent's initial session log omitted this table entirely. The Codex reviewer (issuecomment-4146975269) caught the omission and flagged it as a blocking fix. The table was added in the fixup commit (`4336f33`).

The prompt did name it in §8b but the agent still omitted it. Consider adding the table as a template in the session log section with placeholder rows.

## Part III — Lessons

### New Lessons

#### LESSON-OPS-086 — Prompt Do-NOT lists must exclude expected regeneration side-effects

**Source:** v7.5.7.0 PR #93 — Do-NOT list said "no dashboard JS/HTML changes" but `bump-version.sh` necessarily updates `App.version` in those files.

When a prompt says "Do NOT change file X" but also requires a version bump or regeneration pipeline that necessarily touches file X, the prompt contains an internal contradiction. Future prompts should qualify: "No *functional* changes to file X; version bump and regeneration churn is expected."

---

#### LESSON-OPS-087 — Prompt-provided code blocks must apply the same constant policy as the target codebase

**Source:** v7.5.7.0 PR #93 — prompt introduced C++ named constant `AGG_MANIFEST_BUF_SIZE` but provided Python code with bare literal `8192`.

When a prompt introduces a named constant in one language (C++ `AGG_MANIFEST_BUF_SIZE`), the corresponding value in prompt-provided code for another language (Python) should also use a named constant, not a bare literal. The agent copies prompt code faithfully — including inconsistencies.

**Rule:** Before publishing a prompt that contains code blocks in multiple languages, verify that each named constant defined in language A has a corresponding named constant (not a literal) in language B.

---

#### LESSON-OPS-088 — Mandatory deliverable tables should be templated with placeholder rows

**Source:** v7.5.7.0 PR #93 — prompt required Instruction Compliance Output table (§8b) but agent omitted it from the session log.

When a prompt requires a specific table as a deliverable (e.g., Instruction Compliance Output), include a template with placeholder rows in the session log section. An empty template is harder to overlook than a prose instruction to "provide a table."

**Rule:** The session log section of any prompt that requires a compliance table must include a template like:

```markdown
| Requirement | File(s) Changed | How Satisfied | Verified? |
|---|---|---|---|
| _placeholder_ | _placeholder_ | _placeholder_ | ☐ |
```
