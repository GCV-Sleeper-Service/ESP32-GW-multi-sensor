### Critical prompt defects

#### A1 — `import os` and `import shutil` inside functions, not at module level (Severity: HIGH — caused 3 review comments)

**Lines 170–171, 175, 191, 200 of the prompt-provided Python code:** `import os` and `import shutil` appear inside function bodies (`get_disk_usage()`, `get_ram_usage_macos()`). This violates PEP 8 (E402 — module level import not at top of file). All three automated reviewers flagged it.

**Impact:** The agent faithfully reproduced the imports-inside-functions pattern. Three review comments (r2996339848 from Gemini, implied in Copilot R1/R2 comments) required a dedicated fix commit.

**Root cause:** The prompt author embedded the platform-specific imports at call site to make the code look self-contained in the code block. This is a prompt convenience that becomes a code quality defect when copied verbatim by the agent.

**Fix applied in commit 3 (`9ab8f28`):** All stdlib imports moved to module top level.

**Prevention:** Before committing a prompt, run all embedded Python code through `pylint --disable=all --enable=C0411` (import order). Imports must always appear at module top level, even in prompt-provided code that exists solely as a template.

#### A2 — macOS RAM placeholder returns `50.0` instead of `0.0` (Severity: HIGH — caused 2 review comments, merge-blocking)

**Line 193 of the prompt-provided Python code:** `get_ram_usage_macos()` returns `50.0` as a hardcoded placeholder. This contradicts the documentation claim in §5c that "unsupported metrics return `0.0` safely." Returning `50.0` would display a 50% RAM bar on the dashboard for macOS hosts that have not implemented the metric.

**Impact:** Two review comments (r2996339818 Gemini, r2996351198/r2996351253 Copilot R1/R2). The discrepancy between `return 50.0` and the documentation text "returns 0.0" was independently caught by two reviewers. This was the only merge-blocking defect.

**Fix applied in commit 2 (`8e19dfc`):** Changed `return 50.0` → `return 0.0`.

**Prevention:** Any unsupported-platform path MUST return the documented safe default. In this codebase the convention is `0.0`. The prompt should have stated this explicitly: "All unsupported-platform stub functions MUST return `0.0`, not a non-zero placeholder."

#### A3 — CPU docstring says "1-second sample" but code uses load average (Severity: MEDIUM — caused 2 review comments)

**Line 165 of the prompt-provided Python code:** `"""Approximate CPU usage (1-second sample)."""`. The function body calls `os.getloadavg()` and `os.cpu_count()` — not a 1-second CPU sample. The docstring is factually wrong.

**Impact:** Caught by Gemini (r2996339841) and confirmed by Copilot R2 (r2996525354 implicitly). Required a fix commit.

**Fix applied in commit 3:** Docstring corrected to `"Approximate CPU usage from 1-minute load average, normalized by core count."`.

**Prevention:** Docstrings in prompt-provided code must match the implementation. When providing code that uses load average as a CPU proxy, the docstring must say "load average" — not "sample."

#### A4 — No `LC_ALL=C` on `top` command in bash script (Severity: MEDIUM — caused 2 review comments)

**Line 129 of the prompt-provided bash script:** The `top` invocation does not prefix `LC_ALL=C`. On non-English locales, `top` outputs decimal separators, column headers, and metric labels that differ from the `awk` patterns the script uses. This would produce non-numeric strings (e.g., `"45,2%"` instead of `"45.2"`) on German or French systems.

**Impact:** Caught by Gemini (r2996339852) and Copilot R1 (r2996351235). Required a fix commit.

**Fix applied in commit 3:** `LC_ALL=C` added to the `top` invocation.

**Prevention:** Any prompt-provided shell script that parses command output MUST include `LC_ALL=C` for locale-dependent commands (`top`, `df`, `free`, `date`). Add this as a mandatory quality gate in `writing-prompts-for-coding-agents-guide.md` §3.2.

---

#### A5 — Bash metric values not sanitized before interpolation into curl URL (Severity: MEDIUM — caused 2 review comments)

**Line 138 of the prompt-provided bash script:** The `curl` invocation interpolates `CPU_PCT`, `RAM_PCT`, etc. directly into the query string without sanitization. If `top` or `awk` produces a string with `%`, `us,`, or other non-numeric characters (which can happen on locale-variant systems or when `top` output changes between versions), the curl URL becomes malformed. The gateway returns HTTP 400 or the URL itself is broken.

**Impact:** Caught by Copilot R1 (r2996351235) and Copilot R2 (r2996525276). Required a fix commit.

**Fix applied in commit 3:** `sed 's/[^0-9.+-]//g'` sanitization added for each metric variable before curl.

**Prevention:** All shell metric values passed to curl MUST be sanitized. The prompt should include sanitization as a standard pattern in the bash exporter template. This is analogous to the `escHtml()` lesson for JavaScript — sanitize at injection point.

---

#### A6 — Bash log line says "Pushed" when curl failures are silently ignored (Severity: LOW — caused 1 review comment)

**Line 142 of the prompt-provided bash script:** `echo "Pushed metrics for $DEVICE_ID"`. The curl calls use `|| true`, so failures are silently ignored. The "Pushed" message is misleading — it logs success even if all four curls failed.

**Impact:** Caught by Copilot R2 (r2996525328). Required a fix commit.

**Fix applied in commit 3:** Changed to `echo "Attempted push for $DEVICE_ID"`.

**Prevention:** Log messages must reflect actual outcome. When a script uses `|| true` error suppression, the log message should say "attempted" or "triggered" rather than implying success.

---

#### A7 — `urlopen()` response not closed in Python exporter (Severity: LOW — caused 1 review comment)

**Line 223 of the prompt-provided Python code:** The `urllib.request.urlopen()` call does not use a `with` context manager. In `--interval` continuous mode, each push call opens an HTTP response object that is never explicitly closed. Over hours of continuous operation (cron is one-shot, but `--interval` mode is long-running), this leaks file descriptors.

**Impact:** Caught by Copilot R2 (r2996525354). Required a fix commit.

**Fix applied in commit 3:** Wrapped in `with urllib.request.urlopen(req) as resp:` context manager.

**Prevention:** Any prompt-provided Python code that opens network connections MUST use `with` context managers. This is the network equivalent of the `isFinite()` guard lesson from v7.5.6.2 — provide defensive resource cleanup in the template.

#### A8 — §3 regeneration sequence in documentation omits `grep -q` verification step (Severity: LOW — caused 1 review comment)

**§5c item referencing §3 ("Then regenerate and flash"):** The regeneration sequence described in the documentation section of the prompt omits the `grep -q "free_heap" tests/fixtures/api-status.json` step that §7 (Critical Rule 28 pipeline) lists. The inconsistency between the abbreviated §3 sequence and the full §7 pipeline creates confusion.

**Impact:** Caught by Copilot R1 (r2996351278). Required a fix commit.

**Fix applied in commit 3:** `grep -q` step added to the documentation's regeneration reference.

**Prevention:** When a prompt references a multi-step pipeline in multiple places, all references must be complete and consistent. The §7 pipeline is the canonical reference — any abbreviated version in documentation sections must include all steps.

## Part III — Lessons

### New Lessons for `bugs-and-lessons-learned.md`

#### LESSON-OPS-081 — Prompt-provided code must be reviewed as production code

**Source:** v7.5.6.3 PR #84 — 8 of 9 PR defects were verbatim prompt bugs.

All code blocks provided in coding agent prompts must pass the same review standard as production code before the prompt is committed. Minimum checks:
- PEP 8 import order (`pylint --disable=all --enable=C0411`)
- Resource cleanup (`with` for network calls, file handles, subprocess)
- Locale independence (`LC_ALL=C` on all locale-dependent shell commands)
- Input sanitization (strip non-numeric characters before URL interpolation)
- Accurate docstrings (docstring must match what the function actually does)
- Correct defaults (stub/unsupported-platform functions must return the documented safe value, not a non-zero placeholder)

**Pattern:** This is the same lesson as v7.5.6.2 (prompt code A1–A4). Adding it as a named lesson establishes it as a standing rule.

---

#### LESSON-OPS-082 — Shell scripts must include `LC_ALL=C` for locale-dependent commands

**Source:** v7.5.6.3 PR #84 defect A4 (Gemini comment r2996339852, Copilot R1 comment r2996351235).

Any prompt-provided shell script that parses output from locale-dependent commands (`top`, `df`, `free`, `date`, `ps`) MUST prefix those commands with `LC_ALL=C`. Non-English locales produce decimal separators (`,` instead of `.`), translated column headers, and unit labels (e.g., `Go` for GB in French) that break `awk` field extraction. `LC_ALL=C` forces POSIX output and prevents this entire class of failure.

**Standard pattern:**
```bash
CPU_IDLE=$(LC_ALL=C top -bn1 | awk '/Cpu/ {print $8}' || echo "0")
```

---

#### LESSON-OPS-083 — Python network calls in loops must use `with` context managers

**Source:** v7.5.6.3 PR #84 defect A7 (Copilot R2 comment r2996525354).

Any prompt-provided Python code that opens network connections (`urllib.request.urlopen()`, `http.client.HTTPConnection`, `socket.socket`) inside a loop or long-running mode MUST use `with` context managers to ensure the connection/response is closed regardless of success or exception. Without this, continuous-mode scripts (`--interval N`) leak file descriptors over time.

**Standard pattern:**
```python
with urllib.request.urlopen(req, timeout=5) as resp:
    body = resp.read()
```

This is the Python network equivalent of the `isFinite()` guard lesson (LESSON-OPS-075) — provide defensive resource cleanup in the template, not as an afterthought.
