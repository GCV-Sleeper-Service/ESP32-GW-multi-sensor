## 3. Review Findings & Fixes

### Finding 1 — Empty path segment validation (Copilot PR Reviewer)
- **File:** `dashboard/sensor_history_multi.h` (line 2151)
- **Issue:** `handle_api_ingest_()` treats some malformed paths (e.g., `/api/ingest//<metric>` or `/api/ingest/<device>/`) as 404 instead of returning a clear 400. Specifically, `id_len==0` falls through to 404, and empty `metric_key` returns 404 "Unknown metric".
- **Suggestion:** Add explicit validation for `id_len == 0` and `metric_key[0] == '\0'` returning 400 with clear messages ("Missing device id" / "Missing metric key").
- **Resolution:** Fixed in PR #79 (`fix(ingest): std::string type error and empty path segment validation`), which was squash-merged into PR #78 before merge to main. The fix also replaced Arduino `String` with `std::string` to fix a type error.

### Finding 2 — Ambiguous error message (Gemini Code Assist)
- **File:** `dashboard/sensor_history_multi.h` (line 2147)
- **Issue:** The error message "Missing metric key" when `slash` is null is ambiguous — the actual problem is a malformed URL path (e.g., `/api/ingest/device_id` without trailing `/metric_key`).
- **Suggestion:** Change to "Invalid path format" or "Malformed URL" for clarity.
- **Resolution:** Addressed in PR #79 fix commit alongside Finding 1.
