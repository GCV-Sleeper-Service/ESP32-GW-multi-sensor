### Critical prompt defects

#### A1 — `last_seen` truthy check in provided code (Severity: High — caused a real bug)

**§5d line 191:** The prompt provides this exact code:
```js
if (seenEl && devData.last_seen) {
```

This is a truthy check. `devData.last_seen === 0` (epoch 0, valid timestamp) evaluates to `false`, silently skipping the update. The `uptime_hrs` guard two lines above correctly uses `!== undefined && !== null`. The inconsistency within the prompt's own code block is the defect.

**Impact:** The agent faithfully reproduced this truthy check in both satellite (`updateSystemCards`) and aggregator (`_populateGatewayDeviceLive`) paths. Both Copilot PR review rounds flagged it. The fix commit corrected it to `devData.last_seen !== undefined && devData.last_seen !== null`.

**Root cause:** Prompt author copied the pattern from the `updateNetworkCards()` reference code in `dashboard.js`, which has the same truthy check for `last_seen`. The bug exists in the reference code and propagated into the prompt.

**Gap category:** Gap 2 (Helper Function Has Hidden Assumptions) — the reference function's guard pattern was assumed correct but wasn't.

**Prevention:** When providing code blocks, apply the same guard style consistently. If `uptime_hrs` uses explicit null/undefined checks, `last_seen` must too. Add a standing rule: "All value-presence guards in system card code use `!== undefined && !== null`, never truthy checks."

#### A2 — Missing `escHtml()` on description in `buildSystemCard()` (Severity: High — XSS)

**§5b line 109:** The prompt provides:
```js
(description ? '...' + description + '...' : '')
```

The `description` field comes from `manifest.sensors[].source.description` — arbitrary text from the config file. On an embedded device behind a LAN this is low practical risk, but it's still an XSS vector and inconsistent with the existing `buildNetworkCard()` which also omits `escHtml()` (same latent bug). The prompt should have wrapped description in `escHtml()` since the helper already exists in the codebase.

**Impact:** Caught in PR review round 1. Fixed in the fix commit.

**Root cause:** The prompt copied the card HTML construction pattern from `buildNetworkCard()`, which also doesn't escape the description. Neither the v7.5.4.2 prompt nor this one audited the description insertion path.

**Gap category:** Gap 2 + Gap 12 (copying a pattern that has a latent bug propagates the bug).

**Prevention:** Add to prompt checklist: "Any string from manifest/config inserted via string concatenation into HTML MUST be wrapped in `escHtml()`."

#### A3 — Missing `isFinite()` guard in `updateUsageBar()` (Severity: Medium)

**§5d line 200:** The prompt provides:
```js
if (value === null || value === undefined) return;
```

If `value` is `NaN` (e.g., from a malformed ingest payload), `Math.min(100, Math.max(0, NaN))` produces `NaN`, and the bar width becomes `"NaN%"` — invalid CSS. The formatter's `isNaN()` guard catches it for the text display, but the bar's width and class assignment are not protected.

**Impact:** Caught in PR review round 1. Fixed in the fix commit with `!isFinite(value)`.

**Root cause:** The prompt's `updateUsageBar()` code was written from scratch (no existing reference to copy from). The null/undefined guard was included but the NaN edge case was overlooked.

**Gap category:** New gap — "Edge case in new code not present in any reference pattern."

**Prevention:** For any function that processes numeric input into CSS values, the prompt should include `isFinite()` guards. Add to writing-prompts guide: "Numeric → CSS conversion functions must guard against NaN/Infinity."

#### A4 — No DRY helper for satellite + aggregator system update paths (Severity: Medium — code quality)

**§5d** provides `updateSystemCards()` with inline logic. **§5 preamble** states the aggregator path uses `renderGatewayDevices()` → `CARD_RENDERERS[category]` for card rendering, and describes `_populateGatewayDeviceLive()` for live updates. But the prompt does not provide code for the aggregator live-update system branch — it only says "registering `CARD_RENDERERS.system` makes system cards work in both sections automatically."

The agent correctly added the system branch to `_populateGatewayDeviceLive()` but duplicated all the update logic inline (12 lines copied from `updateSystemCards`). The Copilot reviewer correctly flagged this as a DRY violation and suggested `_updateSystemCardDOM()`.

**Root cause:** The prompt covers card *rendering* in aggregator mode (via CARD_RENDERERS dispatch) but does not cover card *live-update* in aggregator mode. The `_populateGatewayDeviceLive()` function is not named in the prompt.

**Gap category:** Gap 1 (incomplete data path) + Gap 3 (missing identification of all update sites).

**Prevention:** When describing a card renderer that has both satellite and aggregator paths, the prompt must name BOTH the rendering function AND the live-update function for each path, and specify whether they share code.

#### A5 — `_populateGatewayDeviceLive()` not named in prompt (Severity: Low — implicit coverage gap)

The prompt names `pollV2Live()`, `updateNetworkCards()`, `buildNetworkCard()`, `renderGatewayDevices()` — but never mentions `_populateGatewayDeviceLive()`, which is the aggregator-mode live data update handler. The agent found it by reading the codebase, but the prompt did not trace this link in the data path.

**Gap category:** Gap 1 (incomplete data path tracing).

## Part III — Lessons

### New lessons for `bugs-and-lessons-learned.md`

#### LESSON-OPS-080 — Guard style consistency in prompted code blocks

**Date:** 2026-03-26
**Version:** v7.5.6.2

When a prompt provides multiple value-presence guards in the same code block, ALL guards must use the same pattern. If `uptime_hrs` is guarded with `!== undefined && !== null`, then `last_seen` must use the same guard — not a truthy check. Mixing guard styles within a single function creates an inconsistency that reviewers catch but agents reproduce faithfully.

**Rule:** Before finalizing any prompt code block, audit all value-presence checks for consistency. If one uses explicit null/undefined checks, all must.

#### BUG-072 — `last_seen` truthy guard in prompt-provided `updateSystemCards()` code

**Date:** 2026-03-26
**Version observed:** v7.5.6.2 (PR #83 initial commit)
**Severity:** Edge-case functional (epoch 0 timestamp skipped)
**Fixed in:** PR #83 fix commit (`2304fc01`)

**Root cause:** Prompt §5d provided `if (seenEl && devData.last_seen)` — a truthy check copied from the existing `updateNetworkCards()` reference. `devData.last_seen === 0` is a valid epoch (Jan 1, 1970) and evaluates to `false`.

**Fix:** Changed to `devData.last_seen !== undefined && devData.last_seen !== null` in both satellite and aggregator paths via the shared `_updateSystemCardDOM()` helper.

**Prevention:** LESSON-OPS-080.

#### BUG-073 — `description` field in `buildSystemCard()` not escaped with `escHtml()`

**Date:** 2026-03-26
**Version observed:** v7.5.6.2 (PR #83 initial commit)
**Severity:** XSS (low practical risk on LAN-only embedded device)
**Fixed in:** PR #83 fix commit (`2304fc01`)

**Root cause:** Prompt §5b concatenated `description` directly into HTML without escaping. Same latent pattern exists in `buildNetworkCard()`.

**Fix:** Applied `escHtml(description)` in both `dashboard.js` and `dashboard.html`.

**Prevention:** All manifest/config strings inserted via HTML concatenation must use `escHtml()`. Audit `buildNetworkCard()` for the same latent bug.

#### BUG-074 — `updateUsageBar()` missing `isFinite()` guard allows NaN CSS width

**Date:** 2026-03-26
**Version observed:** v7.5.6.2 (PR #83 initial commit)
**Severity:** Cosmetic (corrupted bar rendering with malformed input)
**Fixed in:** PR #83 fix commit (`2304fc01`)

**Root cause:** Prompt §5d guarded against null/undefined but not NaN. `Math.min(100, Math.max(0, NaN))` returns `NaN`, producing `style.width = "NaN%"`.

**Fix:** Added `|| !isFinite(value)` to the early-return guard.

**Prevention:** Any function converting numeric values to CSS must guard against NaN/Infinity.

### Updates needed for `writing-prompts-for-coding-agents-guide.md`

1. **New Gap 14: Inconsistent guard patterns within prompted code blocks.** When a prompt provides a code block with multiple value-presence guards, mixing truthy checks with explicit null/undefined checks creates a trap. The agent will reproduce the inconsistency faithfully. The guide should add: "Audit all guards in a code block for consistency before finalizing."

2. **Extend Gap 2 with "latent bug propagation" variant.** When copying a pattern from an existing function (e.g., `buildNetworkCard()` → `buildSystemCard()`), the prompt author must audit the reference for latent bugs. Bugs in reference code propagate through prompts to agents.

3. **Add to §9 Pre-Flight Checklist (new Check 8):** "For any function that converts numeric input to CSS values, verify the guard includes `isFinite()` or equivalent NaN protection."

4. **Add to §9 Pre-Flight Checklist (new Check 9):** "For any string from manifest/config inserted into HTML via concatenation, verify `escHtml()` wrapping."
