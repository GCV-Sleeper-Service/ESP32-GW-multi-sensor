### 5c. Test Group Implementation Guardrails (MANDATORY — read BEFORE writing ANY test)

**Group number:** Determine the current last group number by reading `dashboard.spec.js` and finding the highest numbered `test.describe()` heading. Your new group is N+1. **Do NOT assume any group number from this prompt.**

**Readiness helper:** All tests in this group that load the dashboard MUST use:
```js
await loadDashboard(page, { expectedSensorCount: 4 })
```
(4 = 2 env + 1 network + 1 system in the `system` fixture)

**DO NOT** use `{ timeout: 30000 }`. That pattern appears in Group 13 for Firefox SSE teardown (BUG-049) and must not be copied. It does not validate that cards have rendered — it only prevents a Playwright timeout. Using it here would allow tests to proceed before cards exist.

**Count assertions:** All count assertions MUST use hardcoded integer literals:
```
await expect(cards).toHaveCount(4)   ✅ (total: 2 env + 1 net + 1 sys)
await expect(envCards).toHaveCount(2)  ✅
await expect(sysCards).toHaveCount(1)  ✅
await expect(cards).toHaveCount(window._manifest.sensors.length)   ❌ PROHIBITED
```

Dynamic reads pass vacuously when the manifest is broken. Hardcoded integers fail loudly.

**Skip guard:** ALL tests in this group must have a `beforeEach` skip:
```js
test.beforeEach(({ }, testInfo) => {
  test.skip(process.env.FIXTURE_SET !== 'system',
    'System-category tests require FIXTURE_SET=system (4 sensors: 2 env + 1 net + 1 sys)');
});
```

### 5d. Playwright tests — Group N: System Devices and Data Ingest

```js
test.describe('N. System Devices and Data Ingest', () => {
  test.beforeEach(({}, testInfo) => {
    test.skip(process.env.FIXTURE_SET !== 'system',
      'System tests require system fixture (2 env + 1 net + 1 sys = 4)');
  });

  test('system fixture renders correct total card count', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 4 });
    await expect(page.locator('.sensor-card')).toHaveCount(4);
  });

  test('system card renders with usage bar elements', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 4 });
    const sysCard = page.locator('.system-card');
    await expect(sysCard).toHaveCount(1);
    await expect(page.locator('[id^="bar-sys-cpu-"]')).toBeVisible();
    await expect(page.locator('[id^="bar-sys-ram-"]')).toBeVisible();
    await expect(page.locator('[id^="bar-sys-disk-"]')).toBeVisible();
  });

  test('environmental cards have full ThermoPro layout', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 4 });
    const envCards = page.locator('.sensor-card:not(.network-card):not(.system-card)');
    await expect(envCards).toHaveCount(2);
  });

  test('network card present alongside system card', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 4 });
    await expect(page.locator('.network-card')).toHaveCount(1);
  });

  test('CARD_RENDERERS.system is registered', async ({ page }) => {
    await loadDashboard(page, { expectedSensorCount: 4 });
    const has = await page.evaluate(() => typeof CARD_RENDERERS.system === 'function');
    expect(has).toBe(true);
  });

  test('/api/v2/live returns system device data', async ({ page, request }) => {
    const resp = await request.get('/api/v2/live');
    expect(resp.ok()).toBeTruthy();
    const data = await resp.json();
    expect(data.devices.nas01).toBeDefined();
    expect(data.devices.nas01.cpu_pct).toBeDefined();
  });

  test('POST /api/ingest returns 200 for valid device/metric', async ({ request }) => {
    const resp = await request.post('/api/ingest/nas01/cpu_pct?val=55.5');
    expect(resp.ok()).toBeTruthy();
    const body = await resp.json();
    expect(body.ok).toBe(true);
  });

  test('POST /api/ingest returns 404 for unknown device', async ({ request }) => {
    const resp = await request.post('/api/ingest/nonexistent/cpu_pct?val=1');
    expect(resp.status()).toBe(404);
  });
});
```

## ADDENDUM: Post-Phase-5 Codebase Context (added 2026-03-22)

**Multi-board infrastructure is now in the codebase.** The generator supports multiple board targets via `config/gateway.json` and `firmware/boards/*.yaml`. Phase 6 features (ingest endpoint, system devices, system card renderer) are satellite-side functionality that compiles on ALL board variants. No board-specific code is needed.

**Aggregator code exists in `sensor_history_multi.h`.** The `#if AGGREGATOR_ENABLED` block contains `SatelliteCache`, polling task, and API endpoint handlers. Phase 6 code must NOT conflict with these. The ingest endpoint (`POST /api/ingest/...`) is a satellite endpoint — it MUST work when `AGGREGATOR_ENABLED` is either 0 or 1.

**`esp_http_client.h` is NOT available.** If any Phase 6 code needs HTTP client functionality (unlikely — Phase 6 adds server endpoints, not client fetches), use `fetch_to_buffer()` from the aggregator code with `lwip_*()` prefixed socket functions (LESSON-OPS-068).

**Zero-sensor aggregator support exists.** The generator can produce YAML with zero local sensors. Phase 6 features that add new device types to the manifest must handle the case where the new device is the ONLY device (NUM_DEVICES = 1, NUM_ENV_SENSORS = 0). Verify that endpoints work correctly in this scenario.
