## 4) Exact Scope (§3.5)
### 4.1 Add settings controls
In `renderSettingsPanel()`:
1. Add form: URL(required), name(optional), `Test`, `Add`.
2. Remove button per satellite card.
3. Status fields: NVS-vs-compile-time, last-seen, consecutive failures.

### 4.2 API wiring
- Test: `POST /api/aggregator/test-satellite?url=...`
- Add: `POST /api/aggregator/add-satellite?url=...&name=...`
- Remove: `DELETE /api/aggregator/satellite/{id}` + confirmation
- Add/remove success → re-fetch gateways + rerender.

### 4.3 UX behavior
- Inline result/errors (no alerts).
- Disable controls during in-flight requests.
- Keep UI resilient on failure.

### 4.4 Hybrid hardening imports
- Programmatic event binding only (no inline onclick/onchange/oninput).
- Explicit anti-pattern prohibition examples in prompt snippets.
- Use satellite IDs as keys (never cached indices).

### 4.5 Data flow trace
```text
User action (test/add/remove)
  → build endpoint URL (query/path)
  → fetch API
  → map response/error into inline panel state
  → on add/remove success: refresh gateways model
  → rerender settings with ID-based mapping
```

## 7) Runtime Mutation Safety Checklist
### Runtime Mutation Safety Checklist
- [ ] All satellite iteration loops use `runtime_satellite_count`, not `MAX_SATELLITES`
- [ ] All cache mutations (add/remove/clear) happen under `s_cache_mutex` (AGG_LOCK/AGG_UNLOCK)
- [ ] No code caches a satellite array index across function calls or requests
- [ ] Boot path remains unified: satellite boot + aggregator overlay, not a fork (LESSON-OPS-074)
- [ ] NVS empty/fallback path verified (first boot or corrupted namespace → compile-time defaults)
- [ ] NVS write errors logged but do not crash or corrupt runtime state
- [ ] Array compaction after delete tested (v7.6.0.2+)
- [ ] Poll task behavior verified during/after add/remove operations
