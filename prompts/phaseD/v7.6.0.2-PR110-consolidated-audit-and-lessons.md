## Implementation Summary

### handle_delete_satellite_()
- Parses satellite ID from URL path
- Authenticates via `authenticate_management_()`
- Validates ID is non-empty (400 if empty)
- `AGG_LOCK()` → scan for matching `.id` → compact array → `runtime_satellite_count--` → `AGG_UNLOCK()`
- Deferred NVS save via `schedule_save_satellites_nvs_()`
- Returns 200 `{"ok":true}`

### Key patterns introduced
- **SatelliteNVSSnapshot**: Mutex-protected snapshot taken before NVS save task runs, preventing torn reads if another delete arrives between task scheduling and execution
- **Generation counter** (`s_satellite_config_gen`): Incremented on every config mutation. Poll task captures gen before fetch, re-validates after fetch, discards stale data if gen changed
- **`s_nvs_save_in_progress` flag**: Prevents concurrent deferred NVS save tasks from rapid successive deletes
- **`AGGREGATOR_SATELLITE_ROUTE_PREFIX_LEN`**: Replaces magic number 26 for strncmp length

## BUG-079: HTTP DELETE Handler Registration

**Bug:** Plain-text 405 from ESP-IDF httpd for all DELETE requests.

**Root cause:** `AsyncWebServer::begin()` in `firmware/local_components/web_server_idf/web_server_idf.cpp` only registered HTTP_GET, HTTP_POST, HTTP_OPTIONS URI handlers. No HTTP_DELETE. The local component (PR #105) copied stock ESPHome which doesn't support DELETE.

**Fix:** Added HTTP_DELETE URI handler registration. DELETE uses the same `request_handler` path as GET (no body). Updated `scripts/patch-esphome-httpd-stack.sh` with PATCH2 block.

**Lesson:** When adding a new HTTP method to the application layer, verify the transport layer (ESPHome/ESP-IDF httpd) actually registers a handler for that method. A plain-text 405 (not JSON) is the diagnostic signature that the request never reached application code.

## New Lessons

- **LESSON-OPS-105**: NVS save tasks run outside the mutex — data can change between task scheduling and execution. Use a snapshot pattern.
- **LESSON-OPS-106**: Concurrent deferred tasks from rapid mutations can corrupt NVS. Serialize with a flag.
- **LESSON-OPS-107**: Poll task must detect config changes during multi-step fetch sequences. Generation counters prevent stale data writes.
- **LESSON-OPS-108**: The GET fallthrough in `handleRequest()` has no method guard. New routes added there intercept ALL methods. Non-GET/POST dispatch must use explicit `request->method()` checks placed BEFORE the GET fallthrough.
- **LESSON-OPS-109**: When `canHandle()` returns false, ESP-IDF httpd returns its own generic 405 `"Specified method is invalid for this resource"`. A plain-text 405 means the request never reached `handleRequest()`.
