## 4) Exact Scope (§3.5)
Implement **only** v7.6.0.0:

### 4.1 New runtime state + NVS helpers
In `dashboard/sensor_history_multi.h`, add:
- `static int runtime_satellite_count` (authoritative runtime loop bound).
- `load_satellites_from_nvs_()`
- `save_satellites_to_nvs_()`
- `save_single_satellite_to_nvs_()`

### 4.2 NVS schema (fixed)
Namespace: `agg_sats`.
Keys:
- `count` (u8)
- Per index `i`: `s{i}_id`, `s{i}_name`, `s{i}_url`, `s{i}_poll`

### 4.3 Boot path migration
Update `init_aggregator_satellites()`:
1. Attempt NVS load first.
2. If NVS empty/missing/corrupt: fall back to compile-time arrays from `aggregator_config.h`.
3. Set `runtime_satellite_count` accordingly.
4. Keep unified boot path (no aggregator-specific fork).

### 4.4 Loop-bound migration
Replace every `MAX_SATELLITES` loop bound in runtime iteration paths with `runtime_satellite_count`:
- Polling loop(s)
- Gateway/live handlers
- Any helper scans over active satellites

Keep `MAX_SATELLITES` as capacity guard only.

### 4.5 Reset endpoint
Add firmware endpoint:
- `POST /api/system/reset-satellites`
- Clears `agg_sats` NVS namespace
- Reloads compile-time defaults into runtime cache
- Leaves `agg_sats` NVS empty after clear (do **not** repopulate NVS in reset handler); runtime cache is reloaded from compile-time defaults for current boot, and subsequent boots use compile-time fallback when NVS is empty

### 4.6 Data lifecycle trace (MANDATORY)
```text
Boot → load_satellites_from_nvs_() → populate satellite_caches[] → set runtime_satellite_count
  ↓ (if NVS empty)
Boot → copy compile-time arrays → populate satellite_caches[] → set runtime_satellite_count = MAX_SATELLITES
  ↓
Poll task iterates 0..runtime_satellite_count-1
  ↓
All API handlers iterate 0..runtime_satellite_count-1
```

- [ ] All satellite iteration loops use `runtime_satellite_count`, not `MAX_SATELLITES`
- [ ] All cache mutations (add/remove/clear) happen under `s_cache_mutex` (AGG_LOCK/AGG_UNLOCK)
