## 7. Root Cause Analysis

### Defect 1: `escHtml()` + `textContent` double-encoding (fixed in `edc7844`)

**Root cause: Prompt ambiguity — missing DOM pairing rule**

The prompt (§5e) stated:
> Use `escHtml()` on **all** dynamic text inserted into HTML

It did not state:
> When using `escHtml()`, the DOM assignment **must** use `innerHTML`, not `textContent`.

The agent correctly applied `escHtml()` to dynamic strings as instructed. However, it assigned
the escaped results via `textContent`, which does not interpret HTML entities — causing visible
double-encoded entities (e.g., a satellite named `O'Brien's Node` would render as
`O&#39;Brien&#39;s Node` in the UI).

Perplexity's root cause classification is correct: this was **prompt ambiguity**. The prompt
provided the `escHtml()` usage requirement but omitted the mandatory pairing rule (`innerHTML`
must be used with `escHtml()`). The agent had no basis to infer the correct pairing from the
instruction as written.

**Specific prompt section that was unclear:** §5e (Dynamic-text safety) — it stated what
function to call but not what DOM property to pair with it.

---

### Defect 2: `_refreshSettingsPanel()` uses `r.json()` instead of `safeJsonResponse()` (fixed in `edc7844`)

**Root cause: Agent followed §6 skeleton code over the compliance checklist**

The prompt §2 reading list explicitly called out `safeJsonResponse()` as an existing helper
to reuse for all fetch parsing. The prompt compliance checklist in §5e stated:
> `safeJsonResponse()` reused for all fetch parsing

However, the §6 recommended implementation skeleton for `_refreshSettingsPanel()` showed
`.then(function(r) { return r.json(); })` directly. The agent used the skeleton verbatim
rather than substituting `safeJsonResponse` as the compliance checklist required.

Perplexity's root cause classification is correct: **agent followed §6 skeleton code rather
than cross-checking against the existing fetch pattern**. The prompt preamble added in
commit `4530d909` warned to cross-check skeleton code against the live codebase, but the
skeleton itself was not updated to use `safeJsonResponse()`, creating a conflict between
the skeleton (concrete code) and the compliance checklist (prose requirement).

**Specific prompt section that was incomplete:** §6 skeleton for `_refreshSettingsPanel()` —
showed `r.json()` directly, contradicting the §5e compliance checklist.

---

### Defect 3: `sensor_count` only in test success message, ignoring `device_count` (fixed in `f28ef4d`)

**Root cause: Prompt data flow trace omitted `device_count → sensor_count` precedence rule**

The prompt §5c data flow trace specified:
> Success: "✓ Found: {name} ({hardware}, {sensor_count} devices)"

This trace used `sensor_count` only. The existing satellite card rendering in the codebase
used a `device_count → sensor_count` fallback. The agent faithfully reproduced the prompt's
data flow trace rather than inferring the fallback from the existing code.

Root cause: **prompt omission** — the data flow trace should have specified the same
precedence logic as the card renderer, or §5e should have included a `device_count`/`sensor_count`
precedence rule for all display paths.

## 10. New Lessons Learned

### LESSON-OPS-111: `escHtml()` must be paired with `innerHTML`, never `textContent`

**Source:** PR #126 defect in `289faa4`; fixed in `edc7844`.

When `escHtml()` is used on a string that is inserted into the DOM, the DOM assignment
**must** use `innerHTML`, never `textContent`. `textContent` does not interpret HTML — it
sets the node's character data literally, causing escaped entities (e.g., `&amp;`, `&lt;`,
`&quot;`) to be shown verbatim to the user.

Conversely, when `textContent` is used, the string **must not** be passed through `escHtml()`
— `textContent` already prevents XSS by treating the value as plain text.

**Prompt quality gate rule to add:**
> "Use either `textContent` with raw (unescaped) strings, or `innerHTML` with `escHtml()`;
> never mix `escHtml()` with `textContent`. Audit every status element assignment before
> submitting."

**Grep gate:**
```bash
rg "textContent\s*=.*escHtml\(" dashboard/dashboard.js dashboard/dashboard.html
# Must return no matches
```

---

### LESSON-OPS-112: All new fetch helpers must use `safeJsonResponse()`, including refresh/reload helpers

**Source:** PR #126 defect in `289faa4`; fixed in `edc7844`.

All new `fetch()` calls introduced in an implementation step must use `safeJsonResponse()`
for JSON parsing. This applies to every new fetch helper — not only the primary action
handlers (`_handleTestSatellite`, `_handleAddSatellite`, `_handleRemoveSatellite`) but
also any new refresh/reload/re-fetch helpers (`_refreshSettingsPanel()`).

Using `.then(r => r.json())` directly bypasses HTTP status validation, causing a `SyntaxError`
if the server returns a non-JSON error body (e.g., a plain-text 502 from a proxy).

If a §6 skeleton code block in a prompt shows `.then(r => r.json())`, treat this as a
placeholder that must be replaced with `.then(safeJsonResponse)` — the compliance checklist
takes precedence over skeleton code.

**Prompt quality gate rule to add:**
> "Every `fetch()` call introduced in this step, including `_refreshSettingsPanel()` and
> any other refresh helpers, must use `.then(safeJsonResponse)`. Do not use
> `.then(r => r.json())` directly. The §6 skeleton may show `r.json()` as a placeholder
> — replace it."

**Grep gate:**
```bash
rg "_refreshSettingsPanel|\.json\(|safeJsonResponse" dashboard/dashboard.js dashboard/dashboard.html
# All .then(... .json() patterns in new code must be .then(safeJsonResponse)
```

> **MANDATORY — `device_count` / `sensor_count` precedence:**
> When displaying device or sensor counts from gateway or manifest data, always apply the
> same fallback logic used in the satellite card renderer:
> ```js
> var deviceCount = (gw.device_count !== undefined && gw.device_count !== null)
>   ? String(gw.device_count)
>   : ((gw.sensor_count !== undefined && gw.sensor_count !== null)
>       ? String(gw.sensor_count) : '\u2014');
> ```
> Apply this to all status message paths, not only the card renderer.

> **MANDATORY — catch blocks must call `logNonFatal()`:**
> The `_refreshSettingsPanel()` catch block must call `logNonFatal('_refreshSettingsPanel', err)`
> before returning. Silent `.catch(function() {})` blocks are not acceptable.
