## 4) Exact Scope (§3.5)
Modify settings UI in `dashboard/dashboard.js` + mirrored `dashboard/dashboard.html`:

### 4.1 New settings controls
In `renderSettingsPanel()`:
1. Add Satellite form:
   - URL input (required)
   - Name input (optional)
   - `Test` button
   - `Add` button
2. Add remove button per satellite card entry.
3. Add status indicators per satellite:
   - NVS-persisted vs compile-time
   - last-seen
   - consecutive failure count

### 4.2 API actions
- Test button: `POST /api/aggregator/test-satellite?url=...`
- Add button: `POST /api/aggregator/add-satellite?url=...&name=...`
- Remove button: `DELETE /api/aggregator/satellite/{id}` with confirmation
- On add/remove success: re-fetch gateways/settings data and rerender.

### 4.3 UX requirements
- Inline status/error display only (no `alert()`).
- Disable/re-enable buttons during in-flight request.
- Keep dashboard responsive under request failures.

### 4.4 Data flow trace
```text
User action (test/add/remove)
  → build endpoint URL with query/path params
  → fetch API
  → parse result and map to inline status state
  → on success (add/remove): refresh gateways/settings model
  → rerender settings panel using satellite IDs (not indices)
```

## 7) Runtime Mutation Safety Checklist
### Runtime Mutation Safety Checklist
- [ ] All satellite iteration loops use `runtime_satellite_count`, not `MAX_SATELLITES`
- [ ] All cache mutations (add/remove/clear) happen under `s_cache_mutex` (AGG_LOCK/AGG_UNLOCK)
- [ ] No code caches a satellite array index across function calls or requests
- [ ] Boot path remains unified: satellite boot + aggregator overlay, not a fork (LESSON-OPS-074)
- [ ] NVS empty/fallback path verified (first boot or corrupted namespace → compile-time defaults)
- [ ] NVS write errors logged but do not crash or corrupt runtime state
- [ ] Array compaction after delete tested (v7.6.0.2+)
- [ ] Poll task behavior verified during/after add/remove operations
