**Assessment:** 5 genuine fixes, 2 documentation updates. This should be added to v7.6.0.1+ prompts as a known invariant.

## 5. Prompt Quality Assessment

### What worked well
- The extensive `Required Reading` section prevented the agent from misunderstanding the architecture
- The `SatelliteCache` struct extension design in §5b was precise enough that the agent implemented it correctly
- The `runtime_satellite_count` migration was exhaustive — listing all loop locations worked
- The `Do-NOT` list prevented scope creep (no dashboard changes, no mock changes)
- The `Snippet Quality Gates` caught potential issues (strncpy null terminator, NVS handle closure)

### What failed
- **Section 11 (Device Testing):** Wrong YAML path. This is a Claude prompt-authoring defect, not a coding agent defect. The prompt author (Claude) copied the C3 compile command without accounting for the generated YAML path for non-C3 boards. **Root cause:** The prompt was written from the perspective of the repo file listing, where only `esp32-c3-multi-sensor.yaml` is visible. The generated S3 YAML is gitignored and invisible unless you understand the generation pipeline.
- **Regeneration pipeline:** Missing `minify-dashboard.sh` step. This was also a prompt authoring defect present since the first Phase D prompt was written.
- **NVS seeding invariant:** The prompt described "compile-time fallback" but didn't explicitly require "save to NVS after fallback load" — this led to the fixup. Future prompts should state this invariant.

- **LESSON-OPS-086 (Do-NOT regeneration exclusion):** ✅ Applied and effective — no false positives from version churn
- **LESSON-OPS-087 (cross-language constant policy):** ✅ No bare literals in the implementation

## 8. New Lessons

### LESSON-OPS-090 — Device testing YAML must reference generated YAML for target board
Prompt device testing sections referenced the committed C3 template for S3 aggregator builds. The operator compiled satellite firmware for the wrong chip. All six Phase D prompts affected.

**Critical Rule 36 added.**

### LESSON-OPS-091 — Regeneration pipeline must include dashboard minification
`minify-dashboard.sh` missing from all pipeline references. Stale `.min.html` can silently embed outdated dashboard content.

**Critical Rule 37 added.**
