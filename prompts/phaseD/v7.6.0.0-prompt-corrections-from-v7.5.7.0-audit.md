## Correction 1 — Do-NOT list conflicts with version bump pipeline (LESSON-OPS-086)

**Finding (from A1 in v7.5.7.0 audit):** The v7.5.7.0 prompt's Do-NOT list said "Do NOT change any dashboard JavaScript or HTML" but its version bump step (`bump-version.sh`) necessarily updates `App.version` in `dashboard.js` and `dashboard.html`. The agent violated the Do-NOT list by performing the correct action.

**Status in v7.6.0.0 prompt:** The same contradiction exists.

- **§6 (Do NOT)** states: "Modify `dashboard/dashboard.js` or `dashboard/dashboard.html` — NO dashboard changes in this step"
- **§7 Critical Rules, Rule 2** states: `bash scripts/bump-version.sh 7.6.0.0` — Version bump

Running `bump-version.sh` updates `App.version` in both `dashboard.js` and `dashboard.html`. This is expected regeneration churn, not a functional change, but the Do-NOT list as written prohibits it.

**Corrected wording for §6:**

Replace:
```
- Modify `dashboard/dashboard.js` or `dashboard/dashboard.html` — NO dashboard changes in this step
```

With:
```
- Make any *functional* changes to `dashboard/dashboard.js` or `dashboard/dashboard.html` — no new logic, UI, or feature changes in this step. Version bump regeneration churn (App.version update via bump-version.sh) is expected and does not violate this rule.
```

## Correction 2 — Python code blocks with bare numeric literals (LESSON-OPS-087)

**Finding (from A2 in v7.5.7.0 audit):** The v7.5.7.0 prompt provided Python code with `board_cap = 8` and `f"#define AGG_MANIFEST_BUF_SIZE 8192\n"` as bare literals, inconsistent with the C++ named constant `AGG_MANIFEST_BUF_SIZE`. After the fixup commit, `render_sensor_config.py` now uses `SATELLITE_CAP_PSRAM = 8` and `AGG_MANIFEST_BUF_SIZE_BYTES = 8192` as module-level constants.

**Status in v7.6.0.0 prompt:** No Python code blocks with bare numeric literals were found in this prompt. The prompt correctly instructs the agent NOT to change `generate_aggregator_config_h()` in §6 (Do NOT list), so the agent will not regress the named constants introduced in v7.5.7.0.

**Action required:** None. This correction is N/A for v7.6.0.0. However, any future prompt that does provide Python code blocks must apply named constants consistently (not bare literals) for values that have named constants in the C++ layer.

## Correction 4 — `board_cap = 8` and `generate_aggregator_config_h()` references now outdated (LESSON-OPS-087)

**Finding:** The v7.6.0.0 prompt §2 item 9 describes `generate_aggregator_config_h()` as: "Currently sets `MAX_SATELLITES` equal to the satellite count in `aggregator.json`."

This description was accurate before v7.5.7.0. After the v7.5.7.0 merge (commit `93242a0`), the function now:
- Accepts a `board_profile` parameter
- Applies PSRAM check: if no PSRAM, forces `AGGREGATOR_ENABLED 0` and skips satellite cap
- For PSRAM boards, caps satellites at `SATELLITE_CAP_PSRAM = 8` (not the raw `aggregator.json` count)
- Emits `#define AGG_MANIFEST_BUF_SIZE {AGG_MANIFEST_BUF_SIZE_BYTES}` (using the named constant, value 8192)

The prompt description in §2 item 9 is now partially inaccurate — it omits the PSRAM cap and `AGG_MANIFEST_BUF_SIZE` emission.

**Corrected wording for §2 item 9:**

Replace:
```
9. `scripts/render_sensor_config.py` — `generate_aggregator_config_h()` function (line ~572). Currently sets `MAX_SATELLITES` equal to the satellite count in `aggregator.json`. You need to understand this to ensure the compile-time arrays still work as fallback.
```

With:
```
9. `scripts/render_sensor_config.py` — `generate_aggregator_config_h()` function (line ~576). As of v7.5.7.0: accepts a `board_profile` parameter; for PSRAM boards caps `MAX_SATELLITES` at `SATELLITE_CAP_PSRAM = 8` (not the raw aggregator.json count); emits `#define AGG_MANIFEST_BUF_SIZE 8192` using the module-level constant `AGG_MANIFEST_BUF_SIZE_BYTES`. The compile-time arrays remain the fallback source. **Do NOT change this function** (§6 Do-NOT list).
```

Also update the §6 Do-NOT entry to match:

Replace:
```
- Change the `generate_aggregator_config_h()` function in `render_sensor_config.py` — the compile-time arrays remain the fallback source
```

With:
```
- Change the `generate_aggregator_config_h()` function in `render_sensor_config.py` — the compile-time arrays remain the fallback source. The v7.5.7.0 PSRAM cap (`SATELLITE_CAP_PSRAM = 8`) and buffer constant (`AGG_MANIFEST_BUF_SIZE_BYTES = 8192`) are already in place.
```
