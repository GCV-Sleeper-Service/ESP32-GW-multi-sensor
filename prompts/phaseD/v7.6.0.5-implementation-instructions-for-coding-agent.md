### Runtime Mutation Safety Checklist
- [ ] All satellite iteration loops use `runtime_satellite_count`, not `MAX_SATELLITES`
- [ ] All cache mutations (add/remove/clear) happen under `s_cache_mutex` (AGG_LOCK/AGG_UNLOCK)

- [ ] Boot path remains unified: satellite boot + aggregator overlay, not a fork (LESSON-OPS-074)

- [ ] NVS write errors logged but do not crash or corrupt runtime state

## 11) Contract-Lock (§3.12)
**Enumerate all mock routes and branch contracts (must match firmware handlers):**

### Firmware handlers referenced
- `handle_add_satellite_()`
- `handle_delete_satellite_()`
- `handle_test_satellite_()`

### Route 1: `POST /api/aggregator/add-satellite`
- Branches:
  - 200 success
  - 400 missing `url`
  - 400 invalid `url` format (not `http://`)
  - 409 full list
  - 409 duplicate URL
  - 400 probe failed
- Response shape requirements:
  - success includes added satellite identity fields (id/name/url/poll or project-equivalent)
  - failures include deterministic `error` field/message
- Test requirement: one explicit test per branch.

### Route 2: `DELETE /api/aggregator/satellite/:id`
- Branches:
  - 200 success
  - 404 unknown ID
- Response shape requirements:
  - success includes deleted ID or confirmation field
  - 404 includes deterministic error payload
- Test requirement: both branches covered and state verified after success.

### Route 3: `POST /api/aggregator/test-satellite`
- Branches:
  - 200 success with gateway summary (`id`, `name`, `hardware`, `sensor_count`)
  - 400 missing URL
  - 400 unreachable/probe failure
- Side-effect requirement:
  - must not mutate mock satellite list
- Test requirement: assert list unchanged before/after.
