### 5a. Extend mock server with STATEFUL satellite management routes

**⚠️ This is harder than previous mock extensions.** The mock server must maintain satellite state across requests within a test. When a test adds a satellite, subsequent requests must see it. When a test deletes one, it must be gone.

Add state tracking at the top of the mock server request handler:

```javascript
// Stateful satellite management (Phase D mock)
// Initialized from the aggregator fixture on server start.
let managedSatellites = [];
const MOCK_MAX_SATELLITES = 8;

function initManagedSatellites() {
  const gateways = loadFixtureJson('aggregator-gateways.json', { gateways: [] });
  managedSatellites = (gateways.gateways || []).map(function(gw) {
    return {
      id: gw.id,
      name: gw.name,
      base_url: gw.base_url || 'http://mock-satellite',
      poll: 30,
      reachable: gw.reachable !== undefined ? gw.reachable : true,
      last_seen: gw.last_seen || Math.floor(Date.now() / 1000),
      consecutive_failures: gw.consecutive_failures || 0,
      firmware_version: gw.firmware_version || '7.6.0.5',
      sensor_count: gw.sensor_count || 0,
      manifest: gw.manifest || null
    };
  });
}

// Initialize on server load
initManagedSatellites();
```

### 5b. Contract-Lock: Mock `POST /api/aggregator/add-satellite`

**Read `handle_add_satellite_()` in `dashboard/sensor_history_multi.h` first.** Mirror all validation branches:

| Condition | HTTP Status | Response |
|-----------|-------------|----------|
| Valid URL, probe succeeds | 200 | `{"ok":true,"satellite":{"id":"mock-sat-N","name":"...","url":"...","poll":30}}` |
| Missing `url` parameter | 400 | `{"ok":false,"message":"Missing url parameter","status":400}` |
| URL doesn't start with `http://` | 400 | `{"ok":false,"message":"URL must start with http://","status":400}` |
| Satellite list full (count >= MOCK_MAX_SATELLITES) | 409 | `{"ok":false,"message":"Satellite list full","status":409}` |
| Duplicate URL | 409 | `{"ok":false,"message":"URL already configured","status":409}` |
| Probe failed (URL contains "unreachable") | 400 | `{"ok":false,"message":"Satellite unreachable or invalid manifest","status":400}` |
| Wrong HTTP method (GET) | — | Fall through to normal routing (404) |

**Mock probe logic:** Since the mock can't actually probe satellites, simulate it:
- If URL contains "unreachable" → probe fails
- Otherwise → probe succeeds, generate a mock satellite ID and use the provided name

```javascript
// Route: POST /api/aggregator/add-satellite
if (pathname === '/api/aggregator/add-satellite' && req.method === 'POST') {
  const params = new URL(req.url, `http://${req.headers.host || 'localhost'}`).searchParams;
  const satUrl = params.get('url');
  const satName = params.get('name');
  const satPoll = parseInt(params.get('poll') || '30', 10);

  if (!satUrl) return json(res, { ok: false, message: 'Missing url parameter', status: 400 }, 400);
  if (!satUrl.startsWith('http://')) return json(res, { ok: false, message: 'URL must start with http://', status: 400 }, 400);
  if (managedSatellites.length >= MOCK_MAX_SATELLITES) return json(res, { ok: false, message: 'Satellite list full', status: 409 }, 409);
  if (managedSatellites.some(s => s.base_url === satUrl)) return json(res, { ok: false, message: 'URL already configured', status: 409 }, 409);

  // Simulate probe
  if (satUrl.includes('unreachable')) return json(res, { ok: false, message: 'Satellite unreachable or invalid manifest', status: 400 }, 400);

  const newId = 'mock-sat-' + (managedSatellites.length + 1);
  const newName = satName || 'Mock Satellite ' + (managedSatellites.length + 1);
  const newSat = {
    id: newId, name: newName, base_url: satUrl,
    poll: satPoll, reachable: true,
    last_seen: Math.floor(Date.now() / 1000),
    consecutive_failures: 0, firmware_version: '7.6.0.5', sensor_count: 0
  };
  managedSatellites.push(newSat);

  return json(res, { ok: true, satellite: { id: newId, name: newName, url: satUrl, poll: satPoll } });
}
```

```javascript
// Route: DELETE /api/aggregator/satellite/{id}
const deleteSatMatch = pathname.match(/^\/api\/aggregator\/satellite\/(.+)$/);
if (deleteSatMatch && req.method === 'DELETE') {
  const satId = decodeURIComponent(deleteSatMatch[1]);
  const idx = managedSatellites.findIndex(s => s.id === satId);
  if (idx < 0) return json(res, { ok: false, message: 'Unknown satellite', status: 404 }, 404);
  managedSatellites.splice(idx, 1);
  return json(res, { ok: true });
}
```

```js
    expect(body.ok).toBe(false);

    const resp = await request.post('/api/aggregator/add-satellite');
    expect(resp.status()).toBe(400);
  });

  test('POST add-satellite: full list returns 409', async ({ request }) => {
    // Reset to known state
    await request.post('/api/system/reset-satellites');
    // Fill to capacity
    for (let i = 0; i < 8; i++) {
      await request.post('/api/aggregator/add-satellite?url=http://fill-' + i + '.local');

    const resp = await request.post('/api/aggregator/add-satellite?url=http://overflow.local');
    expect(resp.status()).toBe(409);
    // Reset after test
    await request.post('/api/system/reset-satellites');
```

```markdown
## Runtime Satellite Management (v7.6.0+)

After Phase D, satellite configuration is managed through the dashboard:

### Adding a satellite
1. Open the aggregator dashboard
2. Navigate to the Settings section
3. Enter the satellite's URL (e.g., `http://192.168.120.189`)
4. Optionally enter a friendly name
5. Click "Test" to verify connectivity (optional but recommended)
6. Click "Add" — the satellite appears in the list and begins polling immediately

### Removing a satellite
1. In the Settings section, find the satellite card
2. Click "Remove" and confirm
3. The satellite stops polling and is removed from NVS

### API endpoints
- `POST /api/aggregator/add-satellite?url=...&name=...&poll=30` — add satellite
- `DELETE /api/aggregator/satellite/{id}` — remove satellite
- `POST /api/aggregator/test-satellite?url=...` — probe without adding
- `POST /api/system/reset-satellites` — restore compile-time defaults

### Configuration persists across reboots
Satellites are stored in NVS (namespace `agg_sats`). On first boot, the compile-time
satellite list from `aggregator_config.h` is used as the initial configuration.
```
