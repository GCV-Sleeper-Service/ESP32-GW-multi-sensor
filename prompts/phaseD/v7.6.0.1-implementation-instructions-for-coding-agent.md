## 3a. v7.6.0.0 Findings Back-Ported to This Step

The v7.6.0.0 PR review (PR #98 + fixes in PR #99) identified patterns that affect this step:

1. **`init_satellite_caches_()` runs without mutex.** The ESPHome startup sequence guarantees `aggregator_poll_task()` init completes before the web server accepts connections, so the current implementation is safe. However, the absence of a mutex creates technical debt if startup ordering ever changes. This is acceptable for v7.6.0.1. If you add any init-time code in this step, ensure it runs before web handlers can fire.

2. **NVS is now seeded on first boot.** `init_satellite_caches_()` calls `save_satellites_to_nvs_()` when falling back to compile-time defaults (added in PR #99 Fix 4). This means `save_single_satellite_to_nvs_()` in the add-satellite handler can safely write just the new entry — the compile-time defaults are already in NVS.

3. **NVS key buffers are `[16]`.** All three NVS functions already use `char key_*[16]` (fixed in PR #99). Do not regress to `[8]`.

4. **Reset handler uses `authenticate_management_()`.** The pattern for all destructive endpoints is: auth check → validation → mutation → response. Follow this pattern for `handle_add_satellite_()`. Note: add-satellite is constructive (not destructive), so whether auth is required is a design choice. The v7.6.0.0 handoff does not require auth for add-satellite — follow the prompt's existing contract (no auth on add).

5. **`save_satellites_to_nvs_()` internally calls `nvs_erase_all()`.** Callers that erase first (like reset handler) cause a double erase. For `handle_add_satellite_()`, use `save_single_satellite_to_nvs_()` — it does NOT erase, it writes a single entry + updates count. This is the correct function for the add path.

## 5. Exact Scope — Implement `POST /api/aggregator/add-satellite`

Replace the 501 stub with a working implementation. **No dashboard changes. No test changes.**

### 5a. API contract

```
POST /api/aggregator/add-satellite?url=http://192.168.120.191&name=Kitchen&poll=30
```

Query string parameters:
- `url` (required): base URL of the satellite (must start with `http://`)
- `name` (optional): friendly name. If absent, derived from the satellite's manifest `gateway.name`
- `poll` (optional): poll interval in seconds. Default 30. Minimum 10, maximum 3600.

**⚠️ Query string, NOT JSON body.** `AsyncWebServerRequest` in ESPHome IDF provides `request->getParam("url")` for query string access. Do NOT attempt JSON body parsing — it requires `handleBody()` callbacks which are Arduino-specific and not available in the ESPHome IDF environment.

### 5b. Data flow trace

```
POST request arrives
  → parse query params: url, name, poll
  → validate url format (must start with "http://")
  → check runtime_satellite_count < MAX_SATELLITES (reject 409 if full)
  → check no duplicate URL in satellite_caches[0..runtime_satellite_count-1]
  → probe: fetch_to_buffer(url + "/api/manifest", s_proxy_tmp, ...) [uses s_proxy_tmp, NOT s_fetch_tmp]
  → if probe fails → 400 "Satellite unreachable or invalid manifest"
  → parse gateway.id and gateway.name from manifest JSON (simple strstr-based parsing)
  → if no name provided, use gateway.name from manifest
  → if no name from manifest either, derive from URL
  → AGG_LOCK()
    → satellite_caches[runtime_satellite_count].set_identity(id, name, url, poll)
    → satellite_caches[runtime_satellite_count].clear_cache()
    → runtime_satellite_count++
  → AGG_UNLOCK()
  → save_single_satellite_to_nvs_(runtime_satellite_count - 1)
  → return 200 {"ok":true,"satellite":{"id":"...","name":"...","url":"..."}}
```

### 5c. Factor out `probe_satellite_manifest_()` helper

This function will be reused by v7.6.0.3 (`test-satellite`). Factor it out now:

```cpp
// Probe a satellite URL by fetching /api/manifest.
// On success, extracts gateway.id and gateway.name into provided buffers.
// Returns true on success, false on failure (unreachable, non-200, or unparseable manifest).
//
// MUST be called from web handler context only (uses s_proxy_tmp).
// NOT safe to call from the polling task.
static bool probe_satellite_manifest_(
    const char* base_url,
    char* out_id,   size_t id_size,
    char* out_name, size_t name_size)
{
  char url_buf[256];
  int url_len = snprintf(url_buf, sizeof(url_buf), "%s/api/manifest", base_url);
  if (url_len < 0 || (size_t)url_len >= sizeof(url_buf)) return false;

  uint16_t resp_len = 0;
  // Use s_proxy_tmp (web handler context only — single-threaded ESPHome loop)
  if (!fetch_to_buffer(url_buf, s_proxy_tmp, (uint16_t)(sizeof(s_proxy_tmp) - 1), &resp_len)
      || resp_len == 0) {
    return false;
  }
  s_proxy_tmp[resp_len] = '\0';

  // Extract gateway.id — look for "gateway":{"id":"..." pattern
  // Simple strstr parsing (no JSON library on ESP32)
  out_id[0] = '\0';
  out_name[0] = '\0';

  const char* gw = strstr(s_proxy_tmp, "\"gateway\"");
  if (!gw) return false;

  // Find "id":"<value>" within the gateway object
  const char* id_key = strstr(gw, "\"id\":\"");
  if (id_key) {
    id_key += 6; // skip past "id":"
    const char* id_end = strchr(id_key, '"');
    if (id_end) {
      size_t len = (size_t)(id_end - id_key);
      if (len >= id_size) len = id_size - 1;
      memcpy(out_id, id_key, len);
      out_id[len] = '\0';
    }
  }

  // Find "name":"<value>" within the gateway object
  const char* name_key = strstr(gw, "\"name\":\"");
  if (name_key) {
    name_key += 8; // skip past "name":"
    const char* name_end = strchr(name_key, '"');
    if (name_end) {
      size_t len = (size_t)(name_end - name_key);
      if (len >= name_size) len = name_size - 1;
      memcpy(out_name, name_key, len);
      out_name[len] = '\0';
    }
  }

  // Must have at least an ID to be a valid manifest
  return out_id[0] != '\0';
}
```

**⚠️ Parsing robustness:** The `strstr` approach assumes the manifest JSON has `"gateway":{"id":"...", "name":"..."}` in that structure. This is guaranteed by the project's manifest v2 contract — every gateway serves this format. Edge cases (no gateway object, malformed JSON) return false, which the caller treats as "probe failed." Good enough for LAN discovery.

The handler implementation:

```cpp
void handle_add_satellite_(AsyncWebServerRequest *request) const {
  if (request->method() != HTTP_POST) {
    send_json_error_(request, 405, "Method not allowed");
    return;
  }

  // 1. Parse query params
  if (!request->hasParam("url")) {
    send_json_error_(request, 400, "Missing url parameter");
    return;
  }
  String url_param = request->getParam("url")->value();
  const char* url_str = url_param.c_str();

  // 2. Validate URL format
  if (strncmp(url_str, "http://", 7) != 0) {
    send_json_error_(request, 400, "URL must start with http://");
    return;
  }

  // 3. Check capacity
  if (runtime_satellite_count >= MAX_SATELLITES) {
    send_json_error_(request, 409, "Satellite list full");
    return;
  }

  // 4. Check duplicate URL
  for (int i = 0; i < runtime_satellite_count; i++) {
    if (strcmp(satellite_caches[i].base_url, url_str) == 0) {
      send_json_error_(request, 409, "URL already configured");
      return;
    }
  }

  // 5. Probe the candidate
  char probe_id[32] = {0};
  char probe_name[64] = {0};
  if (!probe_satellite_manifest_(url_str, probe_id, sizeof(probe_id),
                                  probe_name, sizeof(probe_name))) {
    send_json_error_(request, 400, "Satellite unreachable or invalid manifest");
    return;
  }

  // 6. Determine name: request param > manifest > derived from URL
  char final_name[64];
  if (request->hasParam("name") && request->getParam("name")->value().length() > 0) {
    strncpy(final_name, request->getParam("name")->value().c_str(), sizeof(final_name) - 1);
    final_name[sizeof(final_name) - 1] = '\0';
  } else if (probe_name[0] != '\0') {
    strncpy(final_name, probe_name, sizeof(final_name) - 1);
    final_name[sizeof(final_name) - 1] = '\0';
  } else {
    snprintf(final_name, sizeof(final_name), "Satellite %d", runtime_satellite_count + 1);
  }

  // 7. Parse poll interval
  int poll_s = 30;
  if (request->hasParam("poll")) {
    long p = strtol(request->getParam("poll")->value().c_str(), nullptr, 10);
    if (p >= 10 && p <= 3600) poll_s = (int)p;
  }

  // 8. Add under mutex
  int new_idx = -1;
  if (AGG_LOCK() == pdTRUE) {
    new_idx = runtime_satellite_count;
    satellite_caches[new_idx].set_identity(probe_id, final_name, url_str, poll_s);
    satellite_caches[new_idx].clear_cache();
    runtime_satellite_count++;
    AGG_UNLOCK();
  } else {
    send_json_error_(request, 503, "Mutex timeout");
    return;
  }

  // 9. Persist to NVS (outside mutex — NVS operations can be slow)
  save_single_satellite_to_nvs_(new_idx);

  ESP_LOGI(TAG_AGG, "Added satellite[%d]: id=%s name=%s url=%s poll=%ds",
           new_idx, probe_id, final_name, url_str, poll_s);

  // 10. Success response
  char body[256];
  snprintf(body, sizeof(body),
           "{\"ok\":true,\"satellite\":{\"id\":\"%s\",\"name\":\"%s\",\"url\":\"%s\",\"poll\":%d}}",
           satellite_caches[new_idx].id,
           satellite_caches[new_idx].name,
           satellite_caches[new_idx].base_url,
           poll_s);
  auto *resp = request->beginResponse(200, "application/json", body);
  add_common_headers_(resp);
  request->send(resp);
}
```

**⚠️ Pointer lifetime for `url_param`:** The `String url_param` is a local variable. Its `.c_str()` is valid for the duration of this function. `set_identity()` copies the string into `url_buf`, so the pointer lifetime is fine — the owned buffer outlives the function.

**⚠️ Thread safety:** The probe (`fetch_to_buffer`) happens BEFORE taking the mutex. This is correct — probing is I/O-bound (5s timeout) and must not block the mutex. The actual cache mutation is under mutex and is fast (memcpy + pointer set).

**⚠️ Race between check and add:** Between the duplicate/capacity check and the mutex-protected add, another request could theoretically add a satellite. On ESP32 with single-threaded web handler dispatch, this cannot happen — but the code is safe regardless because `set_identity()` overwrites the slot idempotently and the worst case is a duplicate check false-negative (two identical satellites), which the user can fix by deleting one.
