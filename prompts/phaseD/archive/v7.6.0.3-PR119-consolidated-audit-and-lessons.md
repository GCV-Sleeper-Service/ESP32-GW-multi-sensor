## Part I — Prompt Audit

### What the prompt does well

1. **Complete code block for `handle_test_satellite_()`** (§5d) with inline comments explaining the probe-only, no-side-effects contract. Per Guide §3.13 / Rule 29.

2. **Reuse-first approach** — §5d explicitly instructs reusing `probe_satellite_manifest_()` from v7.6.0.1 rather than reimplementing probe logic. This reduced scope and risk.

3. **API contract table** (§5a) with all 5 response conditions, expected HTTP codes, and exact JSON shapes. This became the review/test checklist.

4. **Known prompt issues section** in the handoff document — correctly flagged G3 (`String` → `std::string` at line 155) and the §7 version typo. The agent caught G3.

5. **Contract-Lock for Mock section** (§12) — documents the mock contract for v7.6.0.5, preventing prompt-vs-implementation drift at test time.

6. **"Do NOT" section** (§6) — clear negative scope preventing dashboard changes, test changes, NVS writes, and `probe_satellite_manifest_()` modifications.

### Critical prompt defects

#### P1 — Missing auth policy declaration (Severity: HIGH — caught in review)

**§5d code block:** The handler code omits `authenticate_management_(request)`. The replaced stub (`handle_aggregator_stub_501_()`) **did** call auth. The prompt does not state whether auth is required or intentionally omitted for this endpoint.

**Root cause:** The prompt author assumed the test-satellite endpoint would follow the same no-auth pattern as add-satellite. But unlike add-satellite, there was no explicit rationale comment or policy statement.

**Impact:** Agent faithfully reproduced the prompt's auth-less code. All 4+ reviewers flagged this. Fixed by adding `authenticate_management_()` call in the fixup commit.

**Prevention:** Future prompts must include an explicit **Auth Policy** block per endpoint:
```
Auth: REQUIRED / NOT REQUIRED
If REQUIRED: add `if (!authenticate_management_(request)) return;` after method gate
If NOT REQUIRED: add comment with rationale
```

#### P2 — Non-whitespace-tolerant JSON parsing in code blocks (Severity: HIGH — caught in review)

**§5c and §5d:** The `hardware` extraction uses `strstr(s_proxy_tmp, "\"hardware\":\"")` which assumes compact JSON (no space after colon). The project's manifests are pretty-printed with `"hardware": "ESP32-C3"` (space after colon). Same issue for `sensor_count`.

**Root cause:** Prompt code blocks were written assuming compact JSON. The existing `probe_satellite_manifest_()` helper already uses whitespace-tolerant parsing for `id` and `name` — the prompt should have instructed the same pattern for `hardware` and `sensor_count`.

**Impact:** Would have returned `"hardware":"unknown"` and `sensor_count: 0` for all valid probes on real devices. Fixed in review.

**Prevention:** All JSON field extraction code blocks in prompts must use the whitespace-tolerant pattern already established in the codebase by `probe_satellite_manifest_()`. Add to the writing guide: "JSON field parsing must skip optional whitespace around `:` separators."

#### P3 — Missing inherited route-level behavior in contract (Severity: MEDIUM)

**§5a / §12:** The contract table lists 5 response conditions but omits the inherited `400 "Non-empty body required for management POST"` branch from `handleRequest()` which applies because `test-satellite` is classified as a management POST route via `is_management_post_route_()`.

**Impact:** The documented contract is incomplete. v7.6.0.5 mock work depends on contract fidelity.

**Prevention:** Future endpoint prompts must include an "Inherited Route-Level Behavior" section listing all branches applied by `handleRequest()` before the handler is invoked.

## Part V — New Lessons

### New lessons

| ID | Title |
|----|-------|
| LESSON-OPS-110 | Prompt code snippets for endpoint handlers must include explicit auth policy — REQUIRED or NOT REQUIRED with rationale. Omitting auth from a prompt code block is a prompt defect that agents will faithfully reproduce. |

### New prompt writing guide additions

1. **Auth Policy Block** — Every endpoint prompt section must include:
   ```
   Auth: REQUIRED / NOT REQUIRED
   Rationale: [one-line explanation]
   ```

2. **JSON parsing must be whitespace-tolerant** — All `strstr`-based JSON field extraction must use the skip-whitespace-around-colon pattern from `probe_satellite_manifest_()`. Hard-coded offsets (`+= 12`) are fragile.

3. **Inherited route-level behavior** — Endpoint contract tables must document all branches applied by `handleRequest()` before the handler is invoked, including:
   - Empty body guard for management POST routes
   - Auth inheritance (if applicable)

4. **Default/fallback field behavior** — §12 contract tables must include rows for missing manifest fields:
   - `hardware` field absent → `"unknown"`
   - `sensor_count` field absent → `0`

### No new bugs

No new bugs were identified. All review findings were addressed before merge or accepted as known limitations.

### No new critical rules

All issues were covered by existing Critical Rules (particularly Rule 44 for `std::string`). The auth omission is addressed by the new prompt writing guide addition rather than a new Critical Rule.

## Part VI — Lessons Carried Forward to v7.6.0.4

1. **v7.6.0.4 prompt must include Auth Policy block** for every new endpoint handler. Format: `Auth: REQUIRED / NOT REQUIRED` with rationale.

2. **v7.6.0.4 prompt must use whitespace-tolerant JSON parsing** in any code blocks that extract fields from manifest JSON. Use the `find key → skip whitespace → expect ':' → skip whitespace → read value` pattern.

3. **v7.6.0.4 (Dashboard UI) will call `test-satellite`** — the dashboard JavaScript must send `POST` with `-d 'a=1'` equivalent (Rule 38/39) and include auth credentials since the endpoint now requires `authenticate_management_()`.

4. **Device test script reconciliation** — Before running `device-test-v7.6.0.3.sh`, verify all test cases include the `-u` auth flag. The auth guard was added during PR review, after the test script was originally written.

5. **`handle_aggregator_stub_501_()` is now removed** — no remaining 501 stubs in the codebase. All Phase D management endpoints are implemented.

6. **The `probe_satellite_manifest_()` helper** continues to be the canonical probe function. v7.6.0.4 dashboard code should use the `test-satellite` endpoint (which wraps it) rather than calling the helper directly.
