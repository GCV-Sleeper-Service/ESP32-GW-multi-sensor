## 4. Did the Codebase State Match the Prompt’s Assumptions?

**Mostly, but not completely.** The biggest prompt/codebase mismatches were real and should be documented explicitly.

### Assumptions that did match

1. `probe_satellite_manifest_()` existed and was reusable.
2. `POST /api/aggregator/test-satellite` was still wired to a 501 stub and ready to be replaced.
3. The step was correctly scoped as read-only probe logic.
4. Mechanical regeneration/version churn was expected.

### Assumptions that did **not** match

#### M1 — Auth behavior inherited from the replaced stub was omitted from the prompt snippet

The replaced stub had an auth gate. The prompt’s code block omitted it. The final merged code added `authenticate_management_()` in `c0590de`.

**Assessment:** real prompt defect / real codebase-state mismatch.

#### M2 — Prompt parsing logic assumed compact JSON, but the codebase manifests are pretty-printed

The prompt’s `hardware` / `sensor_count` extraction used compact patterns like `"hardware":"..."` and `"sensor_count":3`. Review comments correctly noted that the project’s manifests are pretty-printed with optional whitespace. The final merged code changed both parsers to whitespace-tolerant forms.

**Assessment:** real prompt defect / real codebase-state mismatch.

#### M3 — Prompt contract omitted inherited route-level behavior

Because the endpoint remains classified as a management POST route, `handleRequest()` applies the inherited non-empty-body requirement before the handler’s local logic. The prompt contract table did not list this runtime branch, though the final changelog and session log were updated to mention it.

**Assessment:** real prompt defect / real contract-documentation mismatch.

#### M4 — Historical handoff notes and current prompt snapshot are out of sync on G3/G4

The handoff document says the prompt had a `String` bug and a version-typo bug. The current prompt file on `main` already shows `std::string` and the correct version bump command. That means the original audit should not present G3/G4 as current prompt defects without clarifying that they refer to an earlier prompt/handoff state.

**Assessment:** documentation-state mismatch inside the source set.

## 6. Coding Agent Prompt Audit Against the Writing Guide

The original audit discussed prompt quality, but it did not explicitly map its findings back to the writing guide. That mapping belongs here.

### Where the prompt aligned with the guide

#### Guide §3.2 — Required Reading with specific callouts
**Good:** The prompt explicitly told the agent to read `probe_satellite_manifest_()`, `send_json_error_()`, `add_common_headers_()`, and the 501 route wiring.

#### Guide §3.4 — CI-exact pre-conditions
**Good:** The prompt included concrete Playwright and preflight commands.

#### Guide §3.5 — Exact scope with data-flow tracing
**Good:** The prompt clearly described the read-only probe flow and explicitly prohibited NVS/cache side effects.

#### Guide §3.6 — Do NOT section
**Good:** The prompt had a crisp, file-specific scope boundary and correctly exempted mechanical version churn from the no-dashboard-change rule.

### Where the prompt violated the guide’s intent

#### G-Audit-1 — Prompt-provided code was not production-safe enough (§3.13)
The prompt’s own copy-ready code block omitted:
- the auth gate,
- whitespace-tolerant parsing,
- truncation handling,
- explicit inherited-contract documentation.

That is exactly the kind of upstream prompt-code defect the writing guide warns about.

#### G-Audit-2 — Contract fidelity was incomplete (§3.12 / §3.5)
The prompt contract table omitted the inherited `400 Non-empty body required for management POST` branch.

#### G-Audit-3 — Historical state synchronization was weak (§11 Prompt Maintenance)
The handoff document preserved an outdated “known prompt issue” note (`String` / version typo) that does not match the current prompt snapshot. This is a prompt-maintenance problem.

### Guide-driven improvements that should be carried forward

1. Add an explicit **Auth Policy** block to every endpoint prompt:
   - `Auth: REQUIRED / NOT REQUIRED`
   - exact required code placement
   - one-line rationale if omitted

2. Add an explicit **Inherited Route-Level Behavior** block to every endpoint contract:
   - empty-body guard
   - any route-classification behavior
   - transport-vs-handler method behavior if relevant

3. Require prompt code blocks to include:
   - buffer/truncation handling where JSON is composed manually,
   - parsing style that matches actual runtime JSON formatting,
   - fallback behavior for absent fields.
