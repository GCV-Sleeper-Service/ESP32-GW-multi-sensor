## §5 — Implementation Instructions

### 5a. Record baseline state

```bash
# Record current SHA-256 of assembled file
SHA_BASELINE=$(sha256sum dashboard/sensor_history_multi.h | cut -d' ' -f1)
echo "Baseline SHA-256: $SHA_BASELINE"

# Record current assembly check state
bash scripts/assemble-sensor-history.sh --check
# Expected: PASS
```

### 5b. Test the edit → assemble → verify cycle

Make a trivial change in one fragment (add a trailing blank line to `firmware/core/registration.h`):

```bash
# Add a trailing blank line
echo "" >> firmware/core/registration.h

# Reassemble
bash scripts/assemble-sensor-history.sh --write

# Check — this should FAIL because the assembled file now has an extra blank line
# that the committed file doesn't have (until we just overwrote it)
# Actually, --write overwrites the committed file, so let's verify line count changed:
wc -l dashboard/sensor_history_multi.h
# Expected: 4326 (one extra line)

wc -l firmware/core/registration.h
# Expected: 42 (was 41)
```

### 5c. Revert the test change

```bash
# Remove the trailing blank line
sed -i '$ { /^$/d }' firmware/core/registration.h

# Verify line count restored
wc -l firmware/core/registration.h
# Expected: 41

# Reassemble to restore original
bash scripts/assemble-sensor-history.sh --write

# Verify restoration
wc -l dashboard/sensor_history_multi.h
# Expected: 4325

# SHA-256 should match baseline
SHA_RESTORED=$(sha256sum dashboard/sensor_history_multi.h | cut -d' ' -f1)
echo "Restored SHA-256: $SHA_RESTORED"
echo "Baseline SHA-256: $SHA_BASELINE"
[[ "$SHA_RESTORED" == "$SHA_BASELINE" ]] && echo "IDENTITY RESTORED" || echo "IDENTITY MISMATCH — investigate"
```

### 5d. Test the gate (deliberate-break test)

This is the critical test: prove that the `--check` mode detects unauthorized changes.

```bash
# Introduce a deliberate single-byte change in a fragment
# Add a space to the end of line 1 of config.h
sed -i '1s/$/ /' firmware/core/config.h

# Run --check WITHOUT reassembling first
# The fragments now differ from the committed file
bash scripts/assemble-sensor-history.sh --check
# Expected: FAIL (SHA-256 mismatch)
echo "Gate correctly detected change: exit code $?"

# Revert the change
sed -i '1s/ $//' firmware/core/config.h

# Verify gate passes again
bash scripts/assemble-sensor-history.sh --check
# Expected: PASS
echo "Gate passes after revert: exit code $?"
```

**Document all four results in the PR description:**
1. Baseline: PASS
2. After edit + reassemble: assembled file changes correctly
3. Deliberate break without reassemble: FAIL (gate works)
4. After revert: PASS (gate restored)

## §8 — Verification Gate

The verification gate for this step IS the workflow validation itself:

1. **PASS:** Baseline `--check` passes before any changes
2. **CHANGE:** Edit fragment → reassemble → assembled file reflects change
3. **FAIL:** Deliberate break without reassemble → `--check` fails
4. **PASS:** Revert → `--check` passes again

All four results must be documented in the PR description.
