### 5d. Create assembly script

Create `scripts/assemble-sensor-history.sh` with the exact specification from the Phase Y plan §3 v7.6.6.1. The full script content is provided in the plan. Key points:

- MODULES array lists all 8 fragments in order
- `--write` mode: `cat` all fragments into `dashboard/sensor_history_multi.h`
- `--check` mode: generator-aware comparison that strips `SENSOR_MANIFEST` marker content before SHA-256 comparison (because `render_sensor_config.py` writes generated content into the assembled file that doesn't exist in fragment stubs)
- `--list` mode: prints fragment manifest with line counts
- `--dry-run` mode: prints what `--write` would do

**⚠️ CRITICAL:** The `--check` mode MUST use the `strip_generated()` function from the plan. After `render_sensor_config.py --write` runs, the assembled file contains generated content between `SENSOR_MANIFEST:HEADER_BEGIN`/`END` and `SENSOR_MANIFEST:ENTITY_BEGIN`/`END` that does NOT exist in the fragment stubs. A naive SHA-256 comparison would ALWAYS fail after the generator runs. The `strip_generated()` function removes the content between these markers before comparing.

Make the script executable:
```bash
chmod +x scripts/assemble-sensor-history.sh
```

### 5e. Activate assembly step in provision.sh

In `scripts/provision.sh`, find the Step 0 placeholder in `run_full_pipeline()` and replace the no-op comment with:

```bash
  if [[ -f "scripts/assemble-sensor-history.sh" ]]; then
    if [[ "$dry_run" == "true" ]]; then
      echo "  [DRY-RUN] Step 0: bash scripts/assemble-sensor-history.sh --write"
    else
      echo "  Running   Step 0: bash scripts/assemble-sensor-history.sh --write"
      if ! bash scripts/assemble-sensor-history.sh --write; then
        echo "ERROR: Assembly failed" >&2
        exit 1
      fi
    fi
  else
    echo "  [SKIP]    Step 0: assemble-sensor-history.sh (not yet created)"
  fi
```

This preserves backward compatibility: if the assembly script doesn't exist (shouldn't happen after this step, but defensive), it skips gracefully.

### 5f. Add fragment existence check to preflight.sh

Add a new check function to `scripts/preflight.sh` following the existing pattern:

```bash
firmware_core_fragments_exist() {
  local expected=(
    "firmware/core/config.h"
    "firmware/core/data-model.h"
    "firmware/core/nvs-persistence.h"
    "firmware/core/deferred-management.h"
    "firmware/core/ping-adapter.h"
    "firmware/core/aggregator-runtime.h"
    "firmware/core/web-handler.h"
    "firmware/core/registration.h"
  )
  local missing=0
  for f in "${expected[@]}"; do
    if [[ ! -f "$f" ]]; then
      echo "    Missing: $f"
      missing=1
    fi
  done
  if [[ $missing -eq 1 ]]; then
    fail "firmware_core_fragments_exist"
  else
    pass "firmware_core_fragments_exist"
  fi
}
```

Add the function call in the main check sequence.

## §10 — Anti-Patterns and Inline Warnings

| Anti-pattern | Why | Where it applies |
|---|---|---|
| Using `split` command for extraction | Arbitrary boundaries, not line-range-based | Fragment extraction (§5b) |
| Adding code to fragment files | Fragments must be pure byte-slices of original | All fragment files |
| Naive SHA-256 comparison in `--check` | Generator writes content between markers — must strip before comparing | Assembly script `--check` mode |
| Adding fragments to YAML `includes:` | YAML includes only the assembled artifact — never fragments | `firmware/esp32-c3-multi-sensor.yaml` |
| Redirecting generator to fragment files | Generator writes to assembled artifact only | `render_sensor_config.py` |
| Editing `sensor_history_multi.h` directly | It's now an assembled artifact — edit fragments, run assembly | All future Phase Y work |
