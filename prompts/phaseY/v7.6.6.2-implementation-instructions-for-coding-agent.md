## §4 — Do-NOT List

- Do NOT add `assemble-sensor-history.sh --check` to the pipeline steps inside `provision.sh` — it runs in preflight only
- Do NOT modify the assembly script
- Do NOT modify any fragment files
- Do NOT add the assembly `--check` as a post-pipeline step in `run_full_pipeline()` — see §4.2 of the Phase Y plan for why

**⚠️ ANTI-PATTERN:** Adding assembly `--check` at the end of the pipeline would cause a false-sense-of-security problem. After `render_sensor_config.py --write`, the assembled file has generated content that fragments don't have. The `strip_generated()` function in `--check` handles this correctly, but the right architectural placement is preflight (integrity guard), not pipeline tail (pipeline already ends with `render_sensor_config.py --check` as the generator consistency gate).

## §5 — Implementation Instructions

### 5a. Add `firmware_core_assembly_check` to preflight.sh

Add this check function after the existing `firmware_core_fragments_exist` check:

```bash
firmware_core_assembly_check() {
  if [[ ! -f "scripts/assemble-sensor-history.sh" ]]; then
    fail "firmware_core_assembly_check (script missing)"
    return
  fi
  if bash scripts/assemble-sensor-history.sh --check >/dev/null 2>&1; then
    pass "firmware_core_assembly_check"
  else
    fail "firmware_core_assembly_check (SHA-256 mismatch — run: bash scripts/assemble-sensor-history.sh --check)"
  fi
}
```

Add the function call in the main check sequence, immediately after `firmware_core_fragments_exist`.

### 5b. Add `firmware_core_fragment_line_sum` to preflight.sh

```bash
firmware_core_fragment_line_sum() {
  if [[ ! -d "firmware/core" ]]; then
    fail "firmware_core_fragment_line_sum (firmware/core/ missing)"
    return
  fi
  local fragment_total
  fragment_total=$(cat firmware/core/*.h 2>/dev/null | wc -l)
  local committed_total
  committed_total=$(wc -l < dashboard/sensor_history_multi.h 2>/dev/null)
  if [[ "$fragment_total" -eq "$committed_total" ]]; then
    pass "firmware_core_fragment_line_sum ($fragment_total == $committed_total)"
  else
    fail "firmware_core_fragment_line_sum (fragments: $fragment_total, committed: $committed_total)"
  fi
}
```

Add the function call in the main check sequence, after `firmware_core_assembly_check`.

## §10 — Anti-Patterns and Inline Warnings

| Anti-pattern | Why | Where it applies |
|---|---|---|
| Adding `--check` to pipeline tail | Generator modifies assembled file after Step 2 — see Phase Y plan §4.2 | `provision.sh` `run_full_pipeline()` |
| Using `diff` instead of `--check` for preflight | The `--check` mode handles generator-aware comparison correctly | `firmware_core_assembly_check` |
| Hardcoding line count in preflight | Compare fragment sum to committed file dynamically — count may change in future phases | `firmware_core_fragment_line_sum` |
| Suppressing `--check` error output | The error diff helps diagnose mismatches — redirect stdout only, not stderr | `firmware_core_assembly_check` |
