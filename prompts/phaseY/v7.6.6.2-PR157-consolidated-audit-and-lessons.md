## Lessons

### New lessons from this PR

**LESSON-PHASY-001: Fragment-metadata version strings must be kept in sync with assembled header**

When `render_sensor_config.py --write` runs as pipeline Step 2, it updates version-comment strings in `dashboard/sensor_history_multi.h` that live outside the `SENSOR_MANIFEST` markers. The same strings exist verbatim in the fragment source files `firmware/core/config.h` and `firmware/core/data-model.h`. Once `firmware_core_assembly_check` is active, any version bump that updates the assembled header but not the fragment sources produces a SHA-256 mismatch. Fix: `bump-version.sh` must apply matching `sed` updates to both fragment files before the pipeline runs.

**Applies to:** Every future version bump. Already fixed in `bump-version.sh` from this PR.

---

**LESSON-PHASY-002: Preflight line-sum checks must use the assembler's explicit module list, not a glob**

`firmware_core_fragment_line_sum` must compute its fragment total from the same explicit `MODULES` array used by `assemble-sensor-history.sh`, not from a `firmware/core/*.h` wildcard. Using a glob creates a latent false-failure path: any non-assembled helper header added to `firmware/core/` (test helpers, private utilities, etc.) would inflate the fragment line count, causing preflight to fail even when `assemble-sensor-history.sh --check` passes.

**Applies to:** Any future fragment-integrity check. The fixed implementation in `d1e3998` is the reference pattern.

---

**LESSON-PHASY-003: Prompt scope boundaries must include all predictable autonomous decisions**

The `bump-version.sh` modification was both necessary and predictable from the prompt context: the prompt explicitly states `firmware_core_assembly_check` verifies SHA-256 identity, and the version bump step is §5c. Any reviewer reading both would see the conflict. Scope boundaries that exclude predictable necessary changes push agents into autonomous decisions and create review surface. Future Phase Y prompts should include these predictable side-effect files in scope.
