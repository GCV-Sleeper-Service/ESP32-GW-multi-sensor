## §5 — Implementation Instructions

### 5a. Provision aggregator mode

```bash
# Switch to aggregator mode — this generates the S3-specific YAML
bash scripts/provision.sh aggregator

# Verify the generated YAML exists
ls -la firmware/esp32-s3-devkitc1-n16r8-gw.yaml

# Verify aggregator mode is active
bash scripts/provision.sh status
```

### 5b. Flash S3 aggregator board

```bash
cd firmware
esphome run esp32-s3-devkitc1-n16r8-gw.yaml
# Select serial port (/dev/ttyACM0) when prompted
# Monitor boot output for aggregator task start messages
```

**⚠️ LXC USB note:** If flashing from an LXC container, USB permissions may be lost after device reconnect. Run `chmod 0666 /dev/ttyACM0` on the Proxmox host if the serial port is inaccessible. See Critical Rule 25.

### 5c. Boot log inspection

Watch the serial console after flash for:
- Aggregator poll task start message
- WiFi connection
- No crash or stack overflow
- Satellite discovery/polling (if C3 satellite at `192.168.120.189` is online)

**Record the boot log output.** This is required evidence for the PR.

### 5d. Device test protocol

Wait for the device to be reachable on the network (ping `192.168.120.191`).

**Test 1 — Aggregator gateways endpoint:**

```bash
curl -s http://192.168.120.191/api/aggregator/gateways | python3 -m json.tool
```

Expected: JSON response with satellite gateway data. If the C3 satellite is online, it should appear.

**Test 2 — Aggregator live data:**

```bash
curl -s http://192.168.120.191/api/aggregator/live | python3 -m json.tool
```

Expected: JSON response with cached live data from satellites.

**Test 3 — Aggregator history proxy (if satellite is online):**

```bash
# Replace {device} and {metric} with actual values from satellite's manifest
curl -s "http://192.168.120.191/api/aggregator/proxy/192.168.120.189/history/{device}/{metric}" | python3 -m json.tool | head -30
```

Expected: Proxied history data from the satellite.

**Test 4 — Test satellite (probe-only, no mutation):**

```bash
curl -s -u ESPadmin:ESppass100 -d 'a=1' -X POST "http://192.168.120.191/api/aggregator/test-satellite" -d "ip=192.168.120.189"
```

**⚠️ NOTE:** The exact POST body format for test-satellite may use form-urlencoded fields. Check the firmware handler if this fails. The key point: use `-d` (not JSON), include auth.

Expected: 200 response with probe results.

**Test 5 — Add satellite:**

```bash
curl -s -d "ip=192.168.120.189" -X POST http://192.168.120.191/api/aggregator/add-satellite
```

**Note:** add-satellite does NOT require auth (see endpoint inventory §5.3). Record the response.

Expected: 200 response with satellite added (or 409 if already present).

**Test 6 — Verify satellite_config_generation increments:**

```bash
# Check gateways endpoint — look for config_generation field
curl -s http://192.168.120.191/api/aggregator/gateways | python3 -m json.tool | grep -i generation
```

**Test 7 — Delete satellite:**

```bash
# Replace {id} with the satellite's index (typically 0)
curl -s -u ESPadmin:ESppass100 -X DELETE "http://192.168.120.191/api/aggregator/satellite/0"
```

Expected: 200 response, satellite removed. This triggers deferred NVS save.

**Test 8 — Re-add satellite for reboot test:**

```bash
curl -s -d "ip=192.168.120.189" -X POST http://192.168.120.191/api/aggregator/add-satellite
```

**Test 9 — Reboot persistence test:**

```bash
# Record current satellite list
curl -s http://192.168.120.191/api/aggregator/gateways | python3 -m json.tool > /tmp/pre-reboot-agg.json

# Trigger reboot
curl -s -u ESPadmin:ESppass100 -d 'a=1' -X POST http://192.168.120.191/api/reboot

# Wait for device to come back online (30-60 seconds)
sleep 60

# Verify device is back
ping -c 3 192.168.120.191

# Re-check satellite list after reboot
curl -s http://192.168.120.191/api/aggregator/gateways | python3 -m json.tool > /tmp/post-reboot-agg.json

# Compare — satellite should still be present
diff /tmp/pre-reboot-agg.json /tmp/post-reboot-agg.json
```

Expected: Satellite list survives reboot (NVS persistence works for aggregator config).

**Test 10 — Reset satellites (deferred task):**

```bash
curl -s -u ESPadmin:ESppass100 -d 'a=1' -X POST http://192.168.120.191/api/system/reset-satellites

# After a moment, check gateways
sleep 5
curl -s http://192.168.120.191/api/aggregator/gateways | python3 -m json.tool
```

Expected: Satellite list cleared.

## §10 — Anti-Patterns and Inline Warnings

| Anti-pattern | Why | Where it applies |
|---|---|---|
| Using committed C3 YAML for S3 board | S3 MUST use generated `esp32-s3-devkitc1-n16r8-gw.yaml` (Critical Rule 36) | §5b |
| Using `Content-Type: application/json` in curl | ESPHome does not consume JSON POST bodies — socket corruption | All POST curl commands |
| Using `-d ''` or bare `-X POST` without body | Must use `-d 'a=1'` for all POST commands | All POST curl commands |
| Forgetting to switch back to satellite mode | Leaves repo in aggregator mode — breaks CI | §5e |
| Flashing without provisioning first | Generated YAML doesn't exist until `provision.sh aggregator` runs | §5a |
| Skipping the reboot persistence test | This validates NVS satellite config survives power cycles | §5d Test 9 |

### C++ Split Anti-Patterns (apply to all Phase Y steps)

| Anti-pattern | Why |
|---|---|
| `#include` order differs from assembly concatenation order | Assembly concatenation order IS the dependency order |
| `static` function/variable scope confusion | Per-TU under inclusion, file-scoped under assembly — Phase Y uses assembly |
| Mutex redefinition | `s_cache_mutex` defined in exactly one fragment (`aggregator-runtime.h`) |
| Deferred-task visibility violation | Deferred-task functions must be defined before use in assembly order |
| Adding fragments to ESPHome YAML `includes:` | Only the assembled artifact appears in YAML |
| Generated content in fragments | `render_sensor_config.py` marker blocks have delimiter stubs in fragments, content in assembled artifact only |
| `application/json` POST body | All endpoints use `application/x-www-form-urlencoded` with `body: 'a=1'` |
| `maybe_yield_nvs_scan_()` redefinition | Defined once in `nvs-persistence.h`, accessible from all NVS-scanning loop sites |
