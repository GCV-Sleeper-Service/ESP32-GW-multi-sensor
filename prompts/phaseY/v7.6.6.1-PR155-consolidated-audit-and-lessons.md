**Deviation 2 — Security defect introduced in `aggregator-runtime.h`.**  
**Classification:** Omission (fixed in `b15278a`).  
The `lwip_send` call passed `req_len` (the `snprintf` return value) as the send length without a truncation check. If `path` + `host` together exceed 512 bytes, `snprintf` truncates the buffer but `req_len` holds the full would-have-been-written length, causing `lwip_send` to read beyond the 512-byte stack buffer. Fixed by adding:
```c
if (req_len < 0 || (size_t)req_len >= sizeof(req)) { lwip_close(sock); return false; }
if (lwip_send(sock, req, (size_t)req_len, 0) < 0) { lwip_close(sock); return false; }
```
This fix was also applied to `dashboard/sensor_history_multi.h` (the assembled output), making the fragment and monolith consistent. This caused `aggregator-runtime.h` to be 892 lines (one more than the 891-line plan). Documented in the session log with explanation.

**Deviation 3 — `assemble-sensor-history.sh` missing invocation-safety hardening.**  
**Classification:** Omission (fixed in `b15278a`).  
Two low-severity gaps corrected:  
- Missing `ROOT` normalization — script would fail if invoked from a non-root directory. Fixed by adding `ROOT="$(cd ...)" && cd "$ROOT"`.  
- `--check` mode gave opaque `set -e` failure if `$OUTPUT` was absent. Fixed by adding explicit `[[ -f "$OUTPUT" ]]` guard with a clear error message.

### 4. New lessons or critical rules?

**Candidate Critical Rule 58 — `snprintf` return values must be bounds-checked before use as buffer lengths:**  
Any call that uses the return value of `snprintf` (or `sprintf`) as a length argument to a send/write function must first verify the return is non-negative and less than the buffer size. Unchecked, a truncated write will pass the pre-truncation length to the I/O function, causing a buffer over-read.  
_Source: v7.6.6.1 PR #155 — `lwip_send(sock, req, req_len, 0)` without truncation guard._

**Candidate Critical Rule 59 — Version bumps are out of scope for pure infrastructure PRs:**  
When a PR's stated scope is exclusively infrastructure (file splits, scripts, tooling), `bump-version.sh` must NOT be run. Version bumps belong in the step that delivers a user-visible change. Performing a version bump without regenerating ALL derived artifacts (including all variant fixtures) creates version drift that blocks CI.  
_Source: v7.6.6.1 PR #155 — repeats the same pattern as v7.6.5.7 PR #148 (Critical Rule 56). Pattern is systemic._

**LESSON-OPS-125 — Coding agent PRs must target the correct base branch:**  
When a coding agent is used for post-review fixes on a feature branch, the resulting PR must target the feature branch (not `main`). The agent opened PR #156 targeting `main`. This required operator intervention (rebase + base retarget). Future fix prompts should explicitly state: "Open a PR targeting branch `<branch-name>`, NOT `main`."

**LESSON-OPS-126 — Security review should be part of the initial agent prompt for network I/O fragments:**  
`aggregator-runtime.h` contains socket-level network code. The initial prompt did not include a security review step. Adding a mandatory review checkpoint for any fragment containing `lwip_send`, `lwip_recv`, `snprintf`, or `malloc` would catch this class of defect before review.
