**4. Were any new lessons or critical rules discovered during execution?**

- **LESSON-OPS-106:** `satellite_config_generation` is an internal runtime concurrency counter.
  It is never serialised to any HTTP response. Future prompts must not instruct agents to
  `grep` for it in JSON output.
- **LESSON-OPS-107:** `POST /api/aggregator/test-satellite` requires `url=http://...` (full
  URL including protocol) as a POST body field, not `ip=...`.
- **LESSON-OPS-108:** `POST /api/aggregator/add-satellite` requires `url=http://...` as a
  **query parameter** (`?url=http://...`), not as a POST body field (`-d "ip=..."`).
- **LESSON-OPS-109:** `DELETE /api/aggregator/satellite/{id}` uses the satellite's string ID
  (e.g. `sat-c3-4m-189`) from the gateways response, not an integer index (`/satellite/0`).

## Retrospective

**21. What prompt change would have prevented any failures encountered during this step?**

**a) Test 4 (`test-satellite`):** The prompt used `-d "ip=192.168.120.189"` but the endpoint
   expects `-d "url=http://192.168.120.189"` (full URL). Fix: update prompt to use
   `-d "url=http://..."`.

**b) Test 5 and 8 (`add-satellite`):** The prompt used `-d "ip=192.168.120.189"` as a POST body
   field but the endpoint expects `?url=http://...` as a query parameter. Fix: update prompt to use
   `?url=http://192.168.120.189` query parameter with `-d 'a=1'` body.

**c) Test 6 (`satellite_config_generation` grep):** The field is an internal runtime counter and
   is never in any HTTP response. The grep instruction was always going to produce no output. Fix:
   replace the grep with a note explaining the counter is internal (LESSON-OPS-106) and instruct
   the agent to confirm mutation flows work as the observable proxy.

**d) Test 7 (`satellite DELETE`):** The prompt used `/satellite/0` (integer index) but the endpoint
   uses a string satellite ID from the gateways response (e.g. `/satellite/sat-c3-4m-189`). Fix:
   update prompt to document the string-ID form.

All four corrections have been committed to `v7.6.6.6-implementation-instructions-for-coding-agent.md`
and `v7.6.6.7-implementation-instructions-for-coding-agent.md` in this PR.
