## Retrospective

**21. What prompt change would have prevented any failures encountered during this step?**

**Issue 1 — Phase A omitted from initial commit.**
The prompt's §8 (Verification Gate) specifies a complete 21-row endpoint evidence table, but the acceptance criteria in §6 do not explicitly require documenting Phase A results in the session log before creating the PR. The initial agent completed Phase B and Phase C (which were prominent in the PR title) but did not produce the Phase A section.

**Suggested prompt fix:** Add to §6 Acceptance Criteria:
> - [ ] Session log contains `### Phase A — C3 Satellite Endpoint Tests` section with evidence for all 13 local GET endpoints
> - [ ] Session log contains `### ESPHome Build & Flash Log` section with `esphome run` output for both C3 and S3

**Issue 2 — Import/export crash not anticipated.**
The prompt lists import/export endpoints as required test targets with no conditional path for hardware failure.

**Suggested prompt fix:** Add to §4 (Device Test Sequence):
> ⚠️ If any endpoint crashes the board, document the crash, mark the endpoint as `⚠️ Deferred — [reason]` in the evidence table, and continue with the remaining endpoints. A single endpoint failure does not block the gate provided it is documented.

**Issue 3 — Hardcoded credentials in initial session log.**
The prompt does not specify credential handling in curl examples.

**Suggested prompt fix:** Add to §4 (curl conventions):
> All curl commands in the session log MUST use `<user>:<pass>` as the credential placeholder. Never commit literal credentials.
